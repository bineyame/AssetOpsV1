Readings from a file

When the site's connection is down, its readings can be sent as a file in the AssetOps template: solar output and the three feeder meters, every 15 minutes.

Upload readings

Change: one panel on Kobo's Health tab with an "Upload readings" button. It appears only on Kobo and only when the upload switch is on (off by default). No other Site shows it. Open question for the Architect: Health or Evidence as the home (the spec says "the Site's data or Health area").

Every refusal, in the words the page shows

The whole file is refused on the first problem found; the page names the row and column.

11 reasons
ReasonWhat the page says
Not plain textThe file is not plain CSV text (UTF-8). Save it as "CSV" without a byte-order mark and try again.
EmptyThe file has no readings in it.
HeadingsThe column headings do not match the template. Column 3 is "pv_power"; the template calls it "pv_ac_power [kW]".
Time formatA time is not written like 2026-11-17T03:15:00Z (UTC, ending in Z). Row 4.
Time stepA time is not on a 15-minute step (:00, :15, :30, :45). Row 7.
Repeated timeThe same time appears twice. Row 12.
OrderThe rows are not in time order. Row 9 is earlier than the row before it.
ReadingA reading is not a plain number (use a dot for decimals, no thousands separator, at most 3 decimals), or the row has the wrong number of cells. Row 5, mill_feeder_power.
Already savedKobo already has solar readings up to 16 Nov, 23:45. This file starts at or before that; only readings after it can be uploaded.
Too largeThe file is larger than 2 MB.
Not this SiteUploading readings is not available for this site.

The first eight are the gateway's file rules (TEL-06), the same checks the server runs. "Already saved" is new: a file may not overlap readings Kobo already has, so nothing is ever overwritten or doubled. The page shows the plain words; the code and row stay underneath for support.
