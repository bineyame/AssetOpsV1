### Findings

**M1 (Medium; acceptance gap against D-SC1.29). A file in a subfolder of `i18n/` is in no scan scope.**
`tools/checks/statement_catalogue.py:604` globs only `i18n/*.py` for scope (1) and `MECH_UNSCOPED`;
`_ratchet_paths` (`:575-583`) skips everything under `i18n/` except `messages.py` and `locale.py`. The loader
(`catalogue.py:752-779`) also ignores modules that are not in a locale folder, and subpackages of a locale folder.
My plants: a prose f-string in `i18n/helpers/words.py`, `i18n/statements/words.py` and
`i18n/statements/en/extra/words.py` each gave `OK statement catalogue`. The same text in `i18n/words.py` gave
`MECH_UNSCOPED` as it should. Why it matters: D-SC1.29 says "no file is ever unscanned and none can slip out of the
positive scope by being added". A helpers subfolder is a likely place for a future adopter to put word code.
Fix: walk `i18n/**/*.py`. Any file that is not a mechanism module, not `LEGACY_I18N`, and not a data module directly
in `statements/<locale>/` (the load already proves those `NOT_DATA`-free) is `MECH_UNSCOPED`. Add the subfolder case
to P51.

**M2 (Medium; acceptance gap against D-SC1.22 and R9). Private modules can be reached through a public one.**
`import_hits` (`statement_catalogue.py:369-403`) checks the module path and `_`-prefixed names only. `render.py:11`
binds `conditions`, `formats` and `schema` as public attributes, and `facts.py` binds `schema`.
`from assetops_backend.i18n.render import formats` and `import assetops_backend.i18n.render as r; r.formats.money(...)`
in a backend module both pass the guard (plants run). D-SC1.22 says an import of "`render`'s internals is
`I18N_BYPASS`", and its reason is exactly this: "an imported `formats.money` is a second renderer". The text scan
reduces the harm, because composing around the result is still flagged, but the stated contract is not enforced.
Fix (either): import the private modules under `_` aliases in `render.py`, `facts.py` and `wire.py`, as `render.py`
already does for `_catalogue`; or have the guard refuse any name imported from a public `i18n` module that is not in
that module's `__all__` or in `i18n.__all__`. Add the plant to the self-test.

**M3 (Medium; spec gap, for the Architect; the builder followed the spec). The number-word list misses whole classes.**
`schema.NUMBER_WORDS["en"]` equals spec §3.12 (T12 pins it). These load cleanly in a template (my `_build` probe):
"sixty days", "ninety days", "thirteen sites", "the tenth site", "hundreds of sites", "dozens", "a couple of sites".
The list has twenty to fifty but not sixty to ninety, none of thirteen to nineteen, ordinals only to "fifth", and no
plural magnitudes. Why it matters: the mock's "61 days" is the class SC-1 exists to stop, and reviewer guide

Fix: the Architect extends §3.12 (sixty to ninety, thirteen to nineteen, sixth to twelfth, tenth, hundredth,
thousandth, hundreds, thousands, millions, billions, dozens, couple). The builder then updates `schema.py` and T12's
literal. A rule (stems plus `-teen`, `-ty`, `-th`, `-s`) would be less brittle than a list, but that is the
Architect's call.

- **What it catches.** Most hits are real English the owner wants composed cleanly: new `messages.py` templates, CLI

- **False positives**, which only a hand-added fingerprint can clear:
  - SQL fragments joined with `+` (`" FROM structure_snapshot WHERE ..."`). The SQL exemption only checks a
    string's start.
  - `"\n".join(lines)` in a hashing helper (rule e: a whitespace receiver).
  - `"LIVE" if real else "SIMULATED"` (rule f: code values).
  - `self.logger.info(...)`, which is not exempt (only bare `logger` and similar names are).
  - Internal exception text of custom exception classes.
- **What the owner may decide.** Approve as is, accepting that friction. Or ask the Architect, before or soon after
  merge, to (a) let a unit add fingerprints for non-served text in a hand edit the reviewer judges, and (b) tighten
  rules (e), (f) and the SQL test.
- **Speed is fine**: about 5s for the scan plus 13s for the self-test.

### Residual risks the packet does not name

- An `example` slot's `text` is checked by nothing (spec: format examples like `like 2026-10`). It is the one place a
  statement author can put a digit, `%` or currency sign in prose (probe: `"within 1% or $5 twice"` loads).
  SC-1b should restrict it, or the guard should require each example to match a declared format.
- An `evidence` slot prints the word of every *present* covered figure, not only the stated ones (spec §3.3 says so).
  A 3A7 caller who passes `recorded` with an emulated origin on `zero_stated` gets "(Recorded and Emulated)" for a
  figure the sentence does not state. 3A7 should pass only the figures each state states.
- A `Name` may hold a bidi override or zero-width character (category `Cf`); only `Cc` is refused. Records are the
  source, so this risk is low.
- The month vocabulary is checked for 12 entries, not for their order. A future locale with a misordered `order` list
  would print the wrong month silently.
