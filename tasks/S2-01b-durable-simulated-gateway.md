## Result and boundary

An imported Kobo Lab run's public device reports enter a **separate gateway process**. Lab Stage and gateway status show the registered basis, sealed SourceEnvelope V3 rows, one homogeneous Batch V2 and explicit `STAGED`/pending upload state from SQLite after both host and gateway restart. The exact source sequence, message IDs, envelope bytes, batch bytes and digest stay fixed. Repeated host publication of the same observation does not allocate another source event; two distinct observations at the same source time get distinct sequences. There is no central acceptance, authenticated batch POST, successful receipt, Site Evidence write or registered Commit in this slice. S2-02 owns those.

S2-01a already freezes canonical snapshot bytes/hash, revision IDs, source start and `knowledge_at` on `SimulationRun.registered_basis`; it verifies these on reload and checks the final possible report time. Its existing `host/lab_execution.py::_stage` regenerates the whole observation series and writes file-backed v1/v2 Stage data. For **new registered runs**, replace that publication authority with the gateway SQLite outbox and derive Stage inspection from it. Historical YAML runs/stages/committed artifacts remain read-only and retain their original schema and bytes. The unimported YAML Lab boundary stays as built.

## Acceptance criteria

1. **Process and basis transfer.** Launch a separately restartable gateway process with a bounded local host-to-gateway report/configuration channel. Transfer S2-01a's already frozen, canonical registered snapshot bytes and revision references; verify SHA-256/schema and matching tenant/Site/gateway/source, mode `SIMULATED`, validity and run basis before activating the mapping. The gateway cannot fetch arbitrary Site snapshots through S1's development-tenant `GET /foundation/snapshot` route. Scope the channel to the Lab host and intended gateway identity; reject wrong Site/source, changed bytes under the same hash, unsupported schema and unavailable gateway without silently using YAML. The exact authorization/transport choice follows the Architect answer; no S2-02 upload credential is implied here.
2. **Public adapter.** A typed simulated-report adapter passes only `DeviceObservation`/public records and frozen public configuration across the process boundary; the gateway has no kernel/world/oracle/scenario access. Use the selected binding rows for device/signal/source, units, conversion and role, never legacy `signal_mappings` or the newer template's unbound capability links. Keep unavailable reports explicit where the mapping allows them; dropped/suppressed observations create no envelope. Unknown channel, invalid enum, incompatible unit or missing binding gets an inspectable hold/refusal with its field and reason, never an invented reading. The registered Kobo daytime scenario with already bound channels is sufficient; S2-02 owns later generator/capability demo configuration.
3. **Durable V3 identity.** SQLite uses WAL, foreign keys, busy timeout, a migration version and one writer. Store gateway identity and immutable mapping snapshots. In one transaction allocate a monotonic sequence scoped to `(gateway,source,epoch)` and insert the canonical SourceEnvelope V3 text plus hash. Epoch changes only on explicit reprovisioning; sequence overflow refuses acquisition. Specify and fixture length-delimited message-ID framing and canonical JSON/decimal/UTC rules from technical design §3. `published_at` records gateway sealing, not a corrected source time. Replayed host series and process restart reuse previously admitted report identity and bytes; a genuinely second report at the same source timestamp receives a new sequence and ID. Preserve local provenance linking a Lab run to queued rows without putting run ID or private cause/oracle in a production envelope or Batch V2.
4. **Sealed queue.** Seal ready outbox rows into immutable, bounded Batch V2 bytes with ordered `batch_item` ordinals, source/mapping/Foundation homogeneity and canonical SHA-256 excluding `payload_sha256`. A new registered basis opens a separate batch; never rewrite an already sealed batch or envelope. Persist local `STAGED`, `READY`, `IN_FLIGHT`, receipt slot and retry metadata so S2-02 can add upload. Until S2-02, registered Lab rows and batches remain staged/pending; no synthetic `ACKED` or accepted receipt. On restart, an interrupted local in-flight attempt is retryable with identical batch ID/bytes. Retain refused/unacknowledged bytes and show their state; acquisition failure cannot advance the Stage publication watermark or imply delivery.
5. **Lab inspection and carry.** `GET /runs/{run_id}/stage` and the Lab Gateway & Ingestion view resolve new registered runs through the durable gateway read, show queue depth/state, snapshot hash, epoch/sequence, envelope and batch digest/bytes, and label upload as pending. Reopen after host and gateway restart and compare exact bytes. The Stage read for pre-import runs remains its frozen `LEGACY_FILE` view. Direct server Commit for every imported run still refuses before release. Close S2-01a review carry F1 in `frontend/src/shell/RunCommitPanel.tsx`: for a pre-import YAML artifact committed before its Site was imported, an unfinished or refused release must show the basis block instead of an actionable Resume/Retry button; cover that historical committed branch in a frontend test.
