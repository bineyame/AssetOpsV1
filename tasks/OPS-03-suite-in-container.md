## Exact build contract

1. Add `docker-compose.test.yml` with a `backend-test-runner` service, using `python:3.12.7-slim-bookworm`, `profiles: [test]`, `depends_on: postgres: {condition: service_healthy}`, `working_dir: /workspace`, and no published ports. Use `docker compose -p assetopsv1 -f docker-compose.yml -f docker-compose.test.yml run --rm backend-test-runner`; use the same `-p assetopsv1` for `up`. Compose attaches the one-shot runner to the `assetopsv1` project default network used by `assetopsv1-postgres-1`; validate that container's Compose project label before starting and fail if it belongs to a different project. The service name `postgres` resolves there. The runner must use `postgres:5432`, never the Windows port forward `127.0.0.1:55432`. Do not run tests in the Postgres server container. No Dockerfile exists in the current repo, and this task does not need one.
2. Bind mount `${ASSETOPS_WORKTREE:?}` (the wrapper's absolute current worktree root) at `/workspace` with write access so tests see the exact checkout and JUnit lands on the host. Mount separate named volumes `assetops-test-venv:/opt/assetops-venv` and `assetops-test-pip-cache:/root/.cache/pip`; do not mount the Windows `.venv`. Set `VIRTUAL_ENV=/opt/assetops-venv`, prepend its `bin` to `PATH`, set `PYTHONDONTWRITEBYTECODE=1`, `PYTHONPATH=/workspace/backend:/workspace/contracts:/workspace/simulator:/workspace/gateway:/workspace/host`, and pass `ASSETOPS_TEST_DATABASE_URL` from `${ASSETOPS_CONTAINER_TEST_DATABASE_URL:?}` as `postgresql+psycopg://assetops:<URL-encoded ASSETOPS_PG_PASSWORD>@postgres:5432/assetops_test`. The password defaults to the Compose local development value `assetops-local-dev`. The wrapper must not print the URL or password. Do not pass `DATABASE_URL` or the host test URL through to the runner.
3. Add `tools/run-backend-suite-in-container.ps1` as the only public command: `powershell -NoProfile -ExecutionPolicy Bypass -File tools\run-backend-suite-in-container.ps1` from the repository root (an absolute script path also works from elsewhere). It resolves the worktree from `$PSScriptRoot`, checks Docker Compose availability, starts `postgres` with `docker compose -p assetopsv1 -f docker-compose.yml -f docker-compose.test.yml up -d --wait postgres`, builds the URL, creates a unique `var/test-results/OPS-03/<run-id>/` host directory, starts keep-awake, launches the one-shot service, enforces the cap, propagates the container's exit code, and stops keep-awake in `finally`. Do not stop or remove Postgres after the run. The Linux entry command is `sh /workspace/tools/run-backend-suite-in-container.sh`; that script is installed as part of this task, has LF endings, and runs from `/workspace`.
> Note: the `-ExecutionPolicy Bypass` form above is historical; guards now run with no override (`.ai/ROLE_CONFIG.md`).
4. The Linux script creates the cached venv with `python -m venv /opt/assetops-venv` when absent. On each invocation it compares a marker made from the Python image/version and SHA-256 of `backend/pyproject.toml`, `contracts/pyproject.toml`, `simulator/pyproject.toml`, and `gateway/pyproject.toml`; on a miss it installs with `/opt/assetops-venv/bin/python -m pip install -e '/workspace/backend[dev]' -e /workspace/contracts -e /workspace/simulator -e /workspace/gateway`, then writes the marker only after success. Pip's mounted cache serves downloads. A source-only edit uses the bind-mounted source via editable installs/PYTHONPATH without reinstalling dependencies. Fail the run if installation fails; never fall back to host Python or silently skip tests. The service has no shared writable cache for pytest temp data; let the existing `conftest.py` choose its Linux temp base.
5. The test command in the Linux script is exactly `/opt/assetops-venv/bin/python -m pytest backend/tests -n 2 --dist loadfile --no-loadscope-reorder -q --durations=30 --junitxml=/workspace/var/test-results/OPS-03/<run-id>/junit.xml`. Use an environment variable passed by the PowerShell wrapper for `<run-id>` and validate it as a simple unique directory name. Save console output and wall time in the same directory. Keep `-n 2 --dist loadfile --no-loadscope-reorder` unchanged; no `-n auto`, deselection, retries, or altered product code. Run `tools/check-all.ps1` separately on Windows with its repository `.venv` and Node; container pytest does not replace those ten guards.
