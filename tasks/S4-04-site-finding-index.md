## Read contract (route, DTO and cursor are new)

Add `GET /api/sites/{site_code}/finding-index?domain=mini-grid-dispatch&from=<UTC>&to=<UTC>&limit=<bounded>&cursor=<opaque>`. `mini-grid-dispatch` is a **new API domain token**: resolve it to stored `finding.domain='mini_grid' AND finding.analytic_id='dispatch'`, the S3 `dispatch` discovery basis, and the S4 matcher `MATCHER_VERSION` on that basis (`analytics/finding_episode.py:78,76` on the stacked base; `:68` for `DOMAIN` on main; `analytics/dispatch.py:27`; `analytics/assessment_worker.py:51`). Resolve tenant/Site via Finding access before discovery: established 401/403/404 and no foreign count. Require the explicit supported domain and UTC half-open `[from,to)`, `from < to`, maximum 31 UTC days; any other domain or invalid input receives typed 422, with no status, rows or count, never `CURRENT` zero. Echo the requested and resolved domain/analytic, Site, UTC window and display timezone. The UI persists Site/domain/dates in its URL; date change makes a new read. Server bounds page size.

Return `schema_version`, Site/domain/window, display timezone/access basis, selection token, `knowledge_at`, `built_at`, typed status/reasons, coverage/limitations, watermarks, rows, `total_count` and `next_cursor`. `total_count` is null unless status is `CURRENT`. Watermarks contain accepted-source marker, S3 selected assessment/run/input/configuration and analytic selection, S4 matcher/version/pass/selection. Each row has stable `(tenant_id,site_id,finding_id)` key, canonical Finding UUID, exact `finding_revision_id`, episode bounds, lifecycle/transition, selected assessment/run/model/cohort, cited accepted-evidence/configuration IDs, limitations, relation/history links and `/sites/{site_code}/findings/{finding_id}?revision_id={revision_id}`. Exact links survive reload and newer revisions; lineage comes from the selected immutable revision.

Use one transactionally consistent read (no published projection in S4-04); `knowledge_at` is a selection cutoff, not arbitrary commit-ordered replay. **Complete discovery** starts with every UTC-day analytic window intersecting `[from,to)` and repeatedly inspects adjacent UTC days reachable across the current edge through an actual S4 20-minute continuity bridge on one fenced accepted-evidence/configuration/model basis, until a fixed point. This can extend beyond one neighbour on either side. Every inspected day needs S3 selection and canonical S4 match through its current selection seq; record each day and its S3/S4 selection seq in the selection token, including days with no row. Cap discovery at 62 distinct UTC-day windows total, including requested days. If the next reachable day exceeds the cap, return 409 `INDEX_CONTINUITY_LIMIT` with a reason and no rows, count or empty claim; this service cap does not prove continuity ended. Fence before/after read. Moving selection, affected dirty/leased/failed work, watermark mismatch, or late evidence/configuration/model change blocks `CURRENT`. A source-coverage limitation can coexist with a current assessment of available evidence, but cannot assert physical completeness.

`PENDING` means no usable completed selection; `UNASSESSED` no completed discovery basis; `STALE_PROJECTION` and `FAILED` may expose rows only from a durable prior selected snapshot holding exact canonical Finding/FindingRevision IDs, sort order and response basis. Recheck scope and label such rows/count historical, never current. S4-04 builds **no durable snapshot**, migration or new writer. Consequently stale/failed reads return no rows and null `total_count`; use `PENDING` or `UNASSESSED` when no usable completed selection exists, and `FAILED` may report the failure without historical rows. Never reconstruct stale rows from newer heads. None authorizes current count, empty/Healthy assertion or swapping stale links for a new head. A closed S3 Performance source gate returns 409 `PERFORMANCE_CUTOVER_CLOSED` with its reason and no rows/count/empty claim; exact pinned detail remains a separate audit route. Consume S4-05's reviewed stored gate form when merged.

One row per canonical Finding; merged-away IDs remain relationship links. Extension changes its revision; separated recurrence gets another Finding ID and link. Include closed and unconfirmed episodes. Intersect iff `episode_start < to && episode_end > from`; boundary touch is excluded. Order selected `episode_start` descending, then stable Finding UUID ascending; never by money, lifecycle or arrival. Cursor binds tenant/Site/domain/window, basis/selection token and last sort key. A well-formed cursor whose bound scope or fenced basis changed returns 409 `INDEX_BASIS_CHANGED` with a machine-readable reason and instruction to request page one without a cursor; return no rows, count or replacement cursor. A malformed cursor returns typed 422. Pages cannot splice revision sets. No priority tuple until a producer is reviewed.

Optional amount cell starts **unavailable**. On the stacked S5-01/LR-01 baseline, LR-01 `money_eligibility` is reviewed but S4-05 stored accepted-ID provenance is unmerged: show no current amount. After **both** reviewed contracts enter the baseline, separate review may allow amount only for the exact selected FindingRevision/window/basis and consequence head, open source, current list/consequence, eligible series, priced quantity/price and known source/display unit. Withheld/pending, mixed/unknown source, stale, wrong revision/window, unpriced or closed source means no current amount; old values use explicit audit links. No sum, savings inference or unpriced-as-zero. Money does not gate row/empty delivery.
