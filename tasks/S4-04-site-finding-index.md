## Read contract (route, DTO and cursor are new)

Add `GET /api/sites/{site_code}/finding-index?domain=mini-grid-dispatch&from=<UTC>&to=<UTC>&limit=<bounded>&cursor=<opaque>` (route spelling is an Architect question below). Resolve tenant/Site via Finding access before discovery: established 401/403/404 and no foreign count. Require explicit domain and UTC half-open `[from,to)`, `from < to`, maximum 31 UTC days; typed 422 otherwise. Echo Site, UTC window and display timezone. The UI persists Site/domain/dates in its URL; date change makes a new read. Server bounds page size.

Return `schema_version`, Site/domain/window, display timezone/access basis, selection token, `knowledge_at`, `built_at`, typed status/reasons, coverage/limitations, watermarks, rows, bounded current `total_count` and `next_cursor`. Watermarks contain accepted-source marker, S3 selected assessment/run/input/configuration and analytic selection, S4 matcher/version/pass/selection. Each row has stable `(tenant_id,site_id,finding_id)` key, canonical Finding UUID, exact `finding_revision_id`, episode bounds, lifecycle/transition, selected assessment/run/model/cohort, cited accepted-evidence/configuration IDs, limitations, relation/history links and `/sites/{site_code}/findings/{finding_id}?revision_id={revision_id}`. Exact links survive reload and newer revisions; lineage comes from the selected immutable revision.

Use one transactionally consistent read or atomically published projection; `knowledge_at` is a selection cutoff, not arbitrary commit-ordered replay. **Complete discovery** means every UTC-day analytic window intersecting the request and neighbours reachable through S4's 20-minute continuity rule has S3 selection and canonical S4 match through its current selection seq on one accepted-evidence/configuration/model basis. Fence before/after read. Moving selection, affected dirty/leased/failed work, watermark mismatch, or late evidence/configuration/model change blocks `CURRENT`. A source-coverage limitation can coexist with a current assessment of available evidence, but cannot assert physical completeness.

`PENDING` means no usable completed selection; `UNASSESSED` no completed discovery basis; `STALE_PROJECTION` keeps prior rows/IDs and a reason; `FAILED` reports failed work with prior rows historical. None authorizes current count, empty/Healthy assertion or swapping stale links for a new head. A closed S3 Performance source gate returns 409 `PERFORMANCE_CUTOVER_CLOSED` with its reason and no rows/count/empty claim; exact pinned detail remains a separate audit route. Consume S4-05's reviewed stored gate form when merged.

One row per canonical Finding; merged-away IDs remain relationship links. Extension changes its revision; separated recurrence gets another Finding ID and link. Include closed and unconfirmed episodes. Intersect iff `episode_start < to && episode_end > from`; boundary touch is excluded. Order selected `episode_start` descending, then stable Finding UUID ascending; never by money, lifecycle or arrival. Cursor binds tenant/Site/domain/window, basis/selection token and last sort key. A changed basis invalidates it with a typed restart-first-page response; pages cannot splice revision sets. No priority tuple until a producer is reviewed.

Optional amount cell starts **unavailable**. On the stacked S5-01/LR-01 baseline, LR-01 `money_eligibility` is reviewed but S4-05 stored accepted-ID provenance is unmerged: show no current amount. After **both** reviewed contracts enter the baseline, separate review may allow amount only for the exact selected FindingRevision/window/basis and consequence head, open source, current list/consequence, eligible series, priced quantity/price and known source/display unit. Withheld/pending, mixed/unknown source, stale, wrong revision/window, unpriced or closed source means no current amount; old values use explicit audit links. No sum, savings inference or unpriced-as-zero. Money does not gate row/empty delivery.
