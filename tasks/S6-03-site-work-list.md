## Read and UI contract

- One consistent DB snapshot selects `created_at >= from AND created_at < to` and latest event by `(recorded_at,id)`, never `occurred_at`. Return row key `(tenant_id,site_id,action_id)`, code, creation time, origin Finding and FindingRevision IDs, selected event ID/recorded time, lifecycle reduced by the same `actions.lifecycle` reducer used by Action detail, canonical and exact-event Action links. At the same fence, list lifecycle must equal Action detail lifecycle. If S6-02a has merged, show persisted `RESOLVED` and `RESOLUTION_WITHDRAWN` as recorded Action events; the list derives no verification verdict of its own. Order `created_at DESC, action_id ASC`; bounded page and opaque cursor bind tenant, Site, window, selection fence and last sort key.
- Echo scope/display timezone, `read_at`, max included creation/event-recorded fence or explicit zero-row fence, total and next cursor. `CURRENT` only after successful scoped read. Zero means no persisted Actions created in this Site/window. A changed fence invalidates page 2 and requires reload from page 1. Preserve historical Action detail separately.
- 401 unauthenticated, 403 known forbidden, 404 foreign/nonexistent Site or root. Invalid/unbounded window, changed cursor, unavailable store or inconsistent snapshot is typed refusal, never empty success. An unparameterised Site Work entry shows a typed choose-window state until a bounded window is selected. UI keeps Site/window in URL, shows count/page basis, exact FindingRevision and ActionEvent links, Unknown/error distinctly, native keyboard navigation and no invented verification result.
