## Result and boundary

The separate simulated gateway publishes durable `GatewayDiagnosticsV1` reports independently of readings. Lab shows local queue depth and oldest age, last device contact, clock offset when measured, disk pressure, holds and sealing failures after restart. A selectable registered Kobo delay run demonstrates a report absent before its declared release, then admitted with original `source_time` and release-time `published_at`. Repeatable local disconnect/reconnect and disk-pressure cases preserve sealed Batch V2 bytes and leave missing delivery visible. No central upload, server receipt, Site Evidence or Site Health claim occurs here. S2-02 owns authenticated central diagnostics and batch dispositions; S7 later interprets centrally received source health.

S2-01b already provides authenticated host-to-gateway IPC, V3/Batch V2 bytes in a WAL SQLite ledger, `STAGED` batches, `SEALING_PENDING`/`SEALING_REFUSED` states, held reports and registered Stage reads. It does **not** publish diagnostics or admit delay-window reports. Its injected frozen-delay refusal test is a fail-closed regression, not a selectable delayed-run proof. The gateway remains the source of local queue facts; Lab-private causes and oracle never cross into diagnostics or envelopes.

## Acceptance criteria

1. **R1 before fault work.** Close the S2-01b re-review carry: `seal_refusal` currently keys, deletes and looks up by `(source,epoch,snapshot)` while sealing groups also differ by outbox `state`. Migrate the durable key and related write/delete/read paths to include state, or obtain an equivalent state-safe contract without erasing a refused `READY` group when a sibling `STAGED` group seals. Preserve existing sealed bytes and IDs. A mixed-state fixture must show the refusal after restart, partial sibling progress, and clearance only when that same group succeeds. Keep `STAGED` limited to all **admitted** envelopes sealed; holds, `UNBATCHABLE`, unbatched suffixes and active refusal remain separate.
2. **Diagnostic wire and ledger.** Implement the technical design's `GatewayDiagnosticsV1` as a separate bounded canonical report with schema, registered Site/gateway, epoch, local diagnostic sequence, `observed_at`, source contacts, queue count/oldest age, `OK|WARN|STOP` disk pressure, nullable clock offset, mapping error count and digest. Allocate sequence and insert exact bytes/hash in one SQLite transaction; retries and restart return the same identity and bytes. Persist `diagnostic_outbox` state and expose a local read through the existing authenticated IPC. The declared emission cadence and limits are configuration, frozen/provisioned locally and returned with the read so S2-02 can later compute freshness from server receive time. No local `received_at`, `ACKED`, synthetic receipt or AcceptedEvidence row is created.
3. **Truthful counters and pressure.** Derive queue count/age from ledger rows, distinguishing sealed pending batches, admitted but unbatched envelopes, held reports and active sealing refusals. In this simulated-only slice, last source contact advances only on an observed public simulated report/contact and must be labelled as such, not as proof of contact with a physical device; absence is unknown, not healthy. Clock offset is unknown unless actually measured or explicitly injected by a labelled fault fixture. A configured/injected `STOP` pressure refuses new acquisition before sequence assignment, preserves existing unacknowledged envelopes and batch bytes, and remains visible locally and in a diagnostic when storage permits. Make `WARN` and `STOP` triggers explicit in the fixture; never claim actual hardware pressure from an injected case. A disconnected or crashed gateway is unavailable, not a healthy zero queue.
4. **Delayed local admission.** Add a versioned, selectable registered publication profile/fixture with a frozen reporting-path delay window. Follow `D-2026-10-09-s2-simulated-publication-clock`: persist a per-run virtual publication clock and Lab-private pending report with its public value, original source instant, scheduled release instant and stable admission key. A world step may advance this clock to its reached simulation instant; explicit advancement may continue after the world run completes, without advancing the kernel. Pause/restart does not advance it automatically; backward movement refuses and a repeated advance is idempotent. Before due time, the report has no V3 envelope or sequence and is visibly pending in Lab; unrelated due reports may seal. At or after due time, advance the gateway's persisted scoped virtual clock, submit the same public reading, retain its original `source_time` and value, and let the gateway stamp `published_at` from its actual virtual admission instant (not a backdated scheduled instant). If a step skips past due time, use that later instant. Restart/retry must reuse the prior identity and bytes. Do not remove S2-01b's safe refusal for unsupported profiles. No private delay cause, scheduled release or scenario control enters V3/Batch V2/GatewayDiagnostics.
5. **Fault scenarios and Lab view.** Version a small manifest that separates public expected reports, intentionally missing/delayed cases, gateway fault controls and private Lab oracle. Exercise host-to-gateway link loss/reconnect and disk-pressure `STOP` through the real local path; after reconnect, sealed batches and diagnostics remain byte-identical and pending. Show local state in Lab Gateway & Ingestion after host/gateway restart with timestamps, source scope, counts and explicit missing/unavailable text. A local IPC retry is not an HTTPS retry; S2-02 must prove network exact-byte retry and central receipt. Do not present a current diagnostic as proof the device or asset is healthy.
6. **Lab carries and layout.** Close S2-01b F2: while the independent Stage read is pending, unavailable or its basis is unknown, an older already-committed YAML artifact must not offer enabled Resume/Retry release; when Stage resolves after Site import, show the basis block. The server refusal remains. Address or measure F3 on a clean runs store: registered run at 640 px, later full-run sections and the fixture-driven narrow `Sealing refused` table. Record measured width and any remaining limitation; do not count a polluted `var/runs` run as clean evidence.
