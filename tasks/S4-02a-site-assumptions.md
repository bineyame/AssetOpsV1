## Persistence, publication and read contract

1. New Postgres migration: `financial_assumption_revision` with UUID ID, tenant/Site FK (Site required in this slice), stable key `diesel_price_per_litre`, revision number, ISO currency, unit `currency/L`, explicitly authored nonnegative finite `numeric`/Decimal value, basis enum `AUTHORED_ESTIMATE|CONTRACT_RATE|RECORDED_PURCHASE`, source reference, authored `[valid_from,valid_to)` intent, server `recorded_at`, server actor kind/id, nullable human `author_id`, channel, authorization basis, service/job/fixture provenance and idempotency key. Unique `(tenant_id,site_id,key,revision_no)` and publication key. No tenant fallback, default price, negative rate, SCENARIO operational publication, or client-supplied actor/author. The price value/basis/source and authored validity are immutable. Record effective validity separately as assignment rows keyed to the price revision with `[valid_from,valid_to)` and `[recorded_from,recorded_to)`. Assignment rows are immutable except a set-once `recorded_to` (trigger-enforced, as `foundation_revision.superseded_at`). Constraint: `EXCLUDE USING gist (tenant_id WITH =, site_id WITH =, assumption_key WITH =, tstzrange(valid_from,valid_to,'[)') WITH &&, tstzrange(recorded_from,recorded_to,'[)') WITH &&)`. Superseded and new rows share one server instant (`recorded_to` = `recorded_from`), taken with `clock_timestamp()` after acquiring the series lock (not transaction-start `now()`); it must be later than the series' latest `recorded_from`, and every stored range must be non-empty (CHECK `valid_from < valid_to` where bounded, and `recorded_from < recorded_to` when set). A trigger (it spans two tables, so not a CHECK) requires every current assignment's valid range to lie inside its revision's authored range. Index both time axes. A future publication closes the old assignment at `t` and retains its original revision ID for earlier time. A middle-only correction supersedes the old assignment, records two current assignments of the **same old price revision** for the unaffected left/right spans, and assigns the corrected middle to the new revision. Historical assignments remain selectable at older recorded cutoffs. Thus a price row is never rewritten, a pinned consequence still finds its original price ID, and `STALE` arises only if the price revision selected for its entire window actually changes. This assignment table is the migration's explicit resolution of review carry M1 and the technical design's simplified single validity row.
2. Publish only from a server-side CLI/job/fixture with a stable service principal, explicit Site, source, expected prior revision and idempotency key. The CLI is an administrative demo trigger, not an anonymous UI action; record SYSTEM/job/fixture provenance. Each publication carries a stored `change_kind`, shown in History. `INITIAL`: the first price for a Site/key, or one covering time with no current price; it may be backdated, and is refused with 409 if its range overlaps any current assignment. `SUCCESSION`: `valid_from` ≥ the server `recorded_at`; it may only truncate the single open-ended current assignment containing `valid_from`; any other overlap is refused with a typed 409. `CORRECTION`: backdated or bounded; requires a reason; supersedes the current assignments over its authored range and re-assigns the uncovered left/right remainders to their same old revisions. The transaction locks the Site/key series, rejects concurrent prior mismatch and conflicting retry payload, and returns the same revision ID on exact retry. After the transaction no two current assignments overlap (enforced by the item 1 constraint), and an overlap that `change_kind` does not permit is refused. S4-02a builds the human write route with no success path. Refusal order: 401 (no verified principal; the default access), then 422 (any body actor or author field), then 403/404 (tests inject these via the access seam); an admitted request without a verified human principal returns 401. It must not use `development_access`.
3. `GET /api/sites/{site_code}/financial-assumptions?key=&valid_at=&recorded_at=&after_revision_no=&limit=` and `/financial-assumptions/{revision_id}` (equivalent Site-scoped routes acceptable) return exact current/at-recorded-cutoff selection, selected ID, bounded pagination/cursor, valid and recorded intervals, price/currency/unit, basis/source, actor/channel/provenance and explicit no-price or conflict/source-failure state. Half-open boundary: a price ending at `t` does not cover `t`; another beginning at `t` does. An exact ID is stable after later writes. Reuse Finding API's tenant/Site 401/403/404 and 503 semantics; a bad/foreign revision never falls back to latest. Never promise arbitrary S3 `knowledge_at` replay: the cutoff selects stored assumption knowledge only.
4. The selected Finding route/Financials bridge holds Finding ID and exact FindingRevision ID, selected window and accepted-lineage link to S4-03. Before `fuel-cost-1` exists, display `QUANTITY_UNAVAILABLE`; when a separately supported technical quantity exists but no whole-window price, display `UNPRICED` with null amount/currency. These are typed states, not zero and not mock numbers. No consequence revision is manufactured in this slice. Closed Performance gate and pinned historical Finding follow S4-03 audit rules.
