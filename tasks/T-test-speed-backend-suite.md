## Chosen approach and rejected shortcuts

1. **First remove repeated head migrations from ordinary Postgres setup.** Build one clean, migrated `*_test` template for each run, then clone to isolated worker DBs with `CREATE DATABASE ... TEMPLATE` from an admin connection outside the template. Clones must use names ending `_test`; source template must have no open sessions, and all generated DBs need explicit owner/run identity and cleanup in `finally`. Assert migration head on each clone. Keep the existing destructive upgrade/downgrade tests on dedicated clones that no ordinary test shares. If cloning is unavailable under the local role, report it and keep the tested serial migration path; never fall back to a shared live DB while claiming isolation. Rework fixture ownership so ordinary module setup truncates and never drops another module's schema. Preserve any tests whose own reset/migration is their assertion.
2. **Then use bounded pytest-xdist workers, one DB per worker.** Add xdist to backend dev dependencies. Use worker identity only for DB routing; child processes inherit the worker URL. Begin with `-n 2`, measure `-n 3` only if connection counts remain safe, and pick the fastest stable count. Do not use `--dist load` if order-sensitive modules share state; use module grouping or explicit serial group for migration/process/lock tests. One worker DB is not sufficient if tests in that worker race a child process or a module rebuilds schema: identify and serialize or isolate those cases before enabling the default command. No `-n auto` on this machine.
3. **Bound connections rather than assuming worker DB isolation bounds sessions.** Give test-created SQLAlchemy engines small pools (initial candidate `pool_size=1, max_overflow=1`) and dispose stores/clients explicitly where ownership permits. Account for migration `NullPool`, child processes and in-test concurrency when sizing; collect actual peak `pg_stat_activity` and retain legitimate concurrency assertions. `gc.collect()` removal is optional only after proof that engine lifecycle is deterministic. Do not alter production pool defaults simply to improve tests.
4. **Focused suites are a workflow speed gain, not a replacement full run.** Add documented area commands and, only if useful after collection audit, explicit `unit`/`postgres` markers for focused selection. Missing DB must remain visible as skipped and disqualify full proof; markers must never deselect tests from the full command. File-path focus can ship before marker changes. Avoid a broad auto-marker that mislabels mixed files such as `test_s3_demo_configuration.py:126-149`.
