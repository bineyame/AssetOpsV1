## Read and route contract

- Keep canonical `/sites/{site_code}/findings/{finding_id}`; use the existing `revision_id` query and a named Evidence or History view in that root. Preserve Site, Finding, selected revision and selected window context in tabs, links, browser back/forward and reload. An omitted revision means latest **at read time** and is labelled so; a pinned ID stays pinned after an append. Never silently reset an invalid/foreign revision to latest.
- Implement `I-finding-evidence-read` and `I-finding-history-read` as bounded, tenant/Site-scoped reads over persisted revisions. Extend `GET /api/sites/{site_code}/findings/{finding_id}?revision_id=&after_revision_no=&limit=` or add child routes under the same root; expose exact selection, pagination/total/next cursor, source/cutover status and typed refusals. Reuse S4-01 401/403/404/409/503 behavior: 401/403 are access-seam tests under `DEVELOPMENT_TENANT_OPERATOR_CONTEXT`; unknown/cross-Site root or revision is 404; store/lineage failure is unavailable, never empty success. An unpinned current read is 409 while Performance cutover is closed. A pinned revision can display only as `SOURCE_CLOSED` audit material, without live S3 drill-down or current Finding claim.
- Evidence bundle membership is the **selected revision's cited accepted evidence** (`revision.cited_evidence` / `finding_revision_evidence`), distinct from `revision.runs[].input_evidence_count` and `input_evidence_sha256` (the full analytic input set). Return/count the complete cited set, paging if needed; a 60-row preview or the S3-01u day browser is not completeness proof. Show accepted evidence ID, role/value/unit/quality, source time, batch/gateway/source/epoch, message ID, envelope digest and selected interval/window assessment/run/model/cohort, Foundation, binding and control basis where recorded. Link by exact accepted ID/message ID to the existing Site Evidence inspector (`GET /api/sites/{site}/evidence/records/{evidence_id|message_id}`) and by assessment revision ID to S3 Dispatch. Inspect original envelope text there. Never derive lineage from a label, current configuration or private Lab truth. If an expected accepted row, envelope, basis or assessment cannot resolve, name the broken link and withhold the affected positive lineage claim; do not fabricate a row or call it zero evidence.
- History returns **all** stored FindingRevision summaries in stable `revision_no` order, with exhaustive paging. Show recorded time, revision number/ID, transition, lifecycle, support change, period, candidate/necessary/indeterminate quantities, selected/prior assessment IDs and basis/model IDs. Opening a row reads that exact revision and its Evidence. `BASIS_REFRESHED` entries remain individually selectable even if visually grouped; unchanged support is not a new issue. Distinguish source time, acceptance/receipt time when available, analytic completion and Finding recorded time. Late evidence appends; it never rewrites old revisions. The selected stored revision and its basis IDs are the historical anchor. S3's worker `knowledge_cutoff` is not commit ordered, so do **not** offer arbitrary `knowledge_at` replay or imply a timestamp excludes every later acceptance.
- One revision has an explicit “No earlier versions” state. A zero-row Site/window without a Finding remains S4-01's assessed/no-Finding or pending state, not empty History. Keep merged/split/recurrence links and old URLs; an old revision or closed-source audit leads with its non-current status before recorded positive facts.
