## Shared contract

1. A server-side SYSTEM command registers `AUTHORED_DEMONSTRATION` with fixture/spec ID **and version** (authored P01 and P02) or `REGISTERED_SIMULATION` with server-recorded run ID, immutable run identity/digest, registered `SIMULATED` gateway, and proof the exact batch came from that run. Both pin tenant/Site UUID, gateway/source, external batch ID, canonical Batch V2 payload SHA-256, immutable publication ID, server-resolved principal, authorization basis, channel, trigger and recorded time. Private scenario truth stays outside product evidence. `SIMULATED`/`LIVE`, credential, client text, Site/day match or private manifest alone confers no designation. No public designation route.
2. Registration and `open_batch` take the **same transaction-scoped advisory lock** on the scoped tenant/Site/gateway/source/external-batch key and check admission under it. Identical retries return the same ID; changed content or publication-ID reuse fails. Registration after *any* admission, including partial admission, fails. `open_batch` binds only the exact preauthorized digest/identity commitment in its admission transaction; matching key with mismatched commitment fails rather than downgrading to unknown. Unpublished upload remains accepted with unknown source. Accepted IDs inherit immutable batch linkage across chunk restart; duplicate disposition retains its original accepted ID/provenance; rejected/conflict rows acquire none. No retroactive assignment or Site/day backfill.
3. Resolve each selected FindingRevision's immutable cited accepted-ID set. Resolve each consequence revision separately from the union of that FindingRevision set and **its own quantified power-interval accepted IDs**. Return `finding_revision_id`, `consequence_revision_id` where applicable, exact cited/power/union IDs, per-evidence `accepted_evidence_id`, `batch_id`, `publication_id`, `source_class`, fixture ID/version or run ID/basis, all distinct publication IDs, `problematic_accepted_evidence_ids`, state and typed reasons. Historical revisions retain their own state.

| Scoped citation set | State / reason |
| --- | --- |
| Nonempty; every ID bound to authored publications with same fixture ID/version, including several publication IDs | `AUTHORED_DEMONSTRATION`; list every publication ID |
| Nonempty; every ID bound to one run, or several runs with explicitly recorded compatible run basis | `REGISTERED_SIMULATION`; list run/publication IDs |
| Different authored fixture/version; incompatible runs; crossed classes; bound and unbound mixed; consequence-only power conflicts | `MIXED` with exact IDs and basis reason |
| Empty; no positive binding; missing, foreign-Site or broken accepted-ID/publication link | `UNKNOWN` with exact IDs/reasons; broken link precedes `MIXED` |
