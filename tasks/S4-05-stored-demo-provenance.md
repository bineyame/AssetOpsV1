## Implementation contract

1. **Publication, before upload (new).** Add migration `0014` from main's `0013_schedule_state` head for an append-only `evidence_publication` table and a scoped immutable batch-publication binding (either a nullable `ingestion_batch.publication_id` or a one-to-one insert-only link). Publication has UUID ID; tenant/Site UUID; external batch ID, canonical Batch V2 payload SHA-256, gateway/source IDs; designation `AUTHORED_DEMONSTRATION`; fixture/spec ID and version; server-resolved `actor_kind=SYSTEM`, stable service principal, authorization basis, source channel, triggering job/fixture ID, and server `recorded_at`. Use composite tenant/Site FKs, unique publication identity and unique exact batch commitment; prohibit update/delete or conflicting reuse. A real/live assertion is **not** inferred from absence of designation or `source_mode=LIVE`.
2. **Authorization (new).** Expose only a server-side administrative SYSTEM fixture/CLI command with fixed service principal and explicit configured allowlist/authorization basis, modelled on `publish_assumption.py`; no public gateway or browser write route. It must validate fixture/spec identity/version and canonical batch digest against the exact payload, then insert the publication through an extension of `PostgresEvidenceLedger`. No `--actor`, `--author` or client-supplied provenance text can become authority. Refuse wrong tenant/Site, gateway/source, missing or conflicting batch digest, publication ID reuse with changed content, and publication after any batch admission. An identical retry returns the same publication. Registration and subsequent `open_batch` must serialize for the same scoped batch key so ingestion cannot race an after-the-fact designation. The upload remains valid without designation but has `UNKNOWN` authorship.
3. **Accepted binding (new).** `open_batch` matches only the preauthorized exact tenant/Site/gateway/source/external-batch-ID/digest commitment. The accepted evidence already references the scoped batch (`0005:165,197-200`); expose the immutable publication ID per **accepted evidence ID** through that link, including interrupted/resumed chunks. A duplicate disposition retains the original accepted ID and its original provenance; it cannot relabel old evidence. Rejected/conflict rows confer no provenance. No retroactive assignment or mutable backfill of historic accepted rows. Fail the upload if a matching publication conflicts; never silently downgrade a claimed publication to unknown.
4. **Read and amount rules (new).** Resolve every cited accepted ID under the requested tenant/Site, returning publication ID, designation and fixture/spec version per record plus a set-level state: `AUTHORED_DEMONSTRATION` only when every relevant cited ID is bound to a consistent authored publication basis; `MIXED` when some cited IDs have that designation and others have no designation or a different basis; `UNKNOWN` when none is designated or any cited ID/link cannot be resolved (and retain exact problematic IDs). A broken link takes precedence over `MIXED`. A FindingRevision uses its immutable cited set, not an episode date. A consequence uses its **own** quantified power-interval evidence IDs as well as the selected FindingRevision cited set; a later revision can differ. Preserve historical revision-specific results; do not relabel a historical revision from the current head. Mixed/unknown reads say “Source not confirmed” with exact IDs and show no current amount wherever this source gate is used. Preserve `tasks/S5-01-site-overview.md:39-41` no-amount rule when its branch merges. Keep existing “Demonstration data” wording for fully authored P01; propose concise mixed/unknown copy to owner at checkpoint. Remove runtime calls to `demonstration_case` and its date/spec cache; retain its old test only as regression proving same-day real/unknown is not labelled authored.
5. **Writer and migration boundary.** Extend the existing ledger writer's allowed tables in rule 8 (`configuration-persistence.ps1:624-625`); require INSERT only for publication/link rows, and prevent ledger or other writers from UPDATE/DELETE of these immutable rows. Preserve all eight existing writer allowlists, reverse ownership and driver non-vacuity. Add guard probes for permitted ledger INSERT, forbidden other-writer INSERT, mutation, omitted writer/import, and client route attempting designation. If LR-01 merges first and contributes migrations 0014/0015 on its branch, re-chain this migration to the new head and renumber it; never create a parallel head. Recheck S5-01 read composition after its merge without stacking this task on that unmerged branch.

Cutover: existing accepted rows with no pre-admission publication remain `UNKNOWN`; do not backfill authorship from the old Site/day spec. The P01 positive proof must prepare its publication first, then ingest a fresh, isolated exact fixture batch and inspect its accepted IDs. A host that already holds P01 evidence must show the cautious state until a separately authorized new publication and new accepted IDs exist. Do not mutate or delete its old Evidence, Finding or consequence history.
