## Outcome and predecessor gate

A completed registered simulated Kobo run can Commit its **existing** sealed Batch V2 bytes from the separate gateway through authenticated HTTPS. Postgres records durable per-ordinal acceptance, duplicate, rejection or conflict decisions and a queryable Receipt V2. Site Evidence and Evidence Analysis open a selected source-time window, distinguish pending/limited/conflicting evidence, and resolve a visible row to its exact original envelope, accepted-as Foundation/binding revisions and receipt after reload. Lab Commit shows pending, partial and terminal release accurately. Central gateway diagnostics show server contact and `CURRENT|STALE|UNKNOWN`, without treating a diagnostic as AcceptedEvidence or asset health. This is the first S2 owner review checkpoint.

S2-01c R1 (fault, host restart, then post-run advance skips unadmitted ordinary reports) is a **predecessor release gate**: implement `D-2026-10-09-s2-publication-gap-and-batch-boundary` and obtain fresh independent re-review before this task claims the fault/delayed run is complete. A `PUBLICATION_GAP` refusal or terminal `PUBLICATION_INSTANT_PASSED` run remains visibly incomplete through Lab Commit even when some sealed batches have receipts. Per-boundary sealing currently makes 245 Batch V2 objects for 292 Kobo envelopes; plan bounded, resumable upload and receipt progress for this scale, with no one-batch-per-run assumption. S2-01c's C2 diagnostic-byte assertion, C3 seeded layout proof and N1/N2 re-review carries remain recorded for the S2 owner checkpoint unless closed earlier.

## Acceptance criteria

1. **Credential and identity boundary.** Use `D-2026-10-09-s2-pilot-gateway-upload-credential`: TLS plus an independently provisioned high-entropy opaque bearer credential per registered gateway for both Batch V2 and diagnostics. Issue the secret once into protected gateway configuration; store only selector/reference and one-way verifier server-side, never raw secret in product rows, gateway SQLite, logs or responses. Authenticate before processing a batch or diagnostic and derive immutable tenant/Site/gateway/`SIMULATED` mode from the credential/registration, not caller fields. Require active gateway and current source enablement/affiliation for each batch source on every upload, including identical retries; diagnostics may retain historical contact for a disabled source but must verify its gateway/Site affiliation. Separately check original immutable Foundation/binding/source-time basis for accepted-as evidence. Revocation/disable takes effect on the next request; rotate credentials without rewriting sealed bytes. Distinguish 401/403/422/409. A wrong credential, cross-Site source or pending/unregistered identity creates no Evidence or Site-visible receipt. The local IPC credential and S1 development-tenant route grant no upload authority; phase 1 may inject an authenticated principal, but network uploads stay closed until the TLS/bearer boundary is implemented.
2. **Immutable batch and per-record decisions.** Extend `POST /api/ingestion/batches` and `GET /api/ingestion/batches/{id}` to Batch/Receipt V2 using the exact canonical bytes, payload SHA-256, ID, source order and vectors S2-01b sealed. Bound upload size and count. Postgres owns `ingestion_batch`, `accepted_evidence`, `evidence_rejection`/conflict, `ingestion_disposition`, authenticated `batch_refusal` and `recompute_job` per technical design §1. A same ID/same bytes retry returns the durable state; same ID/different bytes is 409 without overwriting it. Lock batch progress in short transactions; write each ordinal's decision, counters/watermark and recompute job atomically. A crash after server commit is recovered by querying/retrying the **same** batch bytes; a partial batch returns 202 `IN_PROGRESS` until a terminal receipt. An invalid sibling does not erase valid decisions. Authentication failure makes no Site ledger row; an authenticated whole-batch refusal is distinct from per-ordinal rejection.
3. **Accepted-as validation and normalization.** Parse V3 MEASUREMENT strictly, verify derived message ID, source scope, original registered Foundation and binding references, the exact Batch V2 `foundation_valid_from` spelling (including fractional seconds), and each envelope's `source_time` in both original half-open valid periods. Accept a once-registered, originally time-valid pair later superseded with an outdated-configuration flag. Reject absent/unregistered references or an out-of-period closing-boundary reading with a specific reason. Keep source-unit value/text and canonical envelope as `original`; apply the **selected registered binding** conversion centrally to persist normalized value/unit, role, quality and immutable revision IDs. Do not infer an older identity from today's mutable external names. ENUM uses its registered map; unsupported POLICY/OPERATIONAL_RECORD remains `SCHEMA_UNSUPPORTED`. `source_time` and `published_at` on `RUN_VIRTUAL` reports are virtual instants; `received_at` is server real UTC. A virtual-to-real subtraction is never labelled network lag.
4. **Identity hardening before acceptance.** Make `asset.asset_code` stable at the Postgres boundary and reconcile any already changed rows before Evidence acceptance, as the S2-01a Architect amendment requires. Prove a direct SQL update is refused and the immutable binding asset UUID still resolves to the intended selected Foundation component. Review Site type and gateway/source external-ID mutability against original snapshot identity during credential/lineage implementation; use immutable registered UUID references for acceptance. Current Site name/timezone frozen on a Draft are not historical metadata at `knowledge_at`; do not display them as such.
5. **Gateway delivery and Commit.** Extend the separate gateway's staged batch/receipt slots to send through the authenticated HTTPS route. Lab Commit authorizes each eligible sealed `STAGED → READY` batch for a new registered run and records a private manifest linking run to existing batch IDs; aggregate Stage may still be partial or `SEALING_REFUSED`. It cannot write Evidence directly or re-envelope a file Stage. Verify Receipt V2 hash, batch ID, digest, ordinal/message IDs and count before transactionally persisting acknowledgements; a timeout or 202 leaves unchanged bytes retryable. ACKED/DEAD_LETTER reflects durable terminal decisions only. A sealed sibling batch may upload while another group is `SEALING_REFUSED`, but Lab shows a partial run and refuses a fully released claim until every admitted envelope is sealed or explicitly resolved and no publication gap remains. Held reports remain visible, not implied accepted. Pre-import YAML Stages remain read-only; historical sealed batches replay only by the explicit migration path.
6. **Central diagnostics.** `POST /api/gateways/{gateway_id}/diagnostics` authenticates the same registered scope and stores append-only `gateway_diagnostic` with server `received_at`; an identical `(gateway,epoch,diagnostic_sequence)`/hash returns the same row and changed bytes are 409. `GET /api/sites/{id}/gateway-health` shows last server contact, registered declared cadence (60 seconds in the demo), source-contact observations, queue count/oldest age, clock offset or Unknown, mapping errors, pressure and `CURRENT|STALE|UNKNOWN` from receive time. Missing reports become stale/unknown after the declared cadence; an outage survives reload. V1 `disk_pressure` is operative level, without measured/injected provenance on the wire; a simulated `STOP` is labelled a reported simulated-gateway condition, not measured hardware. Queue count includes admitted unbatched plus sealed pending envelopes, not holds; V1 reports only the defined mapping-error subset, so central health must not invent all-hold or seal-refusal counts. The fuller held/refused breakdown remains in the local Lab read. Diagnostics are operational records, never AcceptedEvidence, asset health or proof of physical device contact.
7. **Site reads and visible limits.** Switch imported KOBO-001 `GET /api/sites/{id}/evidence?from=&to=` and `/evidence/records/{id}` to Postgres only after the migration comparison below passes. Return tenant/Site scope, half-open selected window, stable cursor, accepted/rejected/conflict and duplicate disposition, coverage, provenance and source/projection watermark; distinguish no data, rejected-only, delayed/pending, partial batch and stale projection. Site Evidence and Evidence Analysis show source, virtual publication and server receive times with their clock labels; use server timestamps for real ingestion/receipt lag. A row opens original and normalized values/units, exact envelope digest/text, gateway/source, Foundation/binding revisions and per-ordinal receipt. A duplicate resolves its first accepted ID; a conflict preserves the original and opens the conflict record. Do not present S3 dispatch, capability or healthy-service conclusions from this Evidence view.
