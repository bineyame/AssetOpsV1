## Read and UI contract

1. **New** `GET /api/sites/{site_code}/financial-assumptions/consequences?recorded_at={UTC instant}&after={opaque cursor}&limit={1..100}` (exact route name may follow API convention). Missing `recorded_at` selects a server-fixed UTC cutoff returned in the response; explicit cutoff must be timezone-aware. For the default Assumptions view, request consequence page one first, then pass its returned `cutoff.recorded_at` to the existing price read and all later price/consequence pages. Carry the cutoff in UI state for the default URL; do not rewrite `/sites/{site}/financials/assumptions` to `?recorded_at=`. Keep the S4-02a "Show the current prices" notice only for an explicitly selected URL cutoff; update the S4-02a walkthrough to assert the unchanged default URL and both responses' identical cutoff instant. Explicit cutoff URLs and consequence next-page URLs preserve that same instant through reload. The existing price API's no-cutoff `CURRENT` contract remains intact for other callers; this composed panel always sends an explicit cutoff after page one. Query `financial_consequence_revision.recorded_at <= cutoff`, tenant and resolved Site in one repeatable-read snapshot; do not depend on current heads to enumerate old rows. Sort by `(recorded_at DESC, id DESC)`. In that snapshot compute a fence over **all** in-scope rows at or before the cutoff, including off-page rows: count plus maximum `(recorded_at, id)` (null pair for zero rows). Bind tenant, Site, cutoff, limit, last sort pair and fence in the opaque cursor. Recompute the fence on each page in its own repeatable-read snapshot before paging; changed scope/fence refuses with typed 409 `CONSEQUENCE_HISTORY_BASIS_CHANGED` and the UI reloads page one without a cursor. Malformed or tampered cursors refuse with typed 400 and no rows. Follow the S6-03 pattern in `backend/assetops_backend/actions/site_index.py:10-14,174-182`. Fetch `limit+1`, return `next` only when more exists. Equal timestamps, empty set and final page neither duplicate nor skip rows within a matching fence; a late commit stamped at or before the cutoff changes the fence and restarts pagination. Reloading the same cutoff later can include that late-committed row because its database timestamp preceded commit. The fence count is internal; no displayed count or Site total is required.
2. **New** each row carries exact `finding_id`, `finding_revision_id`, `consequence_revision_id`, linked `price_revision_id` or typed absence, consequence `revision_no`, `recorded_at`, Finding/consequence valid window, price assignment valid and recorded intervals when available, consequence state, typed missing or closed-source state, and the exact S4-05b source block for *that version*. Join price via stored consequence-assumption link, never today's price. Preserve every immutable revision, including unpriced rows and prior price revisions; an absent price is not zero. A broken/foreign lineage is a typed unavailable row or integrity refusal, never a substituted link.
3. `CURRENT_AT_CUTOFF` means the row is the latest consequence revision recorded by the cutoff within the latest FindingRevision of its Finding recorded by that cutoff; all earlier rows are `HISTORICAL_AT_CUTOFF`. If that latest FindingRevision has no consequence by the cutoff, no row for that Finding is current at cutoff. Use `finding_revision.created_at` (application clock, unlike the consequence's database-clock `recorded_at`) to select revisions at or before the cutoff; a FindingRevision with a consequence recorded by the cutoff also qualifies even when its injected/skewed `created_at` is later. Choose the latest qualifying FindingRevision by `revision_no`, and the latest consequence within it by `(recorded_at, id)`. This is an audit classification, not a valid-at-time physical assertion. Show the cutoff and selected Site above the list. **This endpoint and panel never claim or display a current amount at any cutoff, including the server-defaulted cutoff.** The response has `current_amount_shown: false`; any displayed amount is labelled "Recorded amount — historical, assumption-conditioned audit history" with the exact S4-05b version source label and limitation. Show an amount only for that stored `PRICED` version when its existing exact-version source and historical money-display gates permit it; closed source hides even a recorded amount, and missing/withheld amounts are null. Do not call per-Finding `derive()` across the Site list or compute authorization in React. `CURRENT_AT_CUTOFF` rows link to Finding Financials for a separate current-money read under its own currentness, LR-01, source, quantity and price gates; that read alone may claim today's amount.
4. Scope before lookup: unresolved/foreign Site or foreign Finding or consequence ID returns 404/typed refusal with no row or timing leak. This Site-wide route has no `price_revision_id` filter: selected price history opens the full Site consequence list at the same cutoff, and stored row links identify the exact price used. A source gate closed for an otherwise stored row is shown as a typed closed-source state, not an empty Site history. Store/query failure is unavailable, not zero. Provide plain empty, loading, error, prior/current-at-cut and withheld states at 1440 and 390 px. Default copy explains “price changed; the measured result did not” only when supported; no raw IDs, codes or implementation language outside a labelled “How this was worked out” disclosure. Link to the exact Finding and its selected consequence, with a contextual deeper destination at both widths per `D-2026-10-16-w1-ux`.
