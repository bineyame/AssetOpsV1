## Read and UI contract

1. **New** `GET /api/sites/{site_code}/financial-assumptions/consequences?recorded_at={UTC instant}&after={opaque cursor}&limit={1..100}` (exact route name may follow API convention). Missing `recorded_at` selects a server-fixed UTC cutoff returned in the response and placed in next-page/UI URLs; explicit cutoff must be timezone-aware. The Assumptions price and consequence requests must share that exact cutoff. All pages use the *same* cutoff. Query `financial_consequence_revision.recorded_at <= cutoff`, tenant and resolved Site in one repeatable-read snapshot; do not depend on current heads to enumerate old rows. Sort by `(recorded_at DESC, id DESC)`; cursor encodes the last pair and cutoff, is validated for this tenant/Site and limit, and refuses mismatch/tampering as typed 400. Fetch `limit+1`, return `next` only when more exists. Equal timestamps, insertions after cutoff, empty set and final page must neither duplicate nor skip rows. No count is required.
2. **New** each row carries exact `finding_id`, `finding_revision_id`, `consequence_revision_id`, linked `price_revision_id` or typed absence, consequence `revision_no`, `recorded_at`, Finding/consequence valid window, price assignment valid and recorded intervals when available, consequence state, typed missing or closed-source state, and the exact S4-05b source block for *that version*. Join price via stored consequence-assumption link, never today's price. Preserve every immutable revision, including unpriced rows and prior price revisions; an absent price is not zero. A broken/foreign lineage is a typed unavailable row or integrity refusal, never a substituted link.
3. `CURRENT_AT_CUTOFF` means the row is the latest consequence revision for the latest FindingRevision of its Finding recorded by that cutoff; all others are `HISTORICAL_AT_CUTOFF`. This describes what was recorded then, not a valid-at-time physical assertion or today's current amount. Show the cutoff and selected Site above the list. A closed S3 source gate, unresolved source block, pending/stale consequence, LR-01 `PENDING_REASSESSMENT` or `WITHHELD_GENERATOR_SERIES`, or non-`CURRENT PRICED` exact head forbids a **current** amount. A closed source hides even recorded amounts, as the existing consequence UI does; other prior priced amounts may appear only as labelled audit history with exact links. Reuse server money-gate results; never compute authorization in React.
4. Scope before lookup: unresolved/foreign Site or foreign Finding, consequence or price IDs return 404/typed refusal with no row or timing leak. A source gate closed for an otherwise stored row is shown as a typed closed-source state, not an empty Site history. Store/query failure is unavailable, not zero. Provide plain empty, loading, error, prior/current-at-cut and withheld states at 1440 and 390 px. Default copy explains “price changed; the measured result did not” only when supported; no raw IDs, codes or implementation language outside a labelled “How this was worked out” disclosure. Link to the exact Finding and its selected consequence, with a contextual deeper destination at both widths per `D-2026-10-16-w1-ux`.

## Architect questions

1. Should the list include unpriced consequence versions with no price link? **Recommend yes:** they are part of Site interpretation history and need an explicit missing-price state.
2. Does `CURRENT_AT_CUTOFF` require both the latest FindingRevision and latest consequence within it? **Recommend yes:** a newer FindingRevision must demote all older Finding versions, even when their consequence chain has its own head.
3. Should a selected past cutoff ever show a “current amount”? **Recommend no:** it is audit history; only today's exact-head read may make a current-money claim after every existing gate passes.
