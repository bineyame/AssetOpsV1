## Persistence and tenant contract

1. Pin PostgreSQL 16 in local Docker Compose; add `psycopg` 3, SQLAlchemy Core and Alembic. Document start, migration and test commands. `DATABASE_URL` is required on the product path; only development Compose supplies a documented local default. Commit no credential. Migrations, never app startup, install tenant, site, asset, gateway, source and FoundationRevision DDL with tenant/site composite references, stable UUID row identities and the current design's immutable content and valid/recorded-time rules.
2. First migration enables `btree_gist` and a GiST exclusion constraint preventing overlapping *currently recorded* Foundation validity for one Site. A Site row lock serializes publish; the constraint catches concurrent mistakes. Missing extension privilege fails migration clearly. A separate disposable PostgreSQL test database runs all migrations from zero; no SQLite surrogate or developer-database test writes.
3. Until authentication lands, backend configuration resolves fixed development tenant `demo` at the request boundary. Client tenant IDs, headers and query values confer no authority. Every repository lookup/mutation receives and enforces resolved tenant UUID, including same site code in two tenants, cross-tenant UUID references and direct-by-ID reads. Product URLs retain `{id}` as stable site code within that tenant; API also returns internal UUID.

## Exact one-shot import

4. Provide one-shot entry point `python -m assetops_backend.sites.import_kobo --source var/sites/kobo-001.yaml --tenant demo --report .agent/S1-01-import-comparison.md` from repository root (with the backend package installed). It imports `var/sites/kobo-001.yaml` into configured tenant `demo`: `KOBO-001` site code, `Kobo mini-grid`, `MINIGRID`, `Africa/Addis_Ababa`, `PLANNED`, original Foundation v1 and `valid_from: 2026-09-29T11:57:49Z`. Retain fixture provenance and digest. Same code plus same digest is idempotent; changed bytes or cross-namespace duplicate code is a visible conflict, never overwrite. Lab-created YAML Sites remain private/file-backed and are not auto-imported.
5. Register all ten fixture components as stable assets, including AC bus and three loads: `pv-array`, `pv-inverter`, `battery`, `battery-pcs`, `generator`, `fuel-tank`, `ac-bus`, `load-res`, `load-clinic`, `load-mill`. `component_id` becomes `asset_code`; preserve type, name, rating and properties in attributes and Foundation content. Preserve summary, topology nodes/connections, device inventory and declared signals, control assumptions and typed site controls. Devices reference their component asset; they are not extra assets. Invent no controller asset. Battery `reserve-state-of-charge` is 30%; source and critical-load priority are site controls.
6. Register disabled/pending simulated gateway `edge-kobo-001` and one source per fixture device (`source_external_id = device_id`, eight devices). Each source owns one device report stream under the gateway; its signals share that stream's future `(gateway,source,epoch)` sequence scope. A replacement device or gateway move gets a new source identity. `source.mode: SIMULATED` is proposed provenance only. `credential_ref` is null/pending or points to a provisioned secret, never a placeholder usable for ingestion. These rows are registration metadata, not a running edge process.
7. Legacy `signal_mappings` remain import/comparison data, not active SignalBindingRevision, role authorization or gateway-downloadable mapping. Foundation reports bindings incomplete until S1-02 explicitly maps roles, units and conversions. S1-01 may publish Foundation alone; it cannot download an acquisition snapshot or upload evidence. S1-02 establishes the first atomic Foundation-plus-binding snapshot.

## Foundation API and screen

8. External routes use the existing `/api` mount: `GET /api/sites/{site_id}/foundation?at=&knowledge_at=` resolves both instants on the server (default server now) and returns resolved instants, Site UUID/code, selected Foundation revision ID/version, valid and recorded periods, topology/assets/devices, controls, pending gateway/sources, binding-incomplete state and configuration gaps. Invalid time gives validation error; no effective revision gives explicit not-found/empty state. Never silently substitute current configuration. `GET /api/sites/{site_id}/foundation/versions` lists persisted effective periods and revision IDs for UI selection, with a way to distinguish superseded recorded bases. `knowledge_at` is API-only in S1.
9. A narrow `POST /api/sites/{site_id}/foundation/revisions` publishes a future-effective or backdated change to one battery reserve or site control value. Validate typed value/unit, ownership and interval before a transactionally locked insert/split/supersession. Old content remains immutable; recorded-time correction preserves the previous knowledge basis. Return new revision ID/version and effective period. Expose the minimal publish control on Foundation, plus version list/period selector. Persist selected `at` in the URL query and show historical label/period; reload/share retains selection. A selected past period cannot be mistaken for current.
10. The imported Site's Foundation read/publish path uses Postgres only. No file-backed product writer mutates it. Existing file-backed Overview, Evidence and dispatch/Performance are legacy comparison surfaces: for imported Sites hide/disable them or render explicit `awaiting evidence migration`, not stale values beside a changed Foundation. Configured SLD may read selected Postgres topology but shows no operating status. Lab stays private/file-backed; a Lab run bound to an imported Site is **blocked with a visible Foundation mismatch** until it can use the selected registered basis. S2-02, S3 and S5 own later Evidence, Performance and Overview cutovers.

## Configuration gaps and lineage

11. For `MINIGRID`, name missing/invalid site code, name, type/timezone; no effective revision; absent typed component/rating for generator, PV array, battery, PCS, fuel tank, AC bus or declared load; broken topology reference or no AC-bus path; missing battery reserve, source priority or critical-load priority; and missing registered gateway/source for a declared device. A Site with stable code, name, type and timezone may persist with missing rating, topology path, reserve or site-control configuration and report those gaps; missing/invalid identity fields are structurally rejected before insert. It cannot download an acquisition snapshot or claim health. Report pending bindings separately; these are configuration gaps, not observed source health. Reject references outside the Site.
12. Foundation screen and API expose stable Site, asset, gateway/source and revision IDs, content digest and provenance so a reviewer can resolve every displayed value to a stored Foundation version and original import. There is no accepted SourceEnvelope in S1; do not fabricate evidence lineage or claim a live source.
