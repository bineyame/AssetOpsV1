## Chosen approach and rejected shortcuts

1. **Remove repeated head migrations while preserving fresh schema per module.** Build one clean, migrated `*_test` template per run from an admin connection outside the template. At each module-scoped `engine` setup, `DROP DATABASE <worker_db> WITH (FORCE)` then `CREATE DATABASE <worker_db> TEMPLATE <run_template>`; assert migration head. Keep fixture names and bodies in `test_s1_foundation_postgres.py` and `test_s1_bindings_postgres.py`, calling one shared harness helper, so imports and in-place downgrade/upgrade tests remain intact. Generated databases need explicit run identity and cleanup. If cloning is unavailable under the local role, report it and keep the tested serial migration path; never claim shared-DB isolation.
2. **Use bounded pytest-xdist workers, one DB per worker.** Pin xdist in backend dev dependencies and install it in the shared `.venv`. Route each worker before collection, including child processes; use `--dist loadfile` to keep module-scoped setup together. Begin with `-n 2`, measure `-n 3` only if connection counts remain safe, and pick the fastest stable count. Inventory migration/process/lock and timing-sensitive S4-02d cases before enabling the default command. No `-n auto` on this machine.
3. **Bound connections through ownership.** Dispose test-created stores/clients explicitly. Consider a test-scoped pool cap only after measuring the largest simultaneous checkouts per store; a pool timeout is a failure. Account for migration `NullPool`, child processes and in-test concurrency, collect peak `pg_stat_activity`, and retain legitimate concurrency assertions. Keep `gc.collect()` unless disposal proves it redundant. Do not alter production pool defaults simply to improve tests.
4. **Focused suites are a workflow speed gain, not a replacement full run.** Add documented area commands and, only if useful after collection audit, explicit `unit`/`postgres` markers for focused selection. Missing DB must remain visible as skipped and disqualify full proof; markers must never deselect tests from the full command. File-path focus can ship before marker changes. Avoid a broad auto-marker that mislabels mixed files such as `test_s3_demo_configuration.py:126-149`.

## Implementer carries from plan review

- **M2 — routing and lifecycle:** In `pytest_configure`, set `os.environ["ASSETOPS_TEST_DATABASE_URL"]` in each worker before module collection; fixture-time routing is too late for import-time `URL`, skips, stores and child processes. Controller generates a per-run ID (pid plus random) and passes it via xdist `workerinput`; database names are `<base>_<run>_<gw>_test`, at most 63 characters. Check the base URL's `_test` guard before any DDL. Provision lazily: no template for `--collect-only`, non-Postgres focused commands or an unset URL. DROP only run-owned names. At run start sweep orphaned run-owned databases only when their run has no live `pg_stat_activity` sessions; cleanup in `finally` alone does not cover killed runs.
- **M3 — connection ownership:** First make `store` and analogous fixtures yield and dispose their engines, then use per-module `WITH (FORCE)` re-clone. A pool cap is allowed only via a test-scoped patch sized at least to the largest simultaneous checkouts per store, including a dedicated claim connection; never use `pool_size=1, max_overflow=1`. Treat pool timeout as failure. Keep `gc.collect()` until session counts prove it redundant; removal is outside the speed task otherwise.
- **M4 — exact coverage:** Diff sorted `--collect-only -q` node IDs and per-node outcomes from `--junitxml` for baseline versus final and serial versus parallel. List new harness node IDs explicitly; removed IDs must be zero. Derive the guide's zero-DB-skip proof from JUnit outcomes, not a summary count.
- **M5 — comparable timing:** Final A/B timing is back-to-back in one quiet window, alternating old revision in a separate worktree and new harness here, with at least two runs each and the median reported. Record `pg_stat_activity` by `datname` and other `pytest` processes at both start and end; no other Postgres-heavy agent runs in the window.
- **M8 — parallel scheduling and flakes:** Use `--dist loadfile`. Inventory S4-02d tick tests with `statement_timeout_ms=3_000`, `lock_timeout_ms=1_000`, `backoff_base_seconds=1` and `hang` child, health wall-clock-skew assertions, and 30-second drain/work deadlines. If one flakes under contention, document a second serial invocation and report/diff its counts alongside the parallel run; never use automatic retries or reruns.
- **L1-L6:** Inventory every S2/S3/S4 importer of S1 `engine`/`store`, S4-02d health/tick imports and cross-module helpers. Pin `pytest-xdist` in `backend/pyproject.toml` dev extras and install it in the shared `.venv`. Confirm xdist workers receive controller basetemp, `conftest.pytest_configure` returns early on workers for basetemp handling, and `.pytest-basetemp` fallback works with `-n 2`. Baseline, serial-after, repeated parallel, optional 3-worker and concurrent-pair full suites are a one-off exception to the guide's ordinary one-full-suite-per-slice rule; schedule them without another Postgres-heavy agent. Check `max_connections` against twice measured per-run peak before a concurrent pair. Retain `gc.collect()` unless explicit disposal proves it redundant.
