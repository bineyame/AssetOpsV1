## Decided clock contract

- Production `PostgresEvidenceLedger.decide_chunk` obtains one `clock_timestamp()` from the **database inside the chunk write transaction**, after locking the batch row and before writing its dispositions. Use this one instant for every newly decided ordinal's `ingestion_disposition.decided_at` in the chunk. Do not use `now()`/`transaction_timestamp()` (which can predate a lock wait), the ingestion host's clock, or a timestamp sampled before the transaction. The same decision instant supplies `recompute_job.available_at` and `created_at` **when `_coalesce_job` inserts a new job**. A widened PENDING job retains its existing timestamps. These writes commit or roll back together. `backend/assetops_backend/evidence/ledger_service.py:176-182` currently passes the app clock; `backend/assetops_backend/evidence/adapters/postgres_evidence_ledger.py:251-307,376-404` owns the transactional change.
- Give the ledger an explicitly named `test_decision_clock_override` callable. When absent, always use the DB-time path; production composition at `backend/assetops_backend/main.py:265-269` must never set it. Deterministic fixtures set the override on the ledger, with one override result per chunk for both `decided_at` and a newly inserted job's `available_at`/`created_at`. The override is for fixture ordering and F-A alarm coverage, never evidence for the production race or restart proof. Change the `EvidenceLedger.decide_chunk` contract (`backend/assetops_backend/evidence/ledger.py:403-411`) so the service passes a separate app-clock `completed_at` value, never a production decision timestamp. Keep `BatchIngestionService`'s app clock for `ingestion_batch.received_at` and `completed_at` (receipt fields); a DB-stamped decision must not silently change receipt semantics.
- Preserve duplicate/rejected outcomes, exact accepted identity, Site isolation and idempotent chunk retry. Only newly processed ordinals receive a new decision instant; a retry of a committed chunk retains its stored dispositions. Configuration `recorded_at` versus `reconcile` is a separate, self-healing comparand and is outside this packet.

## Why existing coalescing should suffice - proof obligation

`_coalesce_job` locks an overlapping PENDING job with `FOR UPDATE` and widens it inside the ingestion transaction (`backend/assetops_backend/evidence/adapters/postgres_evidence_ledger.py:376-404`). The worker lease uses `FOR UPDATE SKIP LOCKED` (`backend/assetops_backend/analytics/adapters/postgres_assessment_store.py:203-222`), and selection admits accepted evidence only at `d.decided_at <= :k` (`backend/assetops_backend/analytics/adapters/postgres_assessment_store.py:47-56`). Prove both interleavings in real Postgres: if ingestion locks/widens first, the worker cannot lease that row until ingestion commits; its later DB cutoff can see the decision. If the worker leases first, ingestion cannot widen that leased row and inserts a new PENDING job, due at the DB decision time, for the next tick. Include the blocked/rechecked status case, and prove the outcome when a tick passes while a new job is still uncommitted. The required invariant is that no committed accepted decision is excluded by a finished run with no live work. If either interleaving fails, add an evidence-owned transactional re-enqueue through `recompute_job`; rule 8 already lists it among the ledger writer's tables (`tools/checks/configuration-persistence.ps1:622-625`). Do not add schedule-table writes or silently expand assessment-writer ownership.
