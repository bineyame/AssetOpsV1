## Executive judgment

AssetOps has a credible **simulated source-to-claim foundation** and substantially more vertical code than an empty prototype: deterministic mini-grid, thermal and EV packs; public device projection; an outbox and authenticated HTTPS batch ingest; accepted-evidence assessments; versioned Findings, consequences and selected-window reads; and a cross-domain Portfolio. It is **not yet a rehearsed three-vertical client demo**. The sample worlds are isolated engineering fixtures, not an initialized client portfolio. Mini-grid has the clearest quantitative opportunity. Cold can bound temperature exposure but deliberately cannot price it. EV can prove session energy and a tariff amount but cannot infer a vehicle missed departure. Real OEM, Modbus, MQTT, OCPP and sensor integrations are not demonstrated by the inspected code. The hardware pack proposes these as candidate work, not as achieved support.

Preserve the private-truth/public-evidence seam, exact selected windows and knowledge cutoffs, source gates, immutable revisions, and fail-closed `UNKNOWN`/`WITHHELD` states. Do not replace these with attractive precomputed numbers. Architecture: `frontend/docs/architecture/production-shaped-mvp.md` §§29–73; implementation: `simulator/assetops_simulator/packs/`, `host/{cold,ev}_publication.py`, `host/gateway_publication.py`, `backend/assetops_backend/evidence/ledger_service.py`.

## Hardware and pilot boundary

Hardware Pack 01/03/04 is a **proposed integration checklist**, not implementation evidence. Readiness classes: **1 demonstrated working**, **2 configuration/mapping**, **3 bounded engineering**, **4 new adapter/edge/instrumentation**, **5 unsupported/unknown**. The common simulated HTTPS gateway path is class 1. For a real site, all three need customer-authorized read-only access, meter/sensor map, units and timestamps, retained raw samples, and source-health checks; no named OEM or firmware support is established.

| Hero | Minimum real measurements and cadence | Likely source and acquisition | Readiness and pilot complexity |
|---|---|---|---|
| Mini-grid productive load | PV and load/feeders kW/kWh, battery SoC/power, inverter limit, diesel state/fuel if fuel claim; 1–5 min aligned samples, tariff and vending/settlement export if collection claim | EMS/aggregator cloud export or site gateway; documented Modbus TCP, MQTT or HTTPS **candidates**, no tested brand profile | Class 2 for source/role mapping; 3–4 for adapter or independent metering; medium to high depending on fuel and CT polarity |
| Cold backup/excursion | Room probe (ideally independent logger), grid/bus/transfer/start/door/compressor events at 1–5 min, inventory lot/value and quality-approved rule for commercial range | Logger/controller export or independent probes/contact gateway; Modbus RTU/TCP and HTTPS **candidates** | Class 2 for threshold/zone mapping; 3–4 for logger/contacts/calibration; medium, high if missing backup chronology |
| EV fault/short delivery | Connector state/fault, start/end meter and session IDs, site kW/kWh, tariff; 1–5 min status/meter plus event times; vehicle/departure only if making readiness claim | Existing CSMS API/export, depot meter, optionally fleet API. OCPP event examples are **fixtures**, not an OCPP server | Class 2–3 for CSMS/session/meter joins; 4 for new adapter; medium, high for vehicle-level join |

For each pilot, Pack 03 Gate B must establish permissions, coverage, mapping, baseline and buyer; Gate C requires witnessed real-source and security checks. A gateway over cellular adds an agreed SIM/data payer. The owner has replaced Pack 04's proposed 30-hour cap with a Friday 30 October EOD deadline; its Modbus-first preference remains a planning hypothesis, not a confirmed requirement. Avoid claims of measured savings, spoilage, battery health, OEM certification, OCPP server support or real field verification. No live customer data, hardware, vendor documentation or integration bench was available in this assessment.
