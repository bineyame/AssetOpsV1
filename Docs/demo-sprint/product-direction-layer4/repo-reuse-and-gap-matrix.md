# Repository reuse and gap matrix (Layer 4 appendix)

This is the inventory appendix to `layer4-transformation-design.md`. It is cross-referenced from that document's §3–§8, where the architecture logic, the flows and the reasons for each design position (D1–D10) live. This file does not argue the design. It lists concrete repository elements, what they do today, the role each plays in the design, and the disposition, confidence, migration hazard and test gap for each.
Repository state: `fe2392899` (code identical to `9b4d9bd15`, the commit the code-grounded baseline `.agent/decision-intelligence-mechanism-2026-11-14.html` cites). Every `path:line` below was re-read at HEAD.
Paths: code is relative to `backend/assetops_backend/` unless it starts with `frontend/`, `simulator/`, `host/`, `field/`, `gateway/` or `tools/`. Tests are in `backend/tests/` unless prefixed. Migrations are `backend/migrations/versions/00NN_*`. The latest migration is `0061_reading_upload`.
Labels: [code-observed] read in code at HEAD; [test-confirmed] pinned by a named test; [implementation-report] measured in build logs, as reported in the baseline §8.9–8.10; [proposed] a design element that does not exist in the repo. Anything not in the repo is written "new (proposed)".
Dispositions: `reuse as-is | extend | integrate | expose UI-only | new | retire/avoid`. Confidence (H/M/L) is confidence that the disposition is right and cheap, not confidence in the current code.
