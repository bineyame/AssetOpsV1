# Repository disposition matrix, by mechanic (Layer 4 appendix)

**Appendix to `layer4-transformation-design.md` (rev 4) · AssetOps Architect (Claude) · 17 Nov 2026 · design only**

This file is the inventory. It does not argue the design: the five mechanics (M1 Define, M2 Observe, M3 Evaluate, M4 Choose, M5 Prove) and the reasons for keeping, reworking, replacing or adding each part are in the main document §2 and §8. Here each existing part is placed under the mechanic it serves and judged by one question: **does it fit where the product is going?** Reuse is chosen where it fits and saves work, not for its own sake; where a part does not fit, the reason is stated and the new approach is named.

**Repository state.** Branch `task/product-direction-layer4-design`; backend, frontend, simulator, host and tools are unchanged since `bf6014e02` (checked with `git diff bf6014e02 HEAD`). Every `path:line` below was re-read against that code for this revision; three rev 3 citations that were wrong are corrected and listed in §J.

**Paths.** Backend code is relative to `backend/assetops_backend/` unless it starts with `frontend/`, `simulator/`, `host/`, `field/`, `gateway/` or `tools/`. A bare `00NN:line` is `backend/migrations/versions/00NN_*.py`; the latest migration is `0061_reading_upload`. Tests named `test_*.py` are in `backend/tests/` unless prefixed.

**Labels.** [code-observed] read in code; [test-confirmed] pinned by the named test; [implementation-report] stated only by the baseline document `.agent/decision-intelligence-mechanism-2026-11-14.html`; [proposed] this design; [assumption] to validate. Rows are [code-observed] unless marked otherwise.

**Dispositions.** `reuse as-is` (fits the mechanic now) · `extend` (fits; needs added behaviour, form unchanged) · `rework` (the idea fits, its form must change) · `integrate` (used across a seam or as a pattern by a new component) · `expose UI-only` (computed today, not rendered) · `new` (no existing part can serve) · `retire/avoid` (does not fit where the product is going). **Conf** (H/M/L) is confidence that the disposition is right and proportionate, not a grade of the current code.

**For readers of rev 3.** Rev 3 organised this appendix by ten extensions D1–D10. Those names are dropped. Mapping: D1 thread origins → decision records anchored on a **factor key** (threads become evidence on a factor); D2 commercial records → **commercial record store**; D3 period economics → **structure read**; D4 typed effects and overlap groups → **structure registry** (shared factor IDs make overlap structural); D5 decision/option set → **decision, option and evaluation records**; D6 safeguard policies → **obligation bounds** (obligation policies); D7 dispatch counterfactual → **forward replay adapter**; D8 entitlements → **rights register + supplier-claim work case**; D9 allocation → **allocation run**; D10 verification triple → **economic and causal verdicts**.
