Decision in one minute

Start with one read-only source collector pattern for customer-owned API/CSV, one documented Modbus TCP poller as the local fallback, and one CSMS session normalizer for EV. Prove all three through the real gateway queue and authenticated ingestion. Use the existing BeagleBone Black for a Linux deployment rehearsal after laptop proofs. Buy no meter or gateway before a site survey.

Now · P1

API/CSV maps mini EMS or Victron VRM, EV CSMS, and cold logger data. One collector framework; source-specific maps.

Next · P2 + P3

Victron GX Modbus TCP register emulation and CSMS-derived EV sessions with a separately declared fleet join.

Conditional · P4–P6

Serial, MQTT, or new edge hardware only when a prospect's accessible sources require them.

Critical repository limit. The batch contract admits LIVE, but snapshot.py rejects activation unless the provisioned gateway is SIMULATED. The exact provenance resolver accepts only authored demonstration and registered simulation classes. An emulated accepted batch therefore proves the adapter and simulated delivery path; it is not a claim that live source provisioning, source classification, or a field pilot works today.

Acceptance rule for every proof: captured raw source bytes → real adapter → DeviceReport V2 with source key/time and map version → registered simulated snapshot → gateway holds or durable queue → authenticated HTTPS receipt → accepted evidence IDs → exact source link → one bounded domain read. A bad unit/identity is held, never silently coerced. Compare the accepted observations to the emulator's public projection; private simulator truth is only a test oracle.

ChargePoint's guide says session calls can return at most 500 records, refresh about every five minutes, and 15-minute/driver data can require a service plan: documented fact · high confidence. Thus the proof must work with final sessions alone and label interval power unavailable when absent. OCPP 1.6 and 2.0.1 are incompatible: documented fact · high confidence. Direct OCPP termination is deferred.

5 · Low-cost edge opportunity and hardware shortlist

A headless Python poller, local IPC, SQLite gateway and HTTPS uploader are plausible on it, but RAM/storage endurance, current Debian package compatibility, clock recovery and sustained queue load are unverified inference · medium-low confidence. It has no RS-485, calibrated sensor, meter, UPS or cellular path in the stated kit.

7 · Pilot-readiness gaps to validate with a real customer

Rights and interface

Customer authority to read source and retain lawful raw evidence; endpoint/export format, auth/token rotation, plan limits, polling cadence, historical depth, rate limits and support terms. Obtain sample bytes and field dictionary.

Physical and semantic map

Device/connector/room IDs, CT direction, units, counter epochs, clock offset, meter placement, probe calibration and alarms. Test controlled failure at the actual site before any analytic claim.

Business records

Mini fuel/feeder/collections, EV vehicle/roster/depot tariff, cold lot/quality/contract records. Qualify modeled opportunity separately from verified financial result.

Live boundary: review a LIVE snapshot activation and field-source attestation design; extend provenance storage, resolver and UI so accepted field evidence is neither REGISTERED_SIMULATION nor anonymous UNKNOWN. Recheck the database constraints and any money gates that enumerate source classes. Security review covers read-only OT access, credential scope, outbound TLS, local secret storage and least-privilege operator provisioning. This is a focused field-source extension, not a new ingestion platform.

Unverified compatibility: No real VRM, ChargePoint, Monnit, GX or site controller credential/device was exercised here. Public docs establish interface possibilities, not AssetOps certification or the customer's purchased data tier. AMMP's listed vendors do not establish that its proprietary connector mechanics can be copied. Prices are October 2026 snapshots or explicitly marked planning allowances, excluding tax, shipping, wiring, installation, cellular service and recurring API fees.

8 · Prioritized execution plan and architectural recommendations

  1. Before 30 October: approve this plan and first target profile; pin one vendor-format fixture and source manifest; implement or prepare I0 and a thin I1 mock-to-real-gateway acceptance proof if capacity allows; record fault results and a customer discovery questionnaire. The hard deliverable is an honest end-to-end integration proof, not a polished adapter catalog.
  2. As outreach begins: ask each prospect for actual equipment, source rights, sample exports, meter topology, timestamps, API tier and one priority business question. Choose next slice from access evidence. I2 is next for a bus depot; I3 if a mini site exposes GX/local TCP; cold P1 map if a logger API is offered.
  3. After first source access: compare actual device/vendor bytes against fixture, finish negative controls, run a bounded parallel read with the customer's records, then decide whether BBB or an industrial Linux box is worth deploying. P4/P5/P6 stay conditional.
Architectural recommendations: retain the current gateway's IPC admission, SQLite outbox, TLS upload and principal-scoped ledger. Add a small read-only acquisition layer with per-source maps and explicit source provenance. Reuse the same accepted evidence and analytics, with missing signals kept missing. Make the field-source classification gate before customer data is represented as live evidence.

Owner decisions needed

  1. Choose the first outreach target and source: mini EMS/VRM, EV CSMS, or cold logger. Recommended first reusable proof: mini API/export, then bus CSMS if the first conversations are fleet-led.
  2. Authorize the narrow field-source identity/provenance design for later implementation, including how lawful source bytes or immutable references are retained.
  3. Set the initial pilot spend ceiling and whether BBB is lab-only (recommended) until a site power/network survey.
  4. Name the first commercial question and customer records that may be requested; accept that inferred fuel saving, bus service and spoilage remain unavailable without them.
