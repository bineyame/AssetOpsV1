Each card says **Configured** (green) or **Needs configuration** (amber) only for its stated configuration test; if no selected effective basis can be resolved, say **Unknown** (neutral). Keep an overall “Configuration readiness” verdict and its separation sentence above or beside the cards; a green card never says field-verified, reporting, commissioned or healthy.

| Card | Green only when | Amber wording / source of gap |
| --- | --- | --- |
| Definition | Site code, name, supported type and timezone are present/valid in the selected Site record | “Site definition needs configuration”; `SITE_*` gaps. This does **not** claim a declared operating objective or productive-use designation. |

| Controls | Reserve and required Site Controls are configured for this Foundation | “Controls need configuration”; `BATTERY_RESERVE_MISSING` or `SITE_CONTROL_MISSING`. Named values are configuration, not operating results. |

The table should have **Area / Declared / Confirmed / What is needed / Next step** (the mock's actual last-column label). No “Owner” assignment column: there is no owner-of-commissioning field. Place the full role/binding table in Advanced details as below.

Use the existing `GET /api/sites/{site}/gateway-health` S2 read for a bounded gateway panel **only if the client read succeeds**. Show registered gateway identity and enabled/disabled registration separately from central contact **Current / Stale / Unknown**, with server `read_at`, `last_server_contact`, the declared cadence/status basis, and a link to Site Evidence for detail. “Current” means a diagnostic reached the server within the S2 cadence rule; it is not a live-connected device, accepted telemetry, or condition. “Unknown” covers no diagnostic; unavailable read says **“Gateway contact unavailable”** without falling back to Registered=Online. The selected Foundation `at` is a configuration instant; gateway contact is a separate **current server-time** diagnostic. Explicitly label that difference, especially on past/scheduled Foundation periods; do not imply the diagnostic occurred in that selected period. Optional queue/clock/source-contact fields stay under Advanced details with their reported/clock basis. Do not recreate the mock's uptime %, delivery completeness %, signal strength, firmware, online source dots or commissioning verdict: these are not established by this read. S2 Evidence's selected-window accepted counts belong on Site Evidence, not this gateway-contact verdict.
