This amends the recommendation read and acceptance rule; it does not change an Action's immutable origin or accepted-recommendation snapshot.

Choose (c): show the earlier Action and hold a repeat trial while it is unresolved. A newer `FindingRevision` is a new assessment basis, not evidence that the earlier policy trial worked or that another five-point reserve reduction is appropriate. For a selected revision, the Site-scoped recommendation read must return the prior Actions for the same canonical Finding, with each Action's origin revision, application state, outcome state and exact Action link. A known prior Action is never hidden by `FOUNDATION_BASIS_STALE`, a later Finding revision or a failed live recomputation. Keep the selected revision and any accepted snapshot separately labelled; never relabel an earlier Action as originating on the newer revision.

For `reserve-trial-1` on the same Finding, battery asset and reserve field, an earlier Action whose application is pending (including failed attempts awaiting retry) or applied with verification pending blocks a *new* acceptance. Return typed `PRIOR_ACTION_UNRESOLVED` with the blocking Action ID, origin revision and link; show the current-basis result, including `FOUNDATION_BASIS_STALE`, as a separate live reason where relevant. Do not offer an Accept capability for the new key. Recheck the guard atomically at acceptance, so simultaneous accepts on different Finding revisions cannot create two unresolved trials. Identical retries of the existing accepted key still return its Action. A completed verification outcome alone must not be treated as permission for another trial until S6-02 defines an explicit resolved/closed transition and its eligibility rule. This does not prohibit several Actions over a Finding's lifetime or Actions for a different intervention; it limits this one reserve-trial command.
