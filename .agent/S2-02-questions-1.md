# S2-02 questions 1 (phase 1)

Raised while building S2-02 phase 1 (ledger, identity hardening, decision engine). Each is built on the fail-closed default named; none blocks phase 2. Batch with the next Architect round.

**Q1. Gateway/source external IDs stay mutable.** AC4 asks to "review" Site type and gateway/source external-ID mutability. Migration 0005 freezes `asset.asset_code`, gateway tenant/Site/mode/registered_at, source tenant/Site/gateway/registered_at, and Site type once accepted evidence exists. `gateway_external_id` and `source_external_id` remain mutable current-row names: pinned snapshots (0004) keep their published spelling and acceptance resolves only immutable registered UUIDs from the snapshot. Options: (a) keep mutable (built); (b) freeze both once a binding set or evidence references them (would break the S1-02 carry-m4 rename tests, which would be rewritten). *Recommendation/default:* (a). Freezing gateway mode (previously editable) required editing two S1/S2-01a tests that renamed and re-moded a gateway; they now rename only.

**Q2. Who enables an imported gateway and its sources?** S1-01 import registers the gateway and every source with `disabled_at = now` until a credential is provisioned. AC1 requires an active gateway and enabled, affiliated source on every upload. Phase 1 tests clear `disabled_at` directly in SQL as a stand-in for provisioning. Options: (a) the phase-2 operator provisioning command issues the credential and enables the gateway plus an explicitly listed set of its registered sources, recording each step; (b) credential issuance enables the gateway only, and sources are enabled by a separate operator step; (c) the first authenticated upload enables a source. *Recommendation:* (a). *Fail-closed default for phase 2:* never enable on upload (rejects c); a source stays disabled until an operator step names it.

**Q3. Claim mismatch is 403 with no ledger row.** Technical design section 4 says "a batch with wrong registered mode or configuration reference is refused as a whole". Phase 1 answers a Site/gateway claim mismatch, a mode mismatch, an unaffiliated/disabled source and a disabled gateway with 403 and writes no Site-visible row (AC1: "cross-Site source ... creates no Evidence or Site-visible receipt"). A wrong **configuration** reference (unregistered binding set version, snapshot digest or `foundation_valid_from` spelling mismatch, set published for another gateway) is a whole-batch 422 with an authenticated `batch_refusal` row. *Default:* as built; ask only whether a mode mismatch should also leave an audit `batch_refusal` row.

**Q4. Configuration-reference failures are whole-batch, not per-ordinal.** Batch V2 is homogeneous in Foundation and binding reference and the batch parser already enforces envelope/batch reference equality, so an absent/unregistered reference is a whole-batch refusal kind (`CONFIGURATION_UNREGISTERED`, `CONFIGURATION_MISMATCH`). Per-ordinal rejections are `BINDING_NOT_REGISTERED`, `OUTSIDE_FOUNDATION_PERIOD`, `OUTSIDE_BINDING_PERIOD` (closing-boundary readings land here), `UNIT_INCOMPATIBLE`, `INVALID_ENUM`, `CONVERSION_UNSUPPORTED`, `SCHEMA_UNSUPPORTED` and `MESSAGE_CONFLICT`. *Default:* as built.

**Q5. Recompute job domain and window.** S2-02 only enqueues. Each committed chunk with new acceptances coalesces one `PENDING` job per Site for domain `dispatch` (S3-01's first analytic) under a transaction advisory lock, widening an overlapping/adjacent pending window `[min source_time or interval_start, max interval_end or source_time + 1 µs)`. Duplicates and rejections enqueue nothing. Options: (a) single `dispatch` domain (built); (b) a generic `evidence` domain S3 fans out. *Default:* (a); S3 may add domains without changing these rows.

**Q6. Evidence `received_at` is the batch's first server receipt instant.** A resumed batch keeps the instant the server first received it for every ordinal; per-chunk decision time is `ingestion_disposition.decided_at`. *Default:* as built.

**Q7. Oversize is 413.** A body over `MAX_BATCH_BYTES` (declared Content-Length, or actual length) is 413 `TOO_LARGE`; an authenticated oversize body that reaches the service also leaves a `batch_refusal` row. Other malformed bodies are 422. *Default:* as built.
