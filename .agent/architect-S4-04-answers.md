# Architect answer - S4-04 index contract (2026-10-15)

Authority: `D-2026-10-15-a-finding-index` and `D-2026-10-15-s501-finding-choice`. These rulings settle the three API choices in `tasks/S4-04-site-finding-index.md`; they do not approve UI copy or change the Finding detail route.

1. **Route and cursor error - accept.** Add `GET /api/sites/{site_code}/finding-index` with the packet's required query and scope. Leave `/findings/{finding_id}` and the consumed `findings_over` helper unchanged. When a cursor's bound selection token or scope differs from the current fenced basis, return HTTP 409 `INDEX_BASIS_CHANGED` with a machine-readable reason and instruction to request page one without a cursor. Return no rows, count or replacement cursor in that response. A malformed cursor remains a typed 422; do not treat it as a basis change.
2. **Historical rows - accept.** Return `STALE_PROJECTION` or `FAILED` rows only from a durable prior selected snapshot containing the exact canonical Finding and FindingRevision IDs, sort order and basis used for that response. Recheck scope before reading it and label its rows and count historical, never current. If no such snapshot exists, return `PENDING` or `UNASSESSED` with no rows and no current count as applicable; `FAILED` may report the failure with no historical rows. Never reconstruct historical rows from latest Finding heads. A closed Performance source gate still returns its existing 409 with no index rows or count.
3. **Continuity-neighbour closure - amend with a concrete bound.** Begin with every UTC-day window intersecting `[from,to)`. Repeatedly inspect adjacent UTC days reachable by an actual S4 20-minute continuity bridge across the current edge, on the same fenced accepted-evidence/configuration/model basis; stop at a fixed point. Do not assume only one neighbour on either side. Cap discovery at 62 distinct UTC-day windows total, including requested days. If the next reachable day would exceed the cap, return HTTP 409 `INDEX_CONTINUITY_LIMIT` with a reason and no current rows, count or empty claim; the client displays Unknown and may offer a narrower window. Record every inspected day and its S3/S4 selection seq in the selection token/basis, including days with no row. A dirty, leased, failed, missing or changed neighbour blocks `CURRENT` under the existing status rules. The cap is a service safety limit, not evidence that continuity ends at day 62.

Packet changes: replace question 1 with the route, 409 and malformed-cursor distinction; replace question 2 with the durable snapshot and no-snapshot rules; replace question 3 with fixed-point closure, the 62-day cap and `INDEX_CONTINUITY_LIMIT`. Add focused phase-1 tests for both 409s, no-snapshot reads, a bridge chain beyond one neighbour and cap failure. Keep the packet's two-phase review and owner checkpoint.
