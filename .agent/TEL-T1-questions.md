# TEL T1 questions for the Architect (TEL-01..03)

Status: ruled 2026-10-27 by the Architect (Claude); see TEL-T1-Q1..Q7 in the spec resolutions. None blocks T1. Each item names the narrow behaviour implemented so that the review can see it, and the Architect may overrule any of them; nothing here widens a spec rule.

1. **Sentinel width on a mixed-width row (profile.py `_parse_sentinels`).** 0.6 says sentinels are "unsigned raw integers of the register's width", but a row may list registers of different widths. Implemented: every sentinel must fit the **narrowest** register of the row (strictest reading). No October profile mixes widths. Confirm or name the rule.
   **Ruling TEL-T1-Q1 (Architect, Claude):** Confirmed. Every sentinel must fit the narrowest register of the row; otherwise `SENTINEL_OUT_OF_RANGE`. No code change.
2. **"First sentinel" with a set (decode.py `encode_sentinel`).** `ProfileRow.sentinels` is a `frozenset` by the spec interface, so declaration order is lost. Implemented: the smallest sentinel. Every October profile declares exactly one. Confirm, or make `sentinels` an ordered tuple.
   **Ruling TEL-T1-Q2:** Confirmed. `sentinels` stays a `frozenset`, and "first sentinel" means the **smallest** declared sentinel (`min(row.sentinels)`). Spec wording (Q-T15, TEL-01 `encode_sentinel`) reads that way from now on. No code change.
3. **Malformed Modbus answers (modbus_tcp.py `_parse_pdu`).** The 0.7 table does not name a response whose function code is neither the request's nor its exception form, or whose byte count disagrees with its own length field. Implemented: `NO_ANSWER` kind `RESET`, the connection dropped (stream framing is lost). A well-framed answer with the wrong number of words is `WORDS` and `classify` makes it `CONFIG_FAULT` (the table's "wrong word count").
   **Ruling TEL-T1-Q3:** Confirmed. A wrong function code (neither the request's nor its exception form), or a byte count that disagrees with the MBAP length, is `NO_ANSWER` kind `RESET` with the connection dropped. It is not retried (retries are TIMEOUT, 04 and 06 only). A well-framed answer with the wrong word count is `WORDS` → `CONFIG_FAULT`. No code change.
4. **Exception codes the 0.7 table does not name (05, 07, 08, 0x80+).** Implemented in `modbus_tcp.exception_outcome`: `FAILED` (no sample; the poller does not retry it because retries are only for TIMEOUT, 04, 06).
   **Ruling TEL-T1-Q4:** Confirmed. 05, 07, 08 and any code ≥ 0x80 or otherwise unnamed → `FAILED`, no sample, no retry. The raw-capture line keeps the code. No code change.
5. **Which rows the emulator quantizes (gx_server.py `presented_value`).** The amended TEL-03 rule quantizes "GX-layout rows" and says the TEL-05b illustrative block is "never quantized". Implemented: rows with `status == "ILLUSTRATIVE"` are not quantized, all others are. Only matters from TEL-05b; confirm the discriminator.
   **Ruling TEL-T1-Q5:** Confirmed, with the discriminator stated precisely: **row** status (`row.status == "ILLUSTRATIVE"`), never the profile status. Profile `-2` is `ILLUSTRATIVE` at profile level, but its unit-100 `pv-ac-output` row is copied unchanged from `-1` (row status `UNPINNED`), so it stays quantized. A TEL-05b emulator test asserts both cases. No TEL-03 code change.
6. **Session reference helper.** The `field:<id>:<version>:<wall YYYYMMDDTHHMMSSZ>:<8 hex>` reference is described in TEL-01 but no interface names its builder. Not built in TEL-01; left for the TEL-04 poller, which owns session start-up.
   **Ruling TEL-T1-Q6:** Accepted as deferred. TEL-04 owns it: `modbus_poller.new_session_ref(profile: FieldProfile, wall_now: datetime, token: Callable[[], str] = lambda: secrets.token_hex(4)) -> str`. It returns `field:<profile_id>:<profile_version>:<YYYYMMDDTHHMMSSZ>:<8 lowercase hex>`, and a unit test checks the format with an injected token. This is not a TEL-01 review finding. No TEL-01 code change.

7. **Finding: the source values are exact rationals.** `registered.request()` uses `simulator-lab-publication:3`, so `reported_value` in the `-1` JSONL holds exact rationals (e.g. `1035/19`), not 0.000001-resolution decimals. The representability paragraph's premise (`profiles.py:1826`) holds only for the registered-Kobo profiles (V1/V4), not for v3.
   **Ruling TEL-T1-Q7:** The rule stands and only its premise is corrected. The `-1` fixture keeps v3 and is not regenerated. The emulator quantizes at the register resolution, as built. TEL-04/05 compare at the **emulator register resolution, exactly, with no tolerance**:
   - expected(row, obs) = `gx_server.presented_value(row, Fraction(obs.reported_value))`, then `quantize_half_even(·, row.output_resolution)`. The second step is a no-op for `-1`, because 1 W = 0.001 kW and 1 % = 1. That gives 0.001 kW for PV and 1 % for SoC. Use the existing helpers; do not add a second rounding helper.
   - arrived = `Fraction(envelope value text)`. Assert `arrived == expected` for every `GOOD` interval or state report whose observation is `REPORTED`.
   - As an independent sanity bound that does not reuse the emulator, also assert `abs(arrived - Fraction(obs.reported_value)) <= q / 2`, where `q` = `register_quantum × 10^(scale_exponent + unit_exponent)` in the source unit. Floats are never used, and there is no epsilon.
   - Outcomes are compared as in Q-T40, including the allowed `NO_MEASUREMENT`/`NO_COMPLETED_INTERVAL` difference.
   - TEL-05b: unit-101 rows (`ILLUSTRATIVE`, int32, exponent −6) compare `arrived == Fraction(obs.reported_value)` exactly. The V4 draft publishes at 0.000001, which is that register's resolution. If any value is not a multiple, `encode_value` raises `NOT_A_MULTIPLE`; that is a stop, not a reason to quantize. The unit-100 PV row follows the `-1` rule.
   - The TEL-03 claim record says "values presented at the register's resolution (1 W, 1 %); source values are exact rationals from simulator-lab-publication v3". No TEL-01..03 code change.
