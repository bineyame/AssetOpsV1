## Schema and read-only transaction

**Migration body is empty because there is no migration file**: `upgrade = ∅`, `downgrade = ∅`, added tables/indexes/constraints/triggers = **0** and Alembic head is exactly the merged W2-07 head. Do not create a no-op `0027`, change W1 schema, or add a shadow cache. The query uses existing tenant/Site composite FKs, `finding`, `finding_revision`, S4 match/assessment/evidence links, W1 consequence revisions, `action`, `action_event` and verification tables. No new DB constraint is silently assumed. Existing `0016_action_store.py` has Action `created_at`, `action_code`, `origin_finding_id/revision_id`, and `action_event` `(recorded_at,id)`; it has no authored due-date or owner field, so those columns stay `null`/`Not set`. Existing Finding index `amount` is `UNAVAILABLE` and cannot supply Cost eligibility by itself.

Begin read-only REPEATABLE READ after resolving the principal's authorized tenant and explicit Site set. Scope is **all authorized Sites with a committed `site_import` row at snapshot time and `site_import.imported_at < to`**, ordered by `(site_code_key,id)`, including retired/currently inactive Sites and Sites with missing assessment; no silent omission because a Site has no finding. If the principal is explicitly limited to Site IDs, intersect with that grant and report `scope.authorized_site_count`; never expose a forbidden Site code/name/count. The signed access-basis token is derived from tenant, sorted authorized Site UUIDs and policy version; it is bound to the cursor. A request for a known Site outside grant is 403; tenant-external and unknown IDs are 404. No client-supplied tenant ID. New/missing imported Sites change the cursor basis. Index cannot simply concatenate Site API pages: it must use a single transaction and its own full-set query.

Selected UTC `[from,to)` is at most 31 days, required on every request. `known_at` is optional and defaults to the snapshot's DB time; explicit `known_at` must be UTC and at/before DB time. At the cutoff, select each canonical Finding's latest revision by `(recorded_at,id)` (or its stored revision sequence where W1 is authoritative), then exclude merged aliases; preserve distinct recurrence and withdrawal rows and their lifecycle labels. Include a Finding if its selected episode intersects the window (`start<to AND end>from`) and belongs to an eligible Site. For Actions, membership is `action.created_at >= from AND < to`, with latest `ActionEvent` having `recorded_at <= known_at` by `(recorded_at,id)`; reduce through the W1 reducer. A late revision recorded after `known_at` must not rewrite a historical result. Late accepted evidence/pending jobs mark current coverage pending, while an explicit old cutoff is `HISTORICAL` and retains its exact selected IDs.

The transaction records `read_at`, selected `known_at`, per-Site disposition watermark, Finding matcher/selection fence, Action event fence and source freshness **separately**. `CURRENT` requires each included Site's relevant Finding/Action selection current at that cutoff and no overlapping PENDING/LEASED/FAILED work; any such work is `PENDING_RECOMPUTE`, stale source is `STALE_SOURCE`, explicit earlier cutoff is `HISTORICAL`, missing selection is `UNKNOWN`. Precedence for a full estate claim: explicit historical, then pending, then stale, then unknown, else current. Retain each Site state in `coverage.sites`; never collapse a missing Site to zero. Findings that are authored or cold/EV may have different selected-read grammars; use their merged W2 envelope and exact selected IDs, not a fake universal boolean. An unsupported domain at a Site is `NOT_APPLICABLE`, not missing. `site_count` is the authorized Site count; `covered_site_count` is the number with settled relevant selection. Summary totals are numeric only when all applicable Sites are covered and current (or when historical is explicitly labelled historical). Otherwise each affected metric is `null`, with `coverage=PARTIAL|UNKNOWN` and the known rows still shown with limitations. No cross-Site amount total in W3-01.

### Lens and card predicates

The same canonical Finding IDs underlie All, Cost, Risks and Opportunities. Lens is an **eligibility flag on a selected persisted revision**, not a separate object. `All` includes eligible selected Findings, including WITHDRAWN with its state; a filter may hide it but the total basis still includes it. `Cost` requires a selected same-Site consequence revision linked to the exact Finding revision, a supported non-null amount and currency with acceptable source gate, and a selected window/basis that matches the Finding's claim. An unpriced consequence remains in All, with `Unpriced`; it is absent from Cost. `Risks` requires an explicit persisted risk classification/claim kind on the selected Finding revision. Current W1 `finding_index` does **not** provide a general risk enum; until a domain-selected read exposes one, this lens is truthfully empty with `No supported risk classification in this selection`, even if a title sounds risky. `Opportunities` requires a persisted opportunity-eligible kind and exact Finding revision; W4-03 is its first expected producer. It is empty now unless an already merged supported producer exists. No F-109 mock seed. A Finding may qualify for more than one lens only when each independent predicate is proven; `lens_flags` array is explicit.

`Open findings` counts selected lifecycle OPEN/OPENED across the full authorized basis, **not the page**; `High priority` requires an actual persisted priority level `HIGH`, else its value is null with `Priority not recorded`; `Low confidence` requires an actual selected confidence enum `LOW` with reason IDs, else null with `Confidence not recorded`; `Awaiting verification` requires a linked Action with a persisted verification window and no terminal outcome. W1 Finding revisions do not create priority/confidence merely from claim level or a gap. Show `Not assessed` when no model exists. For Actions, `Open actions` counts nonterminal W1 reduced states; `Due / overdue` stays null/`Not set` because W1 has no authored due date; `Verification window` counts persisted frozen verification windows; `Verified in 30 days` counts actual `VERIFIED` outcomes with decision time within `[known_at-30d,known_at]`, never ActionEvent `OBSERVED`. Every count uses the full scope before pagination and carries `basis_count`/coverage. If any relevant Site is not current, withhold estate totals; a row from a settled Site can still be displayed with its own status.

A repeatable snapshot alone cannot freeze page two across requests; the cursor fence does that.

## Shared provenance DTO resolution (`D-2026-10-20-shared-provenance-dto`)

The public **`source_provenance`** shape for W1/cold/EV and these estate rows is exactly `{classification,source_ids,evidence_ids,basis_sha256,reasons}`. `classification` is one of `AUTHORED_DEMONSTRATION|REGISTERED_SIMULATION|MIXED|UNKNOWN`, never null at this boundary. `source_ids` is the sorted unique `accepted_evidence.source_id` set for the exact cited IDs; `evidence_ids` is that sorted unique cited accepted-ID set. `basis_sha256` is the exact selected assessment/Finding/consequence revision's existing immutable `basis_sha256` (the W2 cold/EV meaning), **not a new provenance hash**; when a selected W1 revision has no stored basis, use SHA-256 of sorted-key compact JSON `{version:"source-provenance-basis/1",tenant_id,site_id,selected_revision_ids:[...],accepted_evidence_ids:[...]}`. It is null only with no selected revision. `reasons` is the exact sorted classifier reason array with `code` and `accepted_evidence_ids`; do not strip problematic IDs. The source classification comes from `SourceProvenanceResolver.resolve` over the **exact deduplicated full cited accepted-ID union**, not `gateway.mode`, `site.proposed_source_mode`, a page subset, source label or persisted EV `result.source_provenance.class`. Persisted EV `class` maps to `classification` at the read adapter, then the resolver's result wins if it disagrees; discrepancy adds `SOURCE_CLASS_MISMATCH`, yields UNKNOWN and is tested. W1's `state` maps to public `classification`; preserve its detailed `accepted_evidence_ids`, publications, fixtures, runs and per-ID evidence under optional `detail`, never lose them. Cold/EV existing `source_ids/evidence_ids/basis_sha256` values and cursor basis stay unchanged. At a missing selection return `classification:UNKNOWN`, empty arrays, `basis_sha256:null`, `EMPTY_CITATION_SET`; never emit a positive label from another Site or previous head.

The classifier's exact precedence is preserved: empty, not-found, broken or foreign → UNKNOWN; bound + unbound, crossed classes, incompatible fixture versions, multiple registered runs without compatible basis → MIXED. One registered run may be coherent only when all links carry the same run ID and identity hash; multiple runs remain MIXED until a reviewed compatibility record exists. **Pending W2 selected-read exception is preserved:** cold/EV `classification`, `source_ids`, `evidence_ids` and `reasons` describe the full current accepted set at the requested cutoff, while `basis_sha256` may still name the prior stored selected head and `currentness.state=PENDING_RECOMPUTE`; this cannot support current money or an estate current total. A W3 row's exact selected-revision source block is separate from the per-Site pending source envelope; never splice the current set's class onto the prior row's selected revision. Do not let an empty head or partial page bypass full cited-set classification. W3-01 commit 1 **implements this shared mapping** with Lane A integration of shared frontend/source UI files, before W3-02 and W5 start. W4-01 consumes the same contract for claims; if W4 reaches merge first it may carry the reviewed adapter as a Lane A integration, with W3-01's exact-ID suite still mandatory before W3-02/W5. No schema migration is required.

Exact-ID tests: one W1 Finding revision and its consequence power union; one W2 cold selected revision; one W2 EV selected session/Finding/consequence; each checks the same sorted accepted IDs/class/reasons and hash input independent of paging. Add empty-head, missing-ID, foreign-ID, bound+unbound, crossed class, two fixture versions, two simulation runs and persisted-EV-class disagreement vectors. Every vector must assert selected revision IDs, every accepted evidence ID, no page-subset substitution, and unchanged historical cutoff. These are public read tests, not simulator truth tests.
