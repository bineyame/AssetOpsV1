## Schema and read-only transaction

**Migration body is empty because there is no migration file**: `upgrade = ∅`, `downgrade = ∅`, added tables/indexes/constraints/triggers = **0** and Alembic head is exactly the merged W2-07 head. Do not create a no-op `0027`, change W1 schema, or add a shadow cache. The query uses existing tenant/Site composite FKs, `finding`, `finding_revision`, S4 match/assessment/evidence links, W1 consequence revisions, `action`, `action_event` and verification tables. No new DB constraint is silently assumed. Existing `0016_action_store.py` has Action `created_at`, `action_code`, `origin_finding_id/revision_id`, and `action_event` `(recorded_at,id)`; it has no authored due-date or owner field, so those columns stay `null`/`Not set`. Existing Finding index `amount` is `UNAVAILABLE` and cannot supply Cost eligibility by itself.

Begin read-only REPEATABLE READ after resolving the principal's authorized tenant and explicit Site set. Scope is **all authorized Sites with a committed `site_import` row at snapshot time and `site_import.imported_at < to`**, ordered by `(site_code_key,id)`, including retired/currently inactive Sites and Sites with missing assessment; no silent omission because a Site has no finding. If the principal is explicitly limited to Site IDs, intersect with that grant and report `scope.authorized_site_count`; never expose a forbidden Site code/name/count. The signed access-basis token is derived from tenant, sorted authorized Site UUIDs and policy version; it is bound to the cursor. A request for a known Site outside grant is 403; tenant-external and unknown IDs are 404. No client-supplied tenant ID. New/missing imported Sites change the cursor basis. Index cannot simply concatenate Site API pages: it must use a single transaction and its own full-set query.

Selected UTC `[from,to)` is at most 31 days, required on every request. `known_at` is optional and defaults to the snapshot's DB time; explicit `known_at` must be UTC and at/before DB time. At the cutoff, select each canonical Finding's latest revision by `(recorded_at,id)` (or its stored revision sequence where W1 is authoritative), then exclude merged aliases; preserve distinct recurrence and withdrawal rows and their lifecycle labels. Include a Finding if its selected episode intersects the window (`start<to AND end>from`) and belongs to an eligible Site. For Actions, membership is `action.created_at >= from AND < to`, with latest `ActionEvent` having `recorded_at <= known_at` by `(recorded_at,id)`; reduce through the W1 reducer. A late revision recorded after `known_at` must not rewrite a historical result. Late accepted evidence/pending jobs mark current coverage pending, while an explicit old cutoff is `HISTORICAL` and retains its exact selected IDs.

The transaction records `read_at`, selected `known_at`, per-Site disposition watermark, Finding matcher/selection fence, Action event fence and source freshness **separately**. `CURRENT` requires each included Site's relevant Finding/Action selection current at that cutoff and no overlapping PENDING/LEASED/FAILED work; any such work is `PENDING_RECOMPUTE`, stale source is `STALE_SOURCE`, explicit earlier cutoff is `HISTORICAL`, missing selection is `UNKNOWN`. Precedence for a full estate claim: explicit historical, then pending, then stale, then unknown, else current. Retain each Site state in `coverage.sites`; never collapse a missing Site to zero. Findings that are authored or cold/EV may have different selected-read grammars; use their merged W2 envelope and exact selected IDs, not a fake universal boolean. An unsupported domain at a Site is `NOT_APPLICABLE`, not missing. `site_count` is the authorized Site count; `covered_site_count` is the number with settled relevant selection. Summary totals are numeric only when all applicable Sites are covered and current (or when historical is explicitly labelled historical). Otherwise each affected metric is `null`, with `coverage=PARTIAL|UNKNOWN` and the known rows still shown with limitations. No cross-Site amount total in W3-01.

### Lens and card predicates

The same canonical Finding IDs underlie All, Cost, Risks and Opportunities. Lens is an **eligibility flag on a selected persisted revision**, not a separate object. `All` includes eligible selected Findings, including NO_LONGER_SUPPORTED with its state; a filter may hide it but the total basis still includes it. `Cost` requires a selected same-Site consequence revision linked to the exact Finding revision, a supported non-null amount and currency with acceptable source gate, and a selected window/basis that matches the Finding's claim. An unpriced consequence remains in All, with `Unpriced`; it is absent from Cost. `Risks` requires an explicit persisted risk classification/claim kind on the selected Finding revision. Current W1 `finding_index` does **not** provide a general risk enum; until a domain-selected read exposes one, this lens is truthfully empty with `No supported risk classification in this selection`, even if a title sounds risky. `Opportunities` requires a persisted opportunity-eligible kind and exact Finding revision; W4-03 is its first expected producer. It is empty now unless an already merged supported producer exists. No F-109 mock seed. A Finding may qualify for more than one lens only when each independent predicate is proven; `lens_flags` array is explicit.

`Supported findings` counts selected lifecycle SUPPORTED across the full authorized basis, **not the page**; `High priority` requires an actual persisted priority level `HIGH`, else its value is null with `Not assessed`; `Low confidence` requires an actual selected confidence enum `LOW` with reason IDs, else null with `Not assessed`; `Awaiting verification` requires a linked Action with a persisted verification window and no terminal outcome. W1 Finding revisions do not create priority/confidence merely from claim level or a gap. Show `Not assessed` when no model exists. For Actions, `Open actions` counts nonterminal W1 reduced states; `Due / overdue` stays null/`Not set` because W1 has no authored due date; `Verification window` counts persisted frozen verification windows; `Verified in 30 days` counts actual `VERIFIED` outcomes with decision time within `[known_at-30d,known_at]`, never ActionEvent `OBSERVED`. Every count uses the full scope before pagination and carries `basis_count`/coverage. If any relevant Site is not current, withhold estate totals; a row from a settled Site can still be displayed with its own status.

### Refusal table and cursor

All error bodies use `{"detail":{"code":"...","message":"...","rows":null,"total_count":null}}`; 401 includes `WWW-Authenticate: Bearer`. Auth/scope checks precede validation and DB reads. Estate endpoints have no Site filter; an empty authorized scope returns an empty covered read without foreign Site disclosure.

| HTTP | Code | Exact message / UI copy |
| --- | --- | --- |
| 401 | `UNAUTHENTICATED` | `Sign in to read estate records.` / `Sign in to see estate records.` |
| 409 | `ESTATE_BASIS_CHANGED` | `The estate selection or Site access changed; request page one without a cursor.` / `The list changed. Reload the first page.` |
| 409 | `ESTATE_SELECTION_INCONSISTENT` | `The selected Site revisions cannot be read consistently.` / `Some records are being updated. Reload the list.` |

| 422 | `INVALID_KNOWN_AT` | `known_at must be UTC and no later than the read time.` / `Choose a valid evidence cutoff.` |
| 422 | `INVALID_LENS` | `Use all, cost, risks or opportunities.` / `Choose a supported Findings lens.` |
| 422 | `INVALID_LIMIT` | `limit must be an integer from 1 to 100.` / `Choose a page size from 1 to 100.` |
| 422 | `INVALID_CURSOR` | `The cursor is not an estate cursor.` / `Reload the first page.` |
| 503 | `ESTATE_STORE_UNAVAILABLE` | `Estate records could not be read.` / `Estate records are unavailable right now. Try again.` |

Default page 50, max 100. Findings order `(episode_start DESC,finding_id ASC)`; Actions `(created_at DESC,action_id ASC)`. URL-safe base64 canonical JSON cursor has `{v:1,tenant_id,authorized_site_ids,access_basis,from,to,known_at,lens,state_filter,selection_token,after:[timestamp,id]}`; actions omit lens/state_filter but include `kind:"actions"`. Token is SHA-256 of sorted `[site_id, selected Finding revision IDs, Action selected event IDs, committed watermarks, matcher/job state]` plus window/cutoff/access basis, not page rows. Reject malformed 422; scope/selection/fence mismatch 409 even when the page is empty. All summary and provenance classification operate over the full selected set, not the current page. A repeatable snapshot alone cannot freeze page two across requests; the cursor fence does that.

## Shared provenance DTO resolution (`D-2026-10-20-shared-provenance-dto`)

The public source_provenance shape is `{classification,state,source_ids,evidence_ids,basis_sha256,reasons}` with optional `detail`. `state` equals `classification` for existing W1 readers. Classification uses the exact per-Site full cited accepted-ID union through `SourceProvenanceResolver.resolve`; consequence rows also keep the resolver's `consequence_revision` fail-closed Finding conflict. `source_ids` contains only found in-scope source UUIDs; `evidence_ids` retains every cited accepted UUID, including missing/foreign IDs. `basis_sha256` is the selection digest defined by the amended decision, with null only without any selected revision. Reasons and detail preserve typed resolver evidence. Persisted EV `class` mismatch returns UNKNOWN and `SOURCE_CLASS_MISMATCH`. No persisted EV result is changed.

Classifier precedence remains: empty/not-found/broken/foreign => UNKNOWN; crossed classes, bound+unbound, incompatible fixtures or unproven multiple runs => MIXED. Pending cold/EV reads carry separate selected-row and current-set provenance blocks; a current set never borrows a prior selected head's basis. W3-01 commit 1 delivers the compatibility alias with Lane A before review or merge. W4 may carry the same reviewed adapter first if its lane merges first. No schema migration is required.

Exact-ID tests: one W1 Finding revision and its consequence power union; one W2 cold selected revision; one W2 EV selected session/Finding/consequence; each checks the same sorted accepted IDs/class/reasons and hash input independent of paging. Add empty-head, missing-ID, foreign-ID, bound+unbound, crossed class, two fixture versions, two simulation runs and persisted-EV-class disagreement vectors. Every vector must assert selected revision IDs, every accepted evidence ID, no page-subset substitution, and unchanged historical cutoff. These are public read tests, not simulator truth tests.
