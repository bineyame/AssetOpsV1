# Architect rulings: post-W6 W4-mini build choices

2026-10-25. These rulings amend `.agent/post-W6-W4-rulings.md` for the builder's units 1–4. They are implementation direction, not D3 closure, independent review, or owner acceptance. The v6.9 mock remains the layout reference; the owner's 2026-10-25 UI bar applies. No product-code change is authorized by this document alone.

1. **R328 — keep open; public code is a backend prerequisite.** `Finding` is the correct crumb for refused and no-revision reads, and is an honest temporary label for a resolved read lacking a code. R328 stays **D3 open**, not close-as-D1: Q15 expressly requires the resolved Finding's real public code. The Finding read/backend owner must first define and expose a stable, Site-scoped public Finding code in the selected canonical mini Finding response, including its persistence or deterministic allocation and historical behavior; the Planner assigns that separate backend contract slice. W4 then consumes the field and proves `Findings › {actual code} › Alternatives` on a resolved read, with `Finding` on refused/no-revision reads. Do not synthesize a code from UUID, title, fixture, or display order. W4's no-backend-edit Q20 remains in force; record the dependency in its packet and carry R328 to the backend follow-on plus W4 UI closeout. **Pattern:** truthful labels and progressive disclosure of identity.

2. **Work 422 copy — confirm with a cause guard.** For `INVALID_WINDOW`, say `Choose a window of 31 days or fewer.` only when the submitted UTC bounds prove a span over the backend's 31 × 24-hour maximum; for a reversed range retain `The end must be after the start.` Otherwise say `Choose a valid Site-local window.` For `INVALID_CURSOR`, the page says `This page of results expired. Return to the first page.` and offers the first-page action; the strip says exactly `Counts not shown: this page of results expired.` The strip for other invalid input stays `Counts not shown: the selected window is not valid.` Keep Q4's exact-code copy for other cases and no raw server message. In particular, a Site-local 31-calendar-day selection that spans more than 744 UTC hours because of a clock change may trigger the backend limit; the copy describes the measured span, not a promise that every 31-date selection succeeds. **Pattern:** GOV.UK validation and recovery copy tied to the proven cause.

3. **`Lens: Opportunity` — change to neutral.** This is a fixed page label, not a favorable assessment or a value series. Use the neutral chip; reserve amber for stored conflict decisions and green status for an actual positive semantic state. If the mock visibly uses green here, register this as **D1 R454** and show the adjacent `MOCK DEVIATION D1 (R454)` marker; R454 is allocated from W4's spare range by this ruling. Keep text independent of color. **Pattern:** WCAG 2.2 use of color and semantic status badges.

4. **Bar colors — confirm the four tokens.** Keep PV `#a87a2c`, retained margin `#77839a`, usable headroom `#3a8f7c`, and stored `CRITICAL` load `#b65252` on their named series only. The text legend and unknown hatching remain mandatory; these colors do not make an unassessed value assessed. Confirm the rendered fill against its actual track at 1440 and 390 for at least 3:1 non-text contrast, including any theme in the W4 capture set. A token value alone is not contrast proof. **Pattern:** WCAG 2.2 non-text contrast and redundant labels.

5. **Refused frame — confirm the 422 scope.** The new Q7 frame applies to invalid-window 422 on all four mini depth screens: period control, heading, refused strip with `Confidence: Not assessed`, muted `Not assessed` tiles, and one reason in the first panel. Keep each screen's existing 401/403/404/503 refusal behavior and copy; do not convert those to an input-validation frame. Where those responses render a refused status strip, keep `Confidence: Not assessed`; never imply a measured confidence. Check each of the four screens for all five status classes during recapture. **Pattern:** GOV.UK recoverable inline validation with preserved page context.

6. **Q11 — keep the mini-local frame.** The permitted fallback in Q11 applies now because W2-cold is not merged. W4's later rebase does **not** require lifting cold `RefusedStrip`/`RefusedTiles`. Lift only if the rebase proves a small shared unit preserves cold props, DOM semantics, visuals and behavior, and its shared-code unit receives independent review before dependent work. Otherwise leave the two local implementations and capture cold regression. **Pattern:** consistent interaction with bounded, low-risk component reuse.

7. **Window end date — unify the two mini forms as inclusive UI dates.** Keep Work's `to (included)` behavior. Change mini Scenarios from the exclusive `To` date to `To (included)`; label both fields with the Site zone (or `UTC` fallback), for example `From (EAT)` and `To (EAT, included)`. A chosen end date is converted to the next Site-local midnight for the half-open UTC URL/API bound; when displaying an existing exclusive bound, show its preceding Site-local date. Preserve `from < to`, cutoff and first-page reset on Apply, and test month end and a clock-change boundary. The backend interval stays half-open. This is within the already proposed D2 R450 page-local Scenarios control; update its proposal/captures so the owner sees the exact UI copy. **Pattern:** consistent, explicit date-range inputs and Site-time context.
