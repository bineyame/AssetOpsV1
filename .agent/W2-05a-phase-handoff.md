## Questions for the Architect (answer before commit 2 or at review; none blocks commit 2's code)

- **QA, timezone `UTC`.** `site_parsing.TIMEZONE_PATTERN` checks shape (`Area/Location`) and refuses a bare `UTC`. The tests use `Etc/UTC`, the IANA name for UTC, which has a fixed offset of 0. Should the commit-2 fixture use `Etc/UTC`, or should the shared pattern be widened to admit exactly `UTC`? The default is `Etc/UTC`, with no change to the shared parser.
- **QB, property kinds.** The spec gives `kind` only for `ev-connector-enabled` (CONTROL). The other eight follow the closest existing precedent: ratings, meter resolution, meter error bound and clock bound are PHYSICAL (like `generator-rated-power` and `cold-probe-error`); site import limit and both cadences are CONTROL (like `cold-min-excursion`). Please confirm or correct. Each is a one-line change in `models.py`.
- **QC, feed absence vs "charger without one feed/meter".** Q3 makes an absent feed publishable. It is applied as follows: a charger or meter with more than one parent is always refused; an unfed charger, or a meter with no feed, is refused only when an AC_BUS is declared; and any schedule hours need a full feed->meter->charger path. Please confirm.
- **QD.** The response shape has a single `feed`. Nothing yet refuses a second AC_BUS on an EV Site. Should a second AC_BUS be refused, or is that left to the commit-3 read?

3. **Q3:** Only absent feed/connector or `ev-site-import-limit` is publishable as a configuration gap. 4. **Q4:** State cadence is the connector `ev-status-cadence` in minutes converted to seconds, >0 and ≤60 s. Energy, power, import, requested and allocated use `ev-meter-cadence`, >0 and ≤300 s; EV publication's interval grid is aligned 300 s. Events have null cadence. `BindingRequest` has no cadence field; derive the selected read's `cadence_seconds` from Foundation. Above-ceiling Foundation values refuse `EV_CONFIGURATION_INVALID`; an unexpected request cadence field refuses `BINDING_REQUEST_INVALID`. Positive `ev-clock-error-bound` seconds is selected configured tolerance, not observed clock attestation.

Check every occurrence for bounded revisions; an open-ended revision admits only a zone with fixed future offset, so a DST zone needs bounded revisions.
