1. **A1 — current money head.** On POST and correction, call `scenario_money_on(c, snap)` with no as-of cutoff on the same repeatable-read write connection. Persist consequence and tariff revision IDs only for the method's eligible current priced result; otherwise persist both as null. `known_at` is the selected EV evidence watermark, not a DB `recorded_at` cutoff. The `_select_as_of` branch would incorrectly hide the E1 fixture's DB-time money head. Test a CURRENT complete selection with an eligible priced consequence: both stored IDs equal the current W2-07 head and cited tariff. Also test withheld/unpriced money: both IDs are null, with an otherwise valid scenario accepted.

2. **A2 — list limit.** Keep existing 422 `EV_LIMIT_INVALID`, message `"'limit' must be 1 to 100."`, for non-ASCII digits, zero, over 100 or any malformed explicit `limit`. Default is 50, maximum 100. Test those boundaries and a 51-root list without a limit: 50 rows and `next_cursor`, then one row.

3. **A3 — correction identity and link scope.** Unknown, malformed or foreign-Site root: 404 `DECISION_NOT_FOUND`, message `No decision with this ID at this Site.` A syntactically valid predecessor revision ID outside the scoped root: 422 `DECISION_LINK_SCOPE_INVALID`, message `A cited or linked ID is outside this Site or basis.` An invalid predecessor UUID shape remains 422 `EV_SCENARIO_INVALID`, message `The EV scenario request or selected basis is invalid.` Test all three with zero appended revisions; retain 409 `EV_SCENARIO_REVISION_CONFLICT` for a valid but stale predecessor in the root.

4. **A4 — index direction.** Keep the specified `ev_scenario_site_order(tenant_id,site_id,recorded_at DESC,id)` index. List ordering remains `(recorded_at DESC,id DESC)` with a matching cursor predicate. The trailing index direction does not change results; no migration churn is justified for this review. Pin the index definition in `test_schema_constraints` and test equal-`recorded_at` pagination in `test_pending_historical_list_and_cursor` so the query/cursor order is explicit.

5. **A5 — currency.** A different authored currency is an unsupported cross-currency tariff comparison when E5 selects an eligible priced consequence with a non-null tariff revision. Refuse POST or correction with 422 `EV_SCENARIO_INVALID`, message `The authored currency must match the selected priced tariff currency.` Compare the uppercase authored ISO code to the selected consequence's currency on the same write connection; return the currency from `scenario_money_on` for this validation without adding it to persisted `authored_basis`. If money is unpriced or withheld (null IDs), there is no priced currency to compare, so accept any syntactically valid authored ISO code and keep both money IDs null. Test KES priced consequence plus USD command refuses with zero rows/appends; KES plus KES succeeds; unpriced plus USD succeeds with null money IDs. No conversion or computed amount is introduced.

6. **A6 — foreign meter evidence.** A complete session's meter evidence is foreign if *either* it is outside the window's accepted evidence at the selected cutoff *or* its ID is absent from the selected assessment head's cited `evidence_ids`. Membership is case-normalized. Refuse 422 `EV_SCENARIO_INVALID`, message `The EV scenario request or selected basis is invalid.` Do not silently intersect and persist a smaller meter list. Test an accepted meter ID omitted from the selected head, and a cited meter ID omitted from the accepted set; each gives zero writes. The positive test asserts `authored_basis.accepted_evidence_ids` equals the complete-session meter IDs and every ID occurs in both sets and in `authored_basis.source_provenance`.
