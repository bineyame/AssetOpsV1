## 1. Frozen model, selection and wire

The merged source of truth is `backend/assetops_backend/work/model.py` (`SCHEMA_*`, `TRANSITIONS`, `MESSAGES`), `work/site_index.py:select`, `work/detail.py:WorkDetailService.detail`, `work/service.py:WorkService`, `work_api.py:build_work_router`, and migration `0027_w4_work_cases`. W3-01 `estate/scope.py` and `estate/index.py` supply tenant-authorized Site selection and cursor/access patterns; W3-03 `estate/portfolio.py` supplies the cross-root link pattern. Reuse those selection primitives on **one read-only REPEATABLE READ connection**, never call the Site HTTP reader N times. No stored public number from the mock (`INC-203`, `WR-019`, `PM-0455`, `REC-312`) is a fixture ID.

**Identity.** Case identity is `(tenant_id,site_id,work_case.id)` with `INC-`/`WR-` code; plan identity is `(tenant_id,site_id,maintenance_plan.canonical_plan_id)` with root `PM-` code; record identity is `(tenant_id,site_id,operational_record.canonical_record_id)` with root `REC-` code. Read the exact stored code, never generate a display code from UUID. `asset_id` is nullable and must join on tenant and Site. A case correction is the max selected `(revision_no,id)` at `recorded_at<=known_at`; events and performed records use `(recorded_at,id)`; plans/operational records select the one successor head at cutoff and expose the full supersession chain when requested. Select only `created_at`/`recorded_at` at or before cutoff; no future knowledge. Historical means an explicit old `known_at`, not merely an old occurrence.

**Window and access.** All four roots use a whole UTC day `[from,to)` window, maximum 31 days, default last seven complete UTC days; `known_at` is one UTC instant no later than captured DB time. Use the existing W3 parser limits (`limit=50` default, 1–100). Scope is principal-derived tenant plus all authorized imported Sites, including Sites with zero records. Access and Site membership precede query parsing; wrong tenant/Site/ID is 404 or 403 by existing scope policy, never a foreign row. `total_count` counts full selected scope before pagination. Status precedence: `EMPTY_SCOPE` (no accessible Sites), `HISTORICAL` (explicit earlier cutoff), `PARTIAL` (a selected Site read unavailable), then `CURRENT`; a store outage is 503, not a successful partial list if the snapshot cannot be established. `coverage` reports selected and unavailable Site counts; zero is asserted only for complete coverage. Sort cases by `(occurred_at desc,site_code_key asc,site_id asc,case_id asc)` for incidents and `(created_at desc,site_code_key asc,site_id asc,case_id asc)` for requests; plans and authored records by `(recorded_at desc,site_code_key asc,site_id asc,id asc)`. Cursor binds route kind, window, cutoff, authorized Site IDs/access basis, complete row/revision/event/record/lineage selection digest and last tuple. Tampering is 422 `INVALID_CURSOR`; changed scope or selected set is 409 `WORK_BASIS_CHANGED`; restart page one.

**New read envelope.** `schema_version` is `global-work-index-1`; keys always present: `scope:{authorized_site_count,covered_site_count,access_basis}`, `window:{from,to,bounds:'[from, to)'}`, `known_at`, `status`, `coverage:{state,reason,sites}`, `total_count` (integer or null), `rows` (array or null on refusal), `next_cursor`, `selection_token`. Read-only detail envelope `global-work-detail-1` uses `selected:{site_code,site_id,case_id,case_code,case_kind,known_at}`, the existing `work-case-detail-1` fields verbatim, `history:{revisions,events,records}`, and `links`. No API accepts a client tenant. Decimal quantities are strings. All timestamps are ISO UTC. Null is never rendered as zero.

**State and refusal literals copied from merged code.** Incident `OPEN|IN_PROGRESS|CLOSED`; request `OPEN|IN_PROGRESS|COMPLETED|CANCELLED` (`VERIFICATION_WINDOW` is unreached by W4); plan `DRAFT` (other stored enum values reserved); operational record `SUBMITTED` (`ACCEPTED|REJECTED` unreached). Case commands remain `ASSIGN|COMPLETE|COMMENT|CLOSE|REOPEN|CANCEL`; `CREATED|OPEN_VERIFICATION` are not writable. Use existing `WORK_CASE_NOT_FOUND` 404, `WORK_INPUT_INVALID` 422, `INVALID_KNOWN_AT` 422, `INVALID_WINDOW` 422, `INVALID_LIMIT` 422, `INVALID_CURSOR` 422, `WORK_BASIS_CHANGED` 409, `WORK_CORRECTION_CONFLICT` 409, `WORK_LINK_SCOPE_INVALID` 422, `WORK_WRITE_FORBIDDEN` 403, `WORK_STORE_UNAVAILABLE` 503, `UNAUTHENTICATED` 401 and `SITE_SCOPE_FORBIDDEN` 403. New global list 404 for an inaccessible exact case uses `WORK_CASE_NOT_FOUND`; do not create a global case ID lookup that discloses existence. Existing response `detail:{code,message}` is preserved on refusal and `rows/total_count:null` is appended for list refusals.

**Links.** Frontend route identity is the stored Site **UUID**, as `frontend/src/shell/operatorSiteRoutes.ts` shows, while API scope is the stored Site code. Use `siteWorkIncidentsHref(siteId,query)` or `siteWorkMaintenanceHref(siteId,query)` for a global case row until W6-01c supplies exact `/work/requests/{case_id}?site_id={site_uuid}&known_at=...` detail; later exact request links carry both Site UUID and cutoff, never a row number. Finding uses `siteFindingHref(siteId,findingId,findingRevisionId)` only if W4's lineage flag is true. Action uses W1 `selected_action_links` exact event URL; null href is plain text. Site uses `siteDetailHref(siteId)`. Asset uses `siteAssetHref(siteId,assetId)` only after W6-03 makes that route live; before then asset code is plain text. `workverification`, warranty and Operational-record detail mock destinations are plain text until a reviewed route exists. No dead anchor or click handler.

**No new schema.** `0036` is reserved **unused** because W4 `0027` contains the required append-only identities, scope FKs, order indexes and correction lineage. Current checked Alembic head on main is exactly `0030_w4_mini_decisions` (down `0029_w4_mini_depth`); `0031` is also unused and `0032`–`0035` are future reservations. There is no `0036` revision or `down_revision`, and no empty migration file. If DDL becomes necessary, the Architect must first name the actual installed predecessor after numeric-order merges and amend the complete migration; no local guess at `0035` is permitted.
