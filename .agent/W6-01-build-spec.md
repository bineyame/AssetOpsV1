**Identity and time.** Frontend `siteId`, API `{site_code}`, and every Site href use the stored **Site code** (`sites_api.py:212`), never Site UUID. UUID is internal scope/FK identity. Case root `(tenant_id,site_id,work_case.id)` retains stored INC/WR code; plan/operational root `(tenant_id,site_id,canonical_plan_id/canonical_record_id)` retains the root PM/REC code. Case revision is the last `(recorded_at,id)` at cutoff, matching `work/detail.py` and `work/site_index.py`; event and record order is `(recorded_at,id)`. For cases, membership uses root `occurred_at` (incident) or root `created_at` (request), even when a later revision crosses the window. Global incident rows sort by `(root occurred_at desc, site_code_key asc, site_id asc, case_id asc)`; global maintenance rows sort by `(root created_at desc, site_code_key asc, site_id asc, case_id asc)`. Compare the complete tuple in that order for cursor continuation; UUID tiebreaks use lowercase canonical strings. For plans and operational records, membership uses **root `occurred_at`**, head selected at cutoff; display/sort by selected head `(recorded_at desc,site_code_key asc,site_id asc,canonical_root_id asc)`. Thus a correction does not move a root between windows. `occurred_at` in an operational row is the selected head's occurrence and is the `When` display; root occurrence is a separate field. Root and head timestamps must be at/before `known_at`. Global list and outer detail wire instants are whole UTC seconds with `Z`; nested `work_detail` retains merged W4's six fractional digits and `Z` for every instant. New `history.revisions[].occurred_at`, `history.revisions[].recorded_at`, `history.operational_records[].occurred_at` and `history.operational_records[].recorded_at` use six fractional digits and `Z` as well; `selected.known_at` uses whole seconds. Cursor/token canonical instants retain six digits. Decimal quantities are strings.

**Parser, access and status.** Global list routes are `GET /api/work/incidents`, `/maintenance`, `/preventive`, `/operational-records`. Authenticate first (401), then the W3 `estate/scope.py:parse_request` window/known/limit discipline adapted to four work kinds: exactly one `from` and `to`, UTC midnight, `[from,to)` 1–31 days; optional single UTC `known_at` no later than DB read time; `limit` 1–100, default 50; optional `cursor`. `kind` only on operational records, one of `all|OPERATOR_LOG|MANUAL_READING|SHIFT_NOTE|SITE_VISIT`, default `all`. Unknown/repeated non-window keys are `INVALID_CURSOR`; bad/missing window keys are `INVALID_WINDOW`. **Server requires the window**; UI initially sends the last seven complete UTC days ending at today's 00:00 UTC and never claims the server defaulted it. Every global page reads single `from`, `to` and optional `known_at` from `location.search`, validates them by the same UTC rules, populates the controls, and sends them unchanged on first read, reload, pagination and Site fallback links; invalid page query shows the `INVALID_WINDOW`/`INVALID_KNOWN_AT` refusal without fetching. Only when both `from` and `to` are absent does the UI use the seven-day initial window; one missing bound is `INVALID_WINDOW`. A denied Site is silently excluded, exactly as W3 estate roots do; global lists have no 403/404. Scope includes `tenant_id` (UUID or null for unavailable tenant), counts, and W3 `access_basis`. If zero Sites are authorized, status is `EMPTY_SCOPE` even with an earlier explicit `known_at`; otherwise earlier explicit cutoff is `HISTORICAL`. `PARTIAL` is reserved for a future per-Site independent read model and is **not produced** by this single-snapshot implementation. Current status is `CURRENT`; store failure is 503. `coverage.state` is `COMPLETE|EMPTY_SCOPE`, `reason` null or `NO_ACCESSIBLE_SITES`, and `sites` is an array of `{site_code,site_id,state:'COVERED'}`. A successful complete zero has `total_count:0`; no null-to-zero coercion. Cursor snapshots pin page-one cutoff and full selected set. Use the W3-03 Portfolio HMAC pattern (`estate/scope.py:299–341`) with a dedicated required `ASSETOPS_WORK_CURSOR_KEY_HEX` (64 hex chars, no default): bad key => 503, bad MAC/shape => 422, changed scope/selection => 409. Set it in test and capture server environments before the first read; A1 documents local generation beside the estate key in `backend/README-db.md`, never prints/logs it, and tests missing/malformed key. Bind route, kind filter, window, cutoff, authorized Site IDs, access basis, full selected root/head/revision/event/link lineage IDs and last sort tuple. Do not reuse W4's unsigned cursor.
