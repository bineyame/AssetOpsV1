# S3-02a handoff to S3-02b (claim-limit UI and walkthrough)

Branch `task/S3-02a-capability-read`. Non-UI read is built; S3-02b builds the Evidence Analysis S3 section on it.

## Route

`GET /api/sites/{site_code}/performance/dispatch/windows/{YYYY-MM-DD}/claim-limit?revision=<assessment_revision_id>[&rule=s3-claim-limit-1]`

- Day = half-open UTC day; `revision` = exact interval (or window) `assessment_revision_id`. Use the S3 Dispatch view's `day` and `revision` identity (`PerformanceDispatch.tsx`), not the legacy `assessment` query param (plan rereview R1).
- No `revision`: 200, `currentness: "UNASSESSED"`, `capability: null`, `claim_limit.ceiling: null`, reason `NO_REVISION_SELECTED`; `window_status` still says the window's state (UNASSESSED/PENDING/CURRENT/STALE_PROJECTION/FAILED). This is the "no assessment selected" section of S3-02b.
- Refusals (body `detail.code`): 401 `UNAUTHENTICATED`, 403 `SITE_SCOPE_FORBIDDEN`, 404 (unknown Site, string detail), 503 `ASSESSMENT_STORE_UNAVAILABLE`, 422 `INVALID_REVISION_ID` / `UNSUPPORTED_RULE_VERSION` / `REVISION_OUTSIDE_WINDOW`, 409 `PERFORMANCE_CUTOVER_CLOSED` (with `capability: null, claim_limit: null`), 404 `ASSESSMENT_REVISION_NOT_FOUND`, 409 `ACCEPTED_LINEAGE_ABSENT`.

## Response (200) fields the UI needs

- Echo: `schema` `assetops.s3-claim-limit-read` v1, `rule_id`, `site_code`, `tenant_id`, `site_id`, `day`, `window{start,end}`, `read_at`, `window_status`, `window_status_reasons`, `current_selection{run_id, model_version, revision_ids}`, `assessment_revision_id`, `scope` (INTERVAL|WINDOW), `assessment_key`, `revision_no`, `claim_level`, `currentness` (CURRENT|STALE_PROJECTION|FAILED|PENDING|HISTORICAL|UNASSESSED), `run{run_id, model_version, knowledge_cutoff, cohort_status, cohort_sha256, input_sha256, configuration_sha256, foundation_revision_ids, binding_set_revision_ids, built_at}`, `accepted_evidence_ids`, `watermarks{source{source_time, published_at, received_at, accepted_at}, analytic_built_at}`, `built_at`, `not_inferred`, `source_gate`.
- `capability.roles[role]` for `generator_state`, `feeder_demand`, `pv_available_power`, `pcs_discharge_capability`, `battery_soc`: `status` (COVERED|INCOMPLETE|NO_SPANS), `covered_minutes`, `minutes_by_status`, `evidence_ids`, `spans[]{status, start, end, minutes, evidence_ids, problems, assessment_revision_id}`. Span status: COVERED, MISSING, POOR_QUALITY, CONFLICTED, NOT_EVALUATED. Each span's `evidence_ids` are the Evidence drill-down targets (all are in `accepted_evidence_ids`).
- `claim_limit`: `ceiling` (CANDIDATE_AVOIDABLE|NECESSARY|INDETERMINATE, null unless CURRENT), `current_positive_claim`, `support` (COMPLETE|LIMITED|NONE), `supported_minutes` (string, the class's segment sum, never the whole interval), `statement`, `historical_ceiling` (same four keys, only when not current), `reasons[]{code, text, role?, start?, end?, minutes?, scope?}` with codes MISSING_ROLE, POOR_QUALITY, CONFLICTING, GENERATOR_UNOBSERVED, OPEN_BOUND, MODEL_LIMIT, COHORT, CONFIGURATION, RULE_BASIS_INCOMPLETE, NOT_CURRENT, NO_REVISION_SELECTED. Window scope adds `interval_ceilings[]{assessment_revision_id, claim_level, ceiling, support}` and has `ceiling: null`.

Normalised sample responses for every case: `backend/tests/fixtures/s3_claim_limit_api_samples.json`.
