# Reply to the owner: demo data questions 2, 4, 5 and 7 (28 October 2026)

**2. Source labels.** Agreed. Histories built on real public inputs get their own label, "Simulated with real public inputs", and their money follows exactly the same rules as any simulation. The server derives the label from the input files' fingerprint, so nobody can type it in, and it disappears if the inputs change. Cost: about half a day. A whole new category would cost three to four days for the same result. *Example:* Turkana shows "Simulated with real public inputs: weather measured by NASA near this location", and its generator saving is calculated exactly as at our lab site.

**4. 90 days.** You are right. The run limit counted minutes, but cost comes from calculation steps. A second limit, meant to catch typing mistakes, would have blocked faults after the first week even at 56 days. Both are being replaced. We will use 13 weeks, which keeps weekdays aligned. Because this laptop recently had runs killed for low memory, the first task measures memory and time at 7, 28, 56 and 91 days before anything is built. *Example:* Turkana gets three clean weeks, four weeks with the battery-reserve fault, the fix on 14 September, then six weeks after.

**5. Licences.** For test and demo use: any publicly downloadable data, always credited. Files without an open licence stay on the laptop, out of the repository, and raw files are never handed to a prospect. Still real: no data marked "non-commercial", because a sales demo is commercial use, and a fresh check before any pilot or production use. *Example:* Caltech charging sessions shape our bus arrivals and are credited on screen, but the file is never shared.

**7. Data requests.** You are right; I have withdrawn it. That data sits under private agreements with named partners. A request would at best start months of contract talks, with limits that could exclude a sales demo. *Example:* Renewvia goes on the pilot list instead, where their data would come under a pilot agreement.
