The "historical file-backed sealed batch" comparison for imported KOBO-001 is therefore an empty-set comparison. Default (fail closed): the comparison tool still runs explicitly, reads the file store and committed artifacts for the Site, records `NO_LEGACY_EVIDENCE` with zero counts and an empty exception list, and the Postgres Evidence read switch for an imported Site opens only when a stored comparison record for that Site says `PASSED` or `NO_LEGACY_EVIDENCE`; without one the routes keep 409 `SiteAwaitingMigration`. Nothing is written into Postgres from file evidence; SITET26 stays on its file path. Is an empty-set record an acceptable cutover basis, or must the owner see a non-empty replay (e.g. a SITET26 dry-run of the legacy parser as a parser fixture)?
