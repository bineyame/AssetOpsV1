Nothing is written into Postgres from file evidence; SITET26 stays on its file path. Is an empty-set record an acceptable cutover basis, or must the owner see a non-empty replay (e.g. a SITET26 dry-run of the legacy parser as a parser fixture)?

Q14. **Where the comparison record lives.** Default: a JSON report under `var/evidence/migration/<site_code_key>.json`, written once by an explicit CLI through a new evidence file adapter added to the guard's evidence file writers; it is not a product row and never overwritten (a re-run writes a new timestamped report; the newest decides).
