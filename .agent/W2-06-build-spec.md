## Identity, selection and storage contract

`ev_session` identity is scoped `(tenant_id,site_id,charger_asset_id,connector_asset_id,external_session_id)`, anchored to the first accepted START evidence ID and source time. An orphan terminal is retained as context in the selected read, not materialized as a started session. An accepted second START with distinct ID is a W2-00 `SESSION_ID_CONFLICT`; separately accepted ENDs/ABORTs remain analytic contradictory inputs. Effective `ev-roles-1` binding resolves the connector's *single* parent charger, exact source/device/signal and Foundation at each source time. Multiple/unknown parent, wrong connector or cross-Site ID is excluded with reason, never joined by label. No session starts from PLUGGED, status or a private vehicle request.

Add 0025 tables/constraints exactly as EV design §1: scoped FKs and uniqueness, positive revision, ordered nullable bounds, nonnegative finite decimal kWh/error/unknown seconds, SUPPORT interval exclusion, immutable triggers and guarded downgrade. Reuse `analytic_run`, `analytic_run_evidence`, `assessment_revision`, `finding`, `finding_revision` and `recompute_job`; widen both Finding domain checks without loosening mini-grid/cold branches or nullable dispatch fields. For EV, `analytic_id='ev-session/1'`, `cohort_status='NOT_APPLICABLE'`, `cohort=[]`, `cohort_sha256=sha256(canonical([]))`. `finding.domain` and job domain are literal `ev_charging`. One fault-abort Finding key is SHA-256 of canonical tenant/Site/`EV_INTERRUPTION`/charger/connector/session/first START evidence. Finding subject is connector; START/FAULT/ABORT exact accepted IDs support the revision, its bounds are START→ABORT, dispatch minute columns null and limitation says fault observed while component cause and unmet demand remain unknown. A new basis appends a revision; a later contradiction withdraws current support without deleting the old record.

For a strict selected half-open UTC `[from,to)` of at most 31 days and committed `known_at`, select accepted GOOD, clock-attested, time-valid records at that cutoff. A session belongs to the full-window denominator and list when its accepted START source time is in `[from,to)`; a session that started earlier and overlaps the window is labelled context, never a new attempt. One START, at most one nonconflicting terminal and source order within the declared 30 s cross-source error establish state. Missing terminal stays INCOMPLETE even if status turns idle. ABORT without a same-session contemporaneous fault is OBSERVED_ABORT but creates no fault-associated Finding. SUSPECT, unattested, wrong binding and ambiguous records are CONTEXT/EXCLUDED with exact reason and IDs. Basis SHA hashes sorted accepted ID+content SHA/use/reason, Foundation/binding/mapping revisions, model/rule version, exact window/cutoff and source class. Replaying the same basis is idempotent; a later END, terminal conflict, meter or source-gate change appends an immutable revision.

For each started session, intersect meter `INTERVAL_DELTA` reports with `[START,terminal)`; while terminal is missing, only the observed active span is bounded and any remaining duration is unknown rather than assumed active to window end. Require same connector and session, GOOD clock/source and wholly contained nonoverlapping half-open interval. Reject a spanning unsplit report, overlap, negative/nonfinite delta, or `kWh > connector_max_kW × hours + 2×meter_error_bound`. Sum accepted exact Decimal deltas. Unknown seconds are the union of uncovered **bounded active** five-minute slots clipped to established bounds; a missing terminal also carries `MISSING_TERMINAL`, so 30.000 known partial in the late case never becomes a complete total before END. `supported_kwh=null` with zero supported intervals; otherwise it is explicitly partial until all active slots, including split boundary slots, are covered and terminal is sound. `energy_complete=false` for incomplete/contradictory or any gap. No selected report implies zero energy; no power-integrated substitute. Status one-minute slots can give known/unknown service context but no W2 availability percentage or equipment-health conclusion. Site import below configured limit is context only, never proof that site power did or did not cause a stop.

Use a caller-supplied transaction in `assessment_worker.py` + `postgres_assessment_store.py` to append analytic run, assessment, session/revision/evidence/intervals, optional Finding and links, then complete the job; rollback all on any invariant failure. Enqueue `ev_charging` on every newly accepted relevant v4 EV event, state, meter or binding/source-gate change, including late source time. Dirty the affected session/window heads with scoped joins; a failed/leased/pending overlapping job keeps current reads `PENDING_RECOMPUTE`, never silently current. Preserve exact old revision at explicit historical cutoff. A duplicate batch adds no new assessment. Do not use the stale older head for a new current claim.
