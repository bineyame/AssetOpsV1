## 2. W2-05a Foundation, role set, readiness

Register immutable `ev-roles-1` in the site-type role registry; bind by effective Foundation and source mapping revisions (`backend/assetops_backend/sites/binding_roles.py:17-27,117-130`). Topology is Site feed → Site import meter → EV charger → EV connector; each connector has exactly one parent charger, each charger one feed, each asset ID distinct, no topology cycles or cross-Site links. Charger/connector serial labels are display metadata, never session IDs. Site import limit and charger/connector ratings are effective Foundation facts, not measured capacity. Connector enable schedule is a time-valid authored schedule in Foundation (`weekly local intervals`, Site timezone, explicit UTC offset resolution for DST); W2 uses it for configured service hours only, not an availability percentage. Reject overlapping intervals, nonexistent/ambiguous local instants and enabled connector without a declared charger/feed/meter. No stationary battery unless explicitly declared.

| --- | --- |
| `ev_session_event` / EV_CONNECTOR | `EV_SESSION_START|END|ABORT`, one event channel per connector; session ID + connector ID required, `correlation_id=session_id`; required for outcome. |
| `ev_connector_fault` / EV_CONNECTOR | `EV_CONNECTOR_FAULT|CLEAR` event, one per connector; optional for completion, required for fault-caused interruption. Fault event's optional session ID must match same connector when attached. |

Each role has registered source/device/signal, same-Site asset, exact unit and mapping, effective validity, cadence and clock bound. One physical signal cannot silently serve incompatible roles. `INTERVAL_DELTA` is an interval energy fact, never a cumulative counter. If a vendor supplies cumulative meter values, the labelled peer adapter converts only adjacent monotone readings with exact timestamps, meter reset/rollover declaration and error bound; reset or ambiguous jump yields no delta. Missing role, wrong unit/asset, overlapping bindings, ambiguous charger parent, invalid schedule, or cadence > configured ceiling refuse publication with typed configuration error; old Foundation revisions remain selectable. Readiness messages are fixed: `CONNECTOR_NOT_DECLARED`, `FEED_OR_LIMIT_MISSING`, `METER_NOT_BOUND`, `SESSION_EVENTS_NOT_BOUND`, `STATUS_NOT_BOUND`, `SITE_IMPORT_NOT_BOUND`, `SOURCE_NOT_CONTACTED`, `COMMISSIONING_UNCONFIRMED`. First six are configuration/capability, contact is S7 receipt state, commissioning needs an actual record. `READY_TO_REPORT` means configured, never commissioned/healthy (`.ai/DECISIONS.md:5-15`; `.agent/W2-technical-design-cold.md:38-57`).

## 3. W2-05b versioned charger/session producer

Add `ev-charger/1` `ModelSpec`, `ev-publication/1`, `ev-observation/1` to the part-1 closed host registry, preserving all existing model identities (`host/execution_adapter.py:123-149`; `.agent/W2-technical-design-cold.md:59-69`). Reject unknown pack/profile/parameter version before Draft. Frozen run identity includes Foundation/binding/source IDs, scenario SHA, pack/profile/observation versions, UTC window and seed. Stage seals only public v4 reports; registered Commit → SQLite outbox → authenticated Batch V2 → S2 accepted evidence. No direct evidence/Finding seed, Lab private state, vehicle/customer identity or hidden demand in envelopes (`host/lab_execution.py:2154-2164,2428-2501`; `frontend/docs/architecture/production-shaped-mvp-technical-design.md:131,183`).

**Discrete model.** One-minute UTC step, exact decimal arithmetic; default fixture has two 60 kW connectors, 80 kW site import cap, both enabled 08:00–16:00 UTC on 2026-10-06, site non-EV base load 0 kW. State per connector: `UNPLUGGED|PLUGGED|AUTHORIZING|CHARGING|FAULTED`, session ID or null, authorization result, requested kW, allocated kW, meter accumulator kWh, fault latch. Private forcing: plug/unplug, authorization accept/deny, request schedule, fault/clear, grid interruption, publication dropout/latency. Initial unplugged, no session/fault, accumulator 0. At each minute: apply forcing ordered `(time,connector,kind)`; a plug assigns next deterministic scoped session ID; authorization takes 1 minute; acceptance emits START when CHARGING begins; denial produces no START and is a contextual observed state, not a failed session. Allocate shared available power `max(0,site_limit-base_load)` by connector ID ascending in round-robin 1 kW quanta among charging connectors up to `min(request,connector_limit,charger_limit)`; persist round-robin pointer so no connector monopolizes successive minutes. `E_next=E+allocated_kW/60`, exact kWh. A fault latches FAULTED, emits FAULT and ABORT for an active started session; explicit user unplug emits END (completed) only after active charge and no fault; grid interruption pauses allocation and connector state, it does not invent ABORT. Fault clear requires explicit forcing and emits CLEAR; a new plug creates a new session. Simultaneous END/ABORT or START twice for one ID is prohibited by simulator sanity guard. Fail run on negative energy, allocated sum above available/site/connector limits, energy residual, state with no valid session, duplicate conflicting forcing or non-monotone time.

**Public transform.** `ev-publication/1`: connector state at transitions and every minute; connector interval energy delta over aligned five-minute `[start,end)` slots (including zero while an active accepted session pauses), with session ID carried in the role-bound measurement extension; power mean per slot optional; site import mean per slot; session/fault events at observed transitions. To make meter correlation explicit, v4 measurement payload gains optional paired `session_id,connector_id` keys: both required for `ev_connector_energy`, connector must match role asset; existing canonical v4 cold payload without those keys remains readable, while v3 remains byte-for-byte unchanged. The parser emits nulls internally when keys are absent. `source_time=interval_end` for interval reports. At a session boundary inside a slot, split at the boundary into nonoverlapping subintervals so no kWh crosses session identities; null-session energy cannot be assigned to a session. Round accumulated energy to 0.001 kWh, half-even, by differencing rounded end/start accumulator, making published slot deltas additive; meter bound 0.001 kWh per boundary. Event IDs derive from scenario SHA, channel and transition ordinal; retransmission preserves IDs/bytes. Observation gap drops a channel report, never changes the world; delayed report retains source time and message identity. Mapping `simulator-lab-gateway-ev/1` is an exact allowlist for `(charger-controller,session-event)`, `(connector-controller,fault-event)`, `(connector-controller,state)`, `(connector-meter,energy)`, `(connector-meter,power)`, `(site-meter,import)`, `(connector-controller,requested-power)`, `(connector-controller,allocated-limit)` with above kinds/units/cadences; no wildcard (`simulator/assetops_simulator/gateway/mappings.py:22-46,87-107`).

## 4. W2-06 session correlation, meter sum, Finding, currentness

Select only accepted, GOOD, clock-attested records with valid effective Foundation/binding and exact `(tenant,site,charger,connector,session_id)`; EVENT session ID comes from W2-00, energy identity from the v4 measurement extension above. Require one START, at most one terminal END or ABORT, ordered by source time with <=30-second declared cross-source clock error; a terminal without START remains orphan context, not a session. An END is COMPLETED only when same scoped ID, no competing ABORT, and no contradictory state; explicit ABORT proves OBSERVED_ABORT, while contemporaneous fault on the same connector/session is additionally required for a **fault-associated** Finding. Fault alone does not prove an abort. Missing terminal is INCOMPLETE regardless of apparently idle status; conflicting good terminal/start times or incompatible connector identity is CONTRADICTORY. `SUSPECT` and unbound reports are context/excluded with reasons, never settle outcomes. Repeat events are deduped by W2-00 and cross-tenant/session collisions cannot join.

For each session, intersect GOOD connector `INTERVAL_DELTA` reports with `[start,terminal)` and same session ID; accept only wholly contained, nonoverlapping half-open intervals with finite `0<=kWh<=connector_max_kW*duration_hours+2*meter_error_bound`, and matching exact source. Do **not** pro-rate a report spanning a boundary, choose between conflicting duplicates, substitute power integration or infer zero for an absent slot. `supported_kwh=sum(exact accepted deltas)`; `unknown_meter_seconds` is the union duration of uncovered active 5-minute slots, clipped to session bounds. A delivered-energy total is **complete** only if every active slot is covered (partial boundary slots must have a split report) and no contradiction; otherwise report known partial sum with `energy_complete=false` and unknown time, never call it total delivered. If no supported intervals, quantity null rather than zero. Session outcome counts use START denominator, separately completed/observed abort/incomplete/contradictory; orphan records are separate. No availability percentage or site constraint cause in W2. Synchronized site import below limit is context only; a power-constraint claim requires independent accepted requested and allocated-limit signals plus site import over the same slots, and W2 still labels competing causes unknown (`.agent/architect-W2-design.md:37-49`).

`ev-session/1` assessment basis SHA sorts accepted evidence IDs+content digests, excluded/context IDs+reasons, effective Foundation/binding/mapping IDs, model/rule versions, `[from,to)`, `known_at` and source classification. Session revision and its evidence/interval links append atomically with `assessment_revision` and any FindingRevision. A fault-abort Finding uses the stable key above, with exact fault/abort/START evidence and limitation “fault observed; component cause and unmet demand unknown.” A completed late END supersedes prior INCOMPLETE by new revision; a contradictory terminal withdraws previous current conclusion. Worker enqueue on **every** newly accepted relevant EV report, including late source time; until latest applicable job settles, previous projection reads `PENDING_RECOMPUTE`, with historical exact revision separately selectable. For current status, latest needed connector state <=2 minutes old at read time and terminal/event sources within declared cadence; old closed sessions may remain historical conclusions. Current service-window coverage uses one-minute status slots and explicit `known_seconds/unknown_seconds`; no available-time inference over gaps >2 minutes. Source gate follows S4-05 exact revision provenance; generated and authored evidence are labelled and mixed/unknown blocks a current positive (`.ai/DECISIONS.md:5-15,4165-4188`).

## 5. W2-07 tariff scenario and claim gate

`ev_gross_tariff_per_kwh` is a Site time-valid, recorded revision in `currency/kWh`, with authored basis/source; no default and no billing/collection identity. A window may price only supported energy in completed or observed-abort sessions, each with complete meter coverage and settled current assessment; no session interval is counted twice. For every included meter interval, select exactly one tariff revision whose **valid** range covers it and whose **recorded** range is visible at `known_at`; W2 v1 requires the same revision and currency across the entire priced window, otherwise `UNPRICED/PRICE_GAP_OR_CHANGE` (no averaging). Formula `amount = Σ exact interval kWh × tariff value`, unrounded in storage; display rounding only. `quantity_kwh` and exact session revision/accepted meter evidence/tariff revision IDs are pinned. No lost-sales estimate: private requested power, incomplete sessions and fault downtime do not measure counterfactual demand. An aborted session can contribute **delivered** pre-abort energy, never lost energy. W1 LR current-money gate and S4-05 coherent source gate apply: pending/late/revised assessment, conflicting meter, historical cutoff, mixed/unknown provenance, unsupported tariff, or missing price → `WITHHELD` or `UNPRICED`, null amount (not zero). Historical amount may appear labelled historical only under its exact old basis, never as today's current money. `overlap_group=site/window/tariff` prevents adding the same meter intervals through multiple Findings; Site scenario is one window revision, not per-Finding additive totals (`backend/migrations/versions/0010_financial_assumptions.py:38-102`; `.ai/DECISIONS.md:5-15`).
