## New model and computation

Create `mini_depth/` pure `rules.py`, `inputs.py`, `projection.py`, Postgres `store.py`, `read.py`, `composition.py`, and `mini_depth_api.py`. Analytic IDs `mini-renewable/1`, `mini-service/1`, `mini-fuel/1`, `mini-backup/1` are separate from Dispatch and W1 consequences. Every persisted revision has one Site/window, exact selected accepted IDs, pinned Foundation/binding revisions, model version and immutable JSON result. A worker may reuse an identical input digest; append a selection event on reuse. A new accepted late row or changed binding produces a new basis and cannot silently rewrite the old revision. UI read does not compute or persist new claims.

| Domain | Positive rule | Hard limitation |
| --- | --- | --- |
| Renewable | Capability bound is an authored, in-force Foundation property with unit and uncertainty; observed PV and addressed load require matching accepted interval means over the entire candidate hour. Retained margin is a separately authored positive bound. Headroom lower/upper = capability lower/upper − observed use − margin, floored at zero only after every term is supported. Eligibility requires observed storage charge acceptance/obligation and no unresolved critical-service deficit for the *same* hour. Daily numerator counts a day only when the designated hour meets all checks; denominator is all selected, completely assessed days. | A missing capability, charge obligation, critical requested-service baseline or a gap means LIMITED/UNKNOWN, never an eligible zero. No revenue or customer demand claim; the 10 kW grain mill example is illustrative only. |
| Service | Sum delivered power only from distinct addressed feeder assets with aligned intervals and known unit; display each role and measured span. A request/availability denominator is a separate accepted source or explicitly labelled authored model, tied to the load and interval. | Without complete requested evidence, `service_state=UNKNOWN`, `unserved_kwh=null`, and no 100% service chip. Missing 40 minutes between instantaneous samples remains a gap. A meter proves delivered power only. |
| Fuel | Expected use is a bounded dispatch-derived generator output × in-force specific fuel consumption, with exact window and model revision; *inventory* residual needs bounded opening, complete deliveries with explicit completeness attestation, bounded consumption and closing. Residual interval is opening + deliveries − consumption − closing using outward interval arithmetic. | `OperationalRecord` in W4-01 does not by itself certify all deliveries. Unattested delivery completeness or no closing reading => `residual=null`. Do not label theft, cost or dispatch saving. No automatic addition to W1 consequence. |
| Backup | Chain is correlated accepted supply-loss, start request/result, generator state, power-path, critical load response and requested-service recovery observations, strictly time ordered in one bounded outage. Outcome is PASS only with witnessed complete chain and declared recovery target; FAIL only with witnessed missed target; otherwise UNKNOWN/INCOMPLETE. | No outage is `NO_EVENT`, not start success. Generator operation alone is `OPERATING_ONLY`. No automatic readiness claim from a single successful episode; witnessed test history is a separate accepted authored record, absent => null. |

For any duplicate, overlapping incompatible, non-GOOD or mixed-class required input, record a typed limitation and exclude the affected candidate; do not choose a favourable row. Source IDs/citations are the full selected set, including limiting rows. Each row has `coverage:{required_seconds,observed_seconds,source_count,gaps[]}`. For instant reports, observed_seconds is zero unless a reviewed continuity rule expressly bounds it; do not interpolate by default. Amount, percentage, successful test and residual fields are nullable, never zero substitutes.

## Wire, order and refusals

`GET /api/sites/{site_code}/performance/mini/{domain}?from=<UTC>&to=<UTC>&known_at=<UTC>` with `domain` in `renewable|service|fuel|backup`. `from<to`; ordinary service/fuel/backup read is one Site local day or one exact hour; renewable accepts 1–5 complete Site local days, each separately selected. Default is the selected Site day from the shell, with `known_at` fixed at request start; explicit cutoff must not exceed request time. Page route `/sites/{site_code}/performance/{domain}?from=...&to=...&known_at=...`. Sorting: daily rows `(local_day ASC,window_start ASC,id ASC)`; load rows `(critical DESC,asset_code ASC,asset_id ASC)`; fuel bridge fixed term order `OPENING,DELIVERIES,USE,CLOSING,RESIDUAL`; backup chains `(outage_start ASC,chain_id ASC)` and steps `LOSS,REQUEST,START,POWER,LOAD,SERVICE`. No client-supplied tenant ID.

```json
{"schema_version":"mini-depth-1","domain":"service","site":{"id":"<site-uuid>","code":"KOBO-001","timezone":"Africa/Nairobi"},"window":{"from":"2026-10-06T11:00:00Z","to":"2026-10-06T12:00:00Z","known_at":"2026-10-07T00:00:00Z","bounds":"[from,to)"},"currentness":{"state":"CURRENT","selection_id":"<selection-uuid>","assessment_revision_id":"<revision-uuid>","input_sha256":"sha256:<64-hex>","committed_watermark":"2026-10-06T12:00:00Z","job_state":"SETTLED"},"source_provenance":{"classification":"REGISTERED_SIMULATION","state":"REGISTERED_SIMULATION","source_ids":["<source-uuid>"],"evidence_ids":["<accepted-uuid>"],"basis_sha256":"sha256:<64-hex>","reasons":[]},"status":"UNKNOWN","coverage":{"required_seconds":3600,"observed_seconds":1200,"source_count":3,"gaps":[{"from":"2026-10-06T11:20:00Z","to":"2026-10-06T12:00:00Z"}]},"cards":{"delivered_load_kw":null,"interruptions_seen":null,"critical_delivered_kw":null,"unserved_kwh":null},"rows":[],"limitations":[{"code":"REQUEST_BASELINE_MISSING","evidence_ids":[]}],"links":{"dispatch":"/sites/KOBO-001/performance/dispatch","evidence":"/sites/KOBO-001/evidence","financials":null,"actions":null}}
```

Each domain uses this envelope; `cards` and `rows` have domain-specific stable keys. Renewable cards: `capability_kw:{low,high}`, `used_kw`, `headroom_kw:{low,high}`, `eligible_days`, `assessed_days`; rows: `day,from,to,opportunity_kwh:{low,high}|null,constraints[],decision,evidence_ids`. Service rows: `asset_id,asset_code,load_label,role,delivered_kw,requested_evidence_state,assessment,coverage,evidence_ids`. Fuel cards: `opening_l,deliveries_l,expected_use_l:{low,high},closing_l,residual_l:{low,high}`; rows: `term,basis,treatment,value,evidence_ids`. Backup cards: `outage_count,start_success_count,last_witnessed_test_at,critical_recovery`; rows: `chain_id,outage_start,steps[],service_outcome,result,evidence_ids`. Each absent value is JSON null; `rows` may be empty. All `source_provenance` blocks use W3-01 q1–q4 exact six-key DTO and selected set, even when status is UNKNOWN. No new `known_at` DB column or nullable Action owner is assumed.

Total status precedence (top to bottom, first match): store error => HTTP 503; no authorized Site => 403/404; no selected revision => UNKNOWN; overlapping pending/leased/failed job or changed watermark => PENDING_RECOMPUTE/STALE_SOURCE; explicit past cutoff => HISTORICAL; provenance UNKNOWN/MIXED => LIMITED; required-role conflict/coverage gap => LIMITED; complete domain rule => SUPPORTED; otherwise UNKNOWN. Preserve `currentness.state` separately from `status`. Row decision precedence: contradictory => CONFLICT; missing role or request => LIMITED; all required present and positive => ELIGIBLE/PASS; all required present and contraindicated => EXCLUDED/FAIL; no event => NO_EVENT. For service row, complete measured delivery with no request remains UNKNOWN. Fuel residual only SUPPORTED if all five terms and completeness attestation pass. `NULL` never participates as zero.

Use `{"detail":{"code":"...","message":"..."}}`: 401 `AUTHENTICATION_REQUIRED` plus Bearer header; 403 `SITE_SCOPE_FORBIDDEN` for known Site outside grant; 404 `SITE_NOT_FOUND` for unknown/foreign Site; 422 `INVALID_WINDOW` or `INVALID_CUTOFF`; 503 `MINI_DEPTH_STORE_UNAVAILABLE` for DB or required lineage failure. Check auth/scope before parsing and DB reads, then time validation. A missing assessment is a successful UNKNOWN envelope. Do not turn a query or provenance failure into an empty set. A known Site without configured mini-grid role returns UNKNOWN with `SITE_ROLE_UNSUPPORTED`, never a 404. On 503 render `Mini-grid evidence is unavailable right now. Try again.`; on 403 `You do not have access to this site.`; on 404 `This site could not be found.`; no foreign Site details in any body.

CREATE TABLE mini_depth_revision (
  id uuid PRIMARY KEY, tenant_id uuid NOT NULL, site_id uuid NOT NULL,

  model_version text NOT NULL, window_start timestamptz NOT NULL,

  CONSTRAINT mini_depth_basis_uq UNIQUE (tenant_id,site_id,domain,model_version,window_start,window_end,input_sha256)

CREATE TABLE mini_depth_revision_evidence (
  tenant_id uuid NOT NULL, site_id uuid NOT NULL, revision_id uuid NOT NULL,
  evidence_id uuid NOT NULL, PRIMARY KEY (revision_id,evidence_id),
  FOREIGN KEY (tenant_id,site_id,revision_id) REFERENCES mini_depth_revision(tenant_id,site_id,id),
  FOREIGN KEY (tenant_id,site_id,evidence_id) REFERENCES accepted_evidence(tenant_id,site_id,id)

CREATE TABLE mini_depth_selection (
  seq bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,

  CONSTRAINT mini_depth_selection_window CHECK (window_start < window_end),
  CONSTRAINT mini_depth_selection_domain CHECK (domain IN ('renewable','service','fuel','backup'))

CREATE INDEX mini_depth_selection_head ON mini_depth_selection
  (tenant_id,site_id,domain,window_start,window_end,seq DESC);
CREATE INDEX mini_depth_revision_evidence_lookup ON mini_depth_revision_evidence

  FOR EACH ROW EXECUTE FUNCTION ledger_append_only();
