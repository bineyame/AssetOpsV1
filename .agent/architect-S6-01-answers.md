# Architect rulings - S6-01a/S6-01b

Decision: `D-2026-10-15-s601-action-store-and-ui`. Authority: `.agent/architect-S6-01-request.md`, the owner's 2026-10-15 delegation, `D-2026-10-14-action-lifecycle-and-policy-application`, and `.agent/A-action-lifecycle-review.md`. These rulings refine the packets; they do not claim a measured effect or waive the S6-01b owner checkpoint.

1. **Q1 - amend.** Use versioned server rule `reserve-trial-1`, a policy-sensitivity trial only. It is eligible only for a reviewed, `SUPPORTED`, current `GENERATOR_SUPPORT_CANDIDATE` FindingRevision whose pinned assessment has at least one cited Candidate segment with a usable numeric battery-SOC reading in that segment's accepted analytic input, strictly above the pinned effective reserve plus the dispatch model's 10-point headroom, and whose cited Foundation has one unambiguous battery reserve in percent. Require the same battery asset and a current Site Foundation reserve equal to that pinned reserve; otherwise return a typed unavailable reason (including stale basis). For an eligible reserve `r` in [15, 90], propose exactly `r - 5` percentage points, which remains in [10, 85]. Values outside that band, missing or conflicting numeric inputs, non-current/unsupported revisions, and an unchanged result are unavailable. Pin input IDs, rule version, old/proposed values and the limitation. This is an experimental control change, not a diagnosis that reserve caused the Finding or a prediction of lower generator runtime, savings or safety. Never use the mock's generator-stop narrative as a reserve rule. **Packet change:** S6-01a must spell out this rule, typed unavailable reasons, exact numeric source and boundary tests; its stored fixture must contain a genuinely eligible pinned Candidate and an ineligible/missing case. S6-01b must display the trial limitation and unavailability reason.

2. **Q2 - accept with transaction detail.** Extend only the existing Site-locked S1 publish callback. Acquire the Action lock before the Site lock, compare the expected current covering Foundation ID under that Site lock, and persist Foundation/SPLIT/binding rows, change artifact and APPLIED event in one transaction. Return the prior artifact for an identical applied retry before the no-change check. A failed transaction cannot leave APPLIED or an effective artifact. After rollback, append a separate same-Site FAILED attempt with the expected/current IDs for a stale authorized command. **Packet change:** S6-01a must state the callback result carries every written/superseded ID and test rollback and concurrent apply with this lock order.

3. **Q3 - accept.** Unknown or wrong-Site Action, Finding, revision or change IDs return 404 without an event. Missing authentication returns 401; denied command authority returns 403 without an Action attempt. Append FAILED only after an authorized same-Site Action application reaches domain validation or publish and fails; it never asserts an effective change. **Packet change:** S6-01a must distinguish these cases in its command table and fixture/API tests; remove wrong-Site from the list of persisted FAILED cases.

4. **Q4 - accept with exposure guard.** Show accept/apply controls only when the server returns a tenant/Site-scoped, server-authorized SYSTEM demonstration capability for that exact command and fixture. Label the control and resulting actor/provenance as SYSTEM demonstration. Otherwise render a read-only unavailable reason; a client flag cannot enable the command. No operator approval wording. **Packet change:** S6-01b must name the capability field, its read-only state and tests for absent/denied capability at both 1440 and 390; S6-01a must supply the scoped capability in its read contract and enforce it again on POST.

5. **Q5 - accept.** `event_id` selects an exact event; `recorded_at` selects all events through the server-recorded instant using `(recorded_at,id)` order. Neither means a client-time or `occurred_at` cutoff. Reject both selectors together with typed 422 on Action and event reads; keep the selected selector in child links and reload. **Packet change:** S6-01a must define the selector/error wire contract and tie tests; S6-01b must test URL selection, navigation and reload for each selector and the conflict state.
