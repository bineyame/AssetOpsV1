### S2-02

- **Carry, Evidence NO_DATA wording (earlier F3).** `frontend/src/sites/LedgerSiteEvidence.tsx:223` says no readings were received for a selected period even when the gateway reports a queue or its contact is STALE/UNKNOWN. It is literally a server-receipt statement, but does not help the reader understand that readings may still arrive. The gateway queue cannot be assigned safely to a source-time window, so qualify the headline using Site-level gateway status without inventing a window-level pending count.
- **Carry, backlogged diagnostics can look current.** `backend/assetops_backend/evidence/adapters/postgres_gateway_access.py:172` selects the last *received* diagnostic, and `gateway_access.py` computes CURRENT from that receive time. A delayed old report delivered after an outage can show old queue/pressure/offset facts beside CURRENT. `gateway_observed_at` is disclosed, and CURRENT correctly means server contact, so this is a presentation risk rather than a freshness-contract violation. Before S7 health uses these fields, separate contact freshness from the age of the reported facts.
- **Carry, Evidence read scale.** `postgres_evidence_ledger.py` loads all Site rejections and referenced full batch texts for a selected-window read, then filters in Python. This is bounded by the present demo Site but grows with Site history. Add a source-time placement/index or bounded query before a long-running Site or pilot volume relies on this read.
- **Carry, request body limit.** `gateway_api.py` and `evidence_api.py` reject a declared oversized `Content-Length`, but a chunked authenticated request is fully read before the size check. The credential boundary limits who can trigger this; enforce a streaming byte cap before broader exposure.
- **Carry, restart loses a non-gap refusal note.** `host/lab_execution.py:2886` derives `PUBLICATION_REFUSED` from in-memory `session.staging_notes`; after restart the persisted schedule still blocks known gaps, but a different refusal note is lost. The gateway delivery and schedule checks still protect the recorded terminal-gap case. Persist a refusal reason if a non-gap refusal must survive restart as part of the release claim.
- **Carry, credential outcome questions Q37/Q38.** `.agent/S2-02-questions-7.md` documents that “halt rotation” after an unknown COMMIT is an operator instruction, and that a fresh no-selector read is treated as proof of non-commit. Both are bounded pilot decisions awaiting Architect ruling. The current code keeps a possibly committed secret on unreadable/ambiguous state and does not silently reissue it; this review does not classify the open policy choice as an implementation block.
- **Carry, owner proof limits.** The walkthrough shows a live labelled valid/rejected sibling and a recorded UNKNOWN → CURRENT → STALE → CURRENT contact sequence. Crash/resume 202 and closing-boundary rejection remain Postgres test evidence, explicitly labelled in the walkthrough under the Architect's Q32 ruling. KOBO-001 cutover is an empty-set comparison, not replay parity. The fault fixture's valid sibling is accepted into the isolated demo database and must not be treated as ordinary gateway output or S3 input.
