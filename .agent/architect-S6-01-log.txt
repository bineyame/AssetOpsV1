Ingestion checks that the **referenced registered versions' original valid ranges** cover each envelope's source time, even if a later configuration correction superseded them while the gateway was offline. It records the accepted-as basis and flags an outdated mapping/configuration; it rejects unregistered versions or times outside the referenced range. Analytics at a later `knowledge_at` may rebind and renormalize the immutable original reading under a corrected time-valid version, recording those new revision IDs in its input set. This never edits accepted evidence. A record dated before any configured period is rejected with a specific reason; it is not assigned current configuration.

frontend/docs/architecture/production-shaped-mvp-technical-design.md-74-## 2. Edge SQLite schema
frontend/docs/architecture/production-shaped-mvp-technical-design.md-75-
frontend/docs/architecture/production-shaped-mvp-technical-design.md-76-Use `PRAGMA journal_mode=WAL`, `foreign_keys=ON`, `busy_timeout`, one writer, and a migration table. SQLite is an acquisition ledger, not a product database. Store UTC instants as ISO text. A source stream means `(gateway_id,source_id)`; `sequence_epoch` changes only on explicit reprovisioning, preventing accidental sequence reuse after restore. Local primary keys can be text UUIDs. Example values below correspond to the central examples.
--
frontend/docs/architecture/production-shaped-mvp-technical-design.md-177-1. **Register configuration.** Publish Foundation and SignalBinding versions together under Site lock. Validate site type, role vocabulary, units, asset ownership and non-overlapping current valid periods. Persist canonical snapshot hash for authenticated gateway download; no detached snapshot signature or key-rotation system is required in S1–S7. Backdated publication enqueues affected windows for recomputation; do not change accepted evidence bytes.
frontend/docs/architecture/production-shaped-mvp-technical-design.md-178-2. **Receive batch.** TLS and gateway credential establish tenant/site/gateway/source. Enforce size/count limits before parsing; resolve external batch ID and digest. Identical retry returns stored receipt; conflicting retry records/refuses without touching prior decisions. A batch with wrong registered mode or configuration reference is refused as a whole.
frontend/docs/architecture/production-shaped-mvp-technical-design.md-179-3. **Decide records.** In one Postgres transaction, lock batch row; for each unprocessed ordinal parse strict envelope, verify identity/sequence and referenced mapping/Foundation validity at `source_time`, normalize with the registered as-accepted conversion, and insert acceptance or rejection plus disposition. Unique message key arbitrates concurrent duplicate deliveries. Equal digest is `DUPLICATE`; changed digest is `CONFLICT` and points to first accepted evidence. Update watermark and create/coalesce recompute jobs in the same commit. Chunk a large batch into short committed transactions; receipt exposes `IN_PROGRESS` until all ordinals are durable. A client retries the same batch/bytes and resumes from the persisted watermark. Return a terminal receipt only after all decisions commit.
frontend/docs/architecture/production-shaped-mvp-technical-design.md-180-4. **Assess.** Worker leases dirty site/domain/window jobs, selects accepted evidence by source time plus interval overlap at a declared knowledge cutoff, resolves the exact public configuration, builds `AnalyticInputSet`, and runs the versioned pure analytic. In one commit insert `AnalyticRun`, immutable assessment/finding/consequence revisions when basis changed, update projections and mark job done. Retry of same input hash is a no-op. Late or out-of-order evidence recomputes the affected and neighboring continuity window; it never mutates old revisions. Model deployment schedules explicit re-evaluation of supported windows.
frontend/docs/architecture/production-shaped-mvp-technical-design.md-181-5. **Verify.** ActionEvent records work. After a later closed window exists, evaluate the frozen plan against accepted evidence, target and each guardrail. Missing coverage is `INCONCLUSIVE`; worsening service prevents `VERIFIED` even if cost falls. Link outcome to exact analytic run/evidence and surface any later superseding outcome.
