# S2-02 questions 6 (phase 3c) - fail-closed defaults applied; batch to the Architect

Each question names the default the slice already ships. None blocks owner review.

- **Q32 - which owner-review demonstrations are live and which are test-only.** A sealing gateway never produces a same-ID/changed-bytes upload, a rejected sibling ordinal, or a 202 partial crash/resume (the live composition builds `BatchIngestionService` with defaults; no env knob). The walkthrough script hand-crafts the changed-bytes POST with the gateway's real credential (live 409) and leaves rejected-sibling and crash/resume to the Postgres tests (`test_s2_evidence_ledger_postgres.py::test_a_rejected_sibling_does_not_erase_valid_decisions`, `::test_a_crash_after_a_committed_chunk_resumes_from_the_watermark`, `::test_a_bounded_request_returns_202_in_progress_until_terminal`). Default: the packet and walkthrough label those three as test evidence, not live. Alternative: a test-only composition flag for crash/202 on the demo server (adds a product knob; not taken).
- **Q33 - rotation needs a gateway restart.** The gateway reads `upload.upload_credential_file` from its config at start; after Q16 the new credential is a new versioned path, so switching it is a config edit plus a restart (sealed bytes and SQLite ledger persist; no reseal). Default: restart, documented in the walkthrough. Alternative: a local IPC op to repoint the file (new privileged op; not taken).
- **Q34 - demo isolation by a copied tree.** Every store path is fixed to the module location (`parents[4]/var/...`), and comparison reports are environment-bound with newest-wins, so a demo against another database in the shared `var/` would close the developer KOBO-001 gate. Default: `tools/s2_demo_walkthrough.py` runs a `git archive` copy of HEAD with its own `var/` and database `assetops_s2demo`. Alternative: one configurable var root (a product setting; not taken).
- **Q35 - two Lab runs' readings side by side in Site Evidence.** The main run and the terminal-gap run both cover 2026-09-30 03:00-15:00 virtual on the same sources; each run's gateway sequence gives distinct message IDs, so both are ACCEPTED (not DUPLICATE/CONFLICT) and the Site window holds two readings per source/time. Default: accepted as source-level Evidence (the ledger is not run-scoped; this is the live "two distinct same-timestamp sequences" case); the walkthrough says so. Alternative: one run per demo database.
- **Q36 - the closing-boundary reading's outcome.** With the converted KOBO-001 bindings (no period ending at 15:00) the post-run 15:00:00Z readings were ACCEPTED centrally after the virtual clock released them. The `OUTSIDE_FOUNDATION_PERIOD` rejection remains proven only by `test_s2_evidence_ledger_postgres.py::test_a_closing_boundary_reading_is_outside_its_half_open_period`. Default: report both, claim no live rejection.
