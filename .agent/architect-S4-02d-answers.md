# Architect answers: S4-02d schedule storage and guard (2026-10-14)

**Ruling: ratify with the boundaries below.** The plan fix round 1 proposes one durable owner of environment and Site scheduling state. Migration 0013 may add `schedule_tick_head`, `schedule_site_head`, `schedule_cursor`, and `schedule_enrolment`. `backend/assetops_backend/scheduling/adapters/postgres_schedule_store.py` is the eighth PostgreSQL writer and the sole runtime writer of those four tables. This state is neither an accepted-evidence record, an S3 analytic result, a Finding, nor a financial consequence. Putting claims, heartbeat, enrolment, and fairness cursor into an existing domain adapter would give that adapter unrelated write authority and obscure restart and cross-host behavior. Site inventory may be read through the Site port; Site-scoped S3 leasing and job updates stay in the existing assessment writer. Consequence claims, attempts, and revisions stay in the consequence writer and its existing triggers.

## Rule 8 amendment allowed

Amend `tools/checks/configuration-persistence.ps1` for **that exact schedule adapter path** and **those four tables only**. Add the adapter to the PostgreSQL writer allowlist and the non-vacuity checks (an observed SQL write and driver import). Permit `INSERT` to the four schedule tables and `UPDATE` of their mutable schedule state: environment tick claim/lease, start/success/failure, heartbeat and retry due in `schedule_tick_head`; Site claim/lease, stage, selected/processed/deferred counts and last failure in `schedule_site_head`; fair position in `schedule_cursor`; explicit enrolment state in `schedule_enrolment`. The implementation should name the actual allowed columns in the guard, then test that unlisted columns and tables fail. Claims and deadlines use database time. The migration owns DDL; it is not an extra runtime writer.

Keep the guard's reverse ownership checks: no other runtime module may write any of these four tables, and the schedule adapter may write no other product table. In particular, it may not write `recompute_job`, `analytic_run_selection`, Finding tables, consequence revisions/attempts/work, accepted evidence, Foundation Site rows, or financial assumptions. Do not use a wildcard SQL or driver exception, permit `DELETE`/`TRUNCATE`/runtime DDL, or weaken the existing seven writer checks. If a schedule domain composition imports this adapter, register that domain in the guard's adapter-isolation list as well; callers receive its port, not the adapter. A migration trigger, if proposed later, requires separate review rather than silently widening this ruling.
