## Frozen contract, migration and wire

The W4 `work/` model and `work_api.py` own the Incident/WR identities and Site list wire; W1 `SiteWorkActions.tsx`, `SiteAction.tsx` and `SiteAnalyticsFrames.tsx` provide the Action presentation and route; the W1 database Action is reserve-trial-only. W5-02 adds a separate persisted `domain_action` under the same public code/route namespace and an explicit W4 case link. W6 owns global Work roots, request detail and rail. W5-03 supplies selected EV session/availability/health and exact EV Finding revision. The W2 SES-011 fault and SES-012 missing end are observations, not automatically created cases or proof of hardware failure. Use W5-02's `domain_action` root, `domain_action_intent` declaration and `domain-action-intent-read-1` read; never route EV through battery-only `verification_plan`.

**V1 migration.** `backend/migrations/versions/0035_w5_ev_work.py` has `revision='0035_w5_ev_work'`, `down_revision='0034_w5_ev_scenarios'` and exactly one parent/head. Alter `domain_action`'s domain CHECK from `COLDCHAIN` to `COLDCHAIN|EV_CHARGING` and the intent's criterion-length DB check from exactly four to either three or four; the service enforces four for COLDCHAIN and three for EV_CHARGING after resolving the Action FK; maintain the existing FKs, append-only triggers, root/supersession and unique idempotency constraints. Add an index `(domain,site_id,recorded_at,id)` for selected EV reads. Downgrade refuses while EV Action, intent or case-link rows exist, then restores the cold-only check. This uses reserved `0035` without duplicating Work identities. The 0033 Action root, intent and case-link schema are explicit prerequisites, not recreated. Rule-8 writer remains the W5-02 adapter, now with an EV typed validator.

**Command/read.** The K1 `POST /api/sites/{site_code}/domain-work/actions` accepts `domain:'EV_CHARGING'` after V1 and creates an EV Action root from an exact selected EV Finding. Its closed body and 201/200 identical retry response are W5-02's, with EV domain and EV title/owner. The same intent and case-link routes and the `site-domain-action-index-1` union index work for EV; a case link remains optional for the mock-zero state. `GET /api/sites/{site_code}/domain-work/actions/{action_id}?known_at=` returns the `domain-action-intent-read-1` envelope with stored Action fields and null semantics. The service checks selected Action/Finding/Site/tenant, W5-03 EV sessions and declaration basis on one caller-connection repeatable-read transaction. EV intent `basis` keys are `{finding_revision_id,work_case_id:null|string,work_record_id:null|string,accepted_evidence_ids:string[],session_ids:string[]}`; every session ID must be a public selected W2/W5-03 session at the cutoff, not Lab truth. No Incident or WR is required for this mock's successful zero. Current `results` are `PENDING` for all three criteria. A future evaluator may support a result only in a reviewed later slice; V1 does not infer verified/no-recurrence from a completion, reset, schedule or low observed peak power.

Refusal order and statuses remain W5-02's. EV-specific new literal messages: 422 `DOMAIN_INTENT_INVALID`: `The EV Action declaration is incomplete or invalid.`; 422 `DOMAIN_INTENT_LINK_INVALID`: `The declared Finding or session is not selected at this site and cutoff.`; 409 `DOMAIN_INTENT_CONFLICT`: `This Action declaration has a newer version; reload it.`; 409 `DOMAIN_INTENT_BASIS_CHANGED`: `The selected EV work basis changed; reload the Action.`. Use W4's existing 401/403/404/503 and `INVALID_KNOWN_AT` messages. Refused payload has `intent:null,results:null`, never a successful zero. Missing declaration is successful `intent:null` with `No verification criteria have been declared for this Action.`

The only accepted EV criteria, in order, are `WITNESSED_SESSION` / `Complete a witnessed charging session` / `Session start, end, outcome and meter delta`; `NO_FAULT_RECURRENCE` / `No fault recurrence during observation` / `Connector diagnostic events with full coverage`; `NO_SERVICE_REDUCTION` / `No reduction in service availability` / `Comparable status coverage / operational window`. V1 validates exactly these key/label/evidence triples. `session_ids` identify public selected sessions; they are source references, not current-result proofs. To change the declared rule, append a superseding intent. At historical cutoff read the selected old intent and old session/Finding basis, never the newest head.
