## Snapshot, selection and comparison rule

`GET /api/estate/portfolio?from=&to=&known_at=&lens=all&limit=50&cursor=`. Principal-derived tenant and authorized imported Site set only; no client Site/tenant override. Auth/access/source disclosure precede value parsing. Shared W3-01 parser requires whole UTC days, `[from,to)` no longer than 31 days, `known_at` UTC no later than captured DB time, `limit` ASCII integer 1..100, default 50. First page defaults to the last seven **complete** UTC days; UI omits `known_at` until explicitly selected. Read one read-only `REPEATABLE READ` snapshot: grant, every Site selection and watermark, full Finding/Action heads, Evidence capability and gaps, Financial lines/groups/exclusions/diagnostics, and exact cited accepted IDs. Call connection-taking selectors on that connection. Sort/dedupe IDs before selection token; W3-01's canonical `estate-selection/2` includes the four assessment/consequence/assumption/citation arrays for **every** Site item, including empty `[]`, plus Finding/Action arrays. `access_basis` remains `estate-access/1`; a cursor from `/1` or changed grant/selection yields 409. Do not build a Portfolio-only token from visible page rows. The Portfolio token is kind `portfolio`, lens-bound, and has one full-scope snapshot; its default lens is `all`.

Coverage is per authorized Site/domain and independently per Finding, Evidence and Financials. Use the three roots' selected read states and original per-Site watermarks; `covered_site_count` is never a sum of page rows. Complete estate means **all applicable** authorized Sites have selected, settled, non-stale records for the selected window and no impossible source/lineage. Historical cutoff is labelled historical even if the pinned state was complete then. When domain applicability is not established by Site configuration, use UNKNOWN, not N/A. A missing imported Site remains in scope with null selection; a foreign Site never appears. `status` precedence: `EMPTY_SCOPE` if zero authorized Sites; `HISTORICAL` for an explicit old cutoff; `PENDING` if any applicable selection has unsettled work; `PARTIAL` for missing, stale or conflicting coverage; otherwise `CURRENT`. Keep the three domain coverage blocks even when the overall status is one word.

No composite health score or numeric combined measure exists. In particular W3-02 `summary.estate_total` stays null even if one `groups[].state=COMPARABLE`; it is prohibited to sum money categories, periods or currencies. Portfolio may display **one** comparable category group with its exact amount, currency, window, assumption fingerprint, line IDs and exclusions, or one Site-owned line labelled as such. A candidate line is current only under W3-02 closure-2 eligibility and closure-3 coverage precedence. Group precedence is `UNKNOWN_COVERAGE > INELIGIBLE > OVERLAPPING_BASIS > SINGLE_LINE > COMPARABLE`; zero heads uses its `NO_LINES` sentinel or `UNKNOWN_COVERAGE` as W3-02 closure 3 requires. No W3-03 override of the W3-02 comparison state. A Finding gets no money merely because a Site/domain line overlaps its window: W1 exact Finding-revision pin is required; cold remains unpriced; EV money's nullable, never-written Finding pin prohibits EV Finding cost attribution. Do not make a productive-use or battery condition assertion from W1 Evidence, W4-02 physical headroom or mock examples. The requested three-domain proof is an aligned-selection **coverage and display** proof: W1, cold and EV appear at the same requested window/cutoff with separate source types and consequence categories; a combined numeric measure is explicitly declined.

## Wire and deterministic order

Decimal numbers are JSON strings; no float or client arithmetic. `rows` are ranked Finding projections over the full selected W3-01 canonical Finding set, not W3-02 consequence lines. Rank order is persisted priority descending **only when a reviewed priority field exists**; in this slice it does not. Therefore order is `(episode_start desc nulls last, site_code_key asc, site_id asc, finding_id asc, finding_revision_id asc)`; do not claim consequence/urgency ranking. `lens=all|cost|risks|opportunities` uses W3-01's exact lens flags and matches corresponding root membership; no client predicate. Cursor `last` is the full tuple, signed with shared W3-01 cursor machinery, limit and selection token. Counts, cards, matrix and disclosures use full scope before paging. `next_cursor` null at end. `rows[].links` use reviewed route builders only.

## Refusals and visible states

Use W3-01/W3-02 frozen error codes/messages, not the conflicting early W3-02 draft table. Errors use `detail`, with `rows:null,total_count:null,value_cards:null,objectives:null,money:null` inside it, no success top-level fields. 401 has `WWW-Authenticate: Bearer`.

| HTTP/code | Literal message / behavior |
| --- | --- |
| 401 `UNAUTHENTICATED` | `Sign in to read estate records.` Clear prior data. |
| 403 on Portfolio root | Unreachable by contract: W3-01 authorized Site enumeration excludes inaccessible Sites; there is no separate source-disclosure permission. If a downstream Site route returns its existing `SITE_SCOPE_FORBIDDEN`, show `You do not have access to this site.` and clear the previous Site detail, without retaining a Portfolio-derived Site name. |
| 404 on Portfolio root | Unreachable by contract: there is no Site ID parameter. A downstream exact Site/detail route uses its existing `SITE_NOT_FOUND`/object-not-found code and copy; show `This site was not found.` and clear stale detail. An empty authorized estate remains 200. |
| 409 `ESTATE_BASIS_CHANGED` | `The estate selection or Site access changed; request page one without a cursor.` Reset cursor, request page one. |
| 409 `ESTATE_SELECTION_INCONSISTENT` | `The selected Site revisions cannot be read consistently.` No partial rows. |
| 422 `INVALID_WINDOW` | `from and to must be UTC instants in order, at most 31 days apart.` |
| 422 `INVALID_KNOWN_AT` | `known_at must be UTC and no later than the read time.` |
| 422 `INVALID_LIMIT` | `limit must be an integer from 1 to 100.` |
| 422 `INVALID_CURSOR` | `The cursor is not an estate cursor.` |
| 422 repeated/unknown keys | W3-02 final closure: missing/repeated `from` or `to` => `INVALID_WINDOW`; repeated/unknown other keys => `INVALID_CURSOR`, with the exact messages above. Reject before query. |
| 503 `ESTATE_STORE_UNAVAILABLE` | `Estate records could not be read.` No stale rows. |

No authorized Sites is 200 `EMPTY_SCOPE`, not 404; an authorized Site with no selected read is 200 PARTIAL, not 404. Loading shows named skeleton slots and no zero. Complete selection with zero rows says `No selected Findings for this window` and leaves all headers/cards/panels visible. Partial/pending show known selected rows with `Some Sites cannot be compared yet`, null full-estate counts and no numeric combined value. Historical values say `Historical as of {known_at}`; they do not present present-tense money or week-over-week change. Mixed/UNKNOWN source leaves exact IDs in restricted disclosure and `Value withheld`, never a zero. A route refusal removes cached privileged result. 503 retry does not silently reuse an older cutoff. Root API tests assert no 403/404 response; UI tests inject 403/404 from downstream Site/detail navigation and verify stale detail is cleared.
