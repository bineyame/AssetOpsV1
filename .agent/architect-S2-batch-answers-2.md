## S2-02 phase-1 questions-1

1. **Q1 — accept mutable gateway/source external IDs.** They are current display names; the pinned snapshot preserves published spelling, while immutable UUIDs and fixed tenant/Site/gateway affiliation establish lineage. Keep the asset-code and mode hardening already built, and do not resolve older evidence through today's renamed IDs.
2. **Q2 — choose (a), operator issue plus explicit source enablement.** Import deliberately leaves identities disabled and an upload cannot grant its own authority. The phase-2 `issue` command may enable the named registered sources with the gateway, but the file/ACL correction below must make failed issuance leave registration and any prior credential unchanged; never enable on first upload.
3. **Q3 — accept 403/no Site row for claim or mode mismatch.** A mismatched Site/gateway/mode or disabled/unaffiliated source fails the authenticated scope, not the content of a legitimate Site batch. Keep 422 with an authenticated `batch_refusal` for a bad configuration reference, and audit wrong-scope attempts only outside the Site evidence ledger.
4. **Q4 — accept whole-batch configuration-reference refusal.** Batch V2 is homogeneous in its Foundation/binding references, so an unregistered or mismatched shared reference invalidates the batch basis. Keep per-ordinal rejection for an individual envelope's source-time validity, unit, ENUM, conversion, schema or message conflict, preserving valid siblings.
5. **Q5 — accept the `dispatch` recompute domain.** S3-01's first worker consumes dispatch jobs; coalescing new accepted source/interval windows under the Site/domain lock prevents loss without requiring a generic fan-out service now. Duplicates and rejections create no new analytic input, and S3 may widen neighboring continuity windows or add later domains.
6. **Q6 — accept first batch server receipt as evidence `received_at`.** The server received the canonical batch once; resumed ordinal decisions have their own `decided_at`, so replacing receipt time with retry/decision time would distort lag and lineage. Keep the first receipt instant stable in Receipt V2 and accepted rows.
7. **Q7 — accept 413 for oversize.** Size is an HTTP payload limit distinct from a well-sized malformed 422. An authenticated request that reaches the service may leave an auditable refusal; pre-auth or edge-rejected bodies create no Site ledger row.

## S2-02 phase-2 questions-2

8. **Q8 — accept immediate revocation only after protected issuance is durable.** No overlap is a sound pilot rule, but current `issue` commits the new verifier/revokes the old one before writing the secret file, so a Windows ACL or file failure can strand the gateway. Correct this before the owner walkthrough: write to a new versioned protected path, verify effective file permissions including Windows ACL, then atomically commit verifier, old revocation and named identity enablement; failure before commit leaves the old secret usable and identities unchanged. Never overwrite the old usable secret as a preparation step; prove failed file/ACL issuance and successful rotation without resealing.
9. **Q9 — accept `CURRENT` through 2× registered cadence.** Slot-edge timing can put valid consecutive receipts almost two cadences apart. Use server `received_at` and the registered cadence; before any report show `UNKNOWN`, after the threshold show `STALE`, and never infer device health.
10. **Q10 — accept direct TLS only for the pilot.** The ASGI HTTPS scheme is an enforceable boundary for this deployment, while a forwarded-proto header needs explicit trusted-proxy configuration that is not in scope. Keep plaintext credentialed uploads at 426 and do not let an arbitrary `X-Forwarded-Proto` bypass it; the owner demo uses a separately generated local TLS key, not the checked-in test fixture.
11. **Q11 — accept diagnostic refusal shape.** Malformed bytes and same-identity changed bytes belong to authenticated 422/409 audit rows; a wrong path, claim or foreign source has no Site authority and leaves no Site ledger row. Keep diagnostic upload refusal distinct from accepted health and make the local/central UI show it as a delivery limit rather than a healthy or empty state.
12. **Q12 — accept demo-tenant-only CLI with a provenance label.** Until there is a tenant operator model, OS username is local machine context, not authenticated tenant authorship. Keep the CLI restricted to the configured development tenant and label audit/readback accordingly; a real-pilot/multi-tenant provisioner needs authenticated operator identity.
