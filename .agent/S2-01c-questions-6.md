# S2-01c questions 6 (fix round 2)

Raised while building `D-2026-10-09-s2-publication-gap-and-batch-boundary` (R1, questions-5 Q2/Q3/Q5). Each is built with the fail-closed default named; none blocks re-review.

**Q1. Schedules written before the boundary count.** The gap check needs to know whether the world has reached any boundary, because after `start` and before the first step `world_reached_instant` is the interval start and `admitted_through` is empty, which is not a gap. Fix round 2 persists `world_boundaries_completed`. A schedule written by earlier branch code has no count, so it is judged by the two instants alone. A run that was only started under that code reads `INCOMPLETE`, and a stored-only advance on it refuses `PUBLICATION_GAP`. *Default built:* fail closed with no migration. These are branch-only Lab files, nothing on `main` writes them, and the recovery is a new run.

**Q2. A live session on a terminal gap.** The ruling keeps `PUBLICATION_INSTANT_PASSED` while a live session is present. As built, that advance still writes the Lab clock forward before the gateway refuses the first missing boundary. The answer is a 200 with `publication_refused` naming `PUBLICATION_INSTANT_PASSED`, the schedule reads `TERMINAL_GAP`, and the UI shows the gap paragraph. No envelope, batch or delayed report crosses the gap, and the test asserts this. *Default built:* as ruled. The alternative is to preflight-refuse `PUBLICATION_GAP` for `TERMINAL_GAP` even with a session, so that neither clock moves. That is stricter, and it is the Architect's call.

**Q3. No schedule written on the first start.** Q5 allows a schedule to be created only on the first start, before the execution artifact exists. If that first pass writes nothing (`REPORT_NOT_ADAPTABLE`, or an unreadable schedule), every later step notes `PUBLICATION_SCHEDULE_MISSING`. The read and the advance also say `SCHEDULE_MISSING`, so the run must be replaced. *Default built:* fail closed, because a step never creates a schedule after execution has begun.

**Q4. Where the two instants go on the refusal.** `PUBLICATION_GAP` names the `admitted_through` instant and the world-reached instant (plus `ordinary_stopped_at` when terminal) in the 409 message, as other refusals do with their detail. The structured values are in the schedule read (`admitted_through`, `world_reached_instant`, `ordinary_publication`, `ordinary_stopped_at`), which the panel re-reads and shows. *Default built:* no new structured fields on the shared 409 body.

**Q5. Which refusal makes a gap terminal.** `ordinary_stopped_at` is recorded only when the gateway refuses an ordinary boundary group with `PUBLICATION_INSTANT_PASSED`. Link loss, `DISK_PRESSURE_STOP` or a seal refusal leave the run `INCOMPLETE`, which a live session can retry and a stored-only advance refuses. *Default built:* only a passed instant is terminal.
