# Architect answer - Site FindingIndex (2026-10-15)

Decision: `D-2026-10-15-a-finding-index`. Resolve `A-finding-index` for the W1 Site read only. Authority is the owner-absence work order item 9, the reviewed S4-01 episode contract, `D-2026-10-14-s5-selected-window-overview`, and `D-2026-10-15-s501-finding-choice`. This decision defines a reusable row contract; it does not implement an estate/global index, cold-chain or EV analytics, or approve UI copy.

## Scope and row selection

- Require an authenticated tenant, resolved Site UUID/code, domain and selected half-open UTC window `[from,to)` of at most 31 UTC days. Reject longer windows. The W1 producer is mini-grid dispatch. Resolve the Site within the tenant and use the established 401/403/404 identity rules. Do not silently expand to another Site, another domain or the mock's global Findings area. Echo the requested window and display timezone; changing dates makes a new scoped read, not a client-side filter of an old list.
- Start with persisted S4-01 Finding and immutable FindingRevision records, never a UI seed, S3 interval alone, Lab private state or a financial consequence. Select the latest permitted revision of each canonical Site Finding from one consistent S3/S4 basis. A row qualifies only when its selected episode intersects the window (`episode_start < to` and `episode_end > from`); a boundary touch does not qualify. Apply S4 merge canonicalization: one row for the surviving ID, with superseded IDs available as relationship/history links. Extension changes the revision on the same Finding; separated recurrence uses a new Finding ID and recurrence link. Closed and unconfirmed episodes remain eligible historical rows in an intersecting window; the default list is not an implicit open-only filter.
- Row identity is `(tenant_id, site_id, finding_id)` with the stable Finding UUID, canonical ID, exact selected `finding_revision_id`, domain, episode bounds, lifecycle/transition, selected assessment/run/model/cohort and cited accepted-evidence/configuration IDs. Include limitations and exact Site detail URL `/sites/{site_code}/findings/{finding_id}?revision_id={revision_id}`; the API may also return an unpinned canonical URL. The selected revision link must survive reload and later revision creation. A row's source and analytic lineage is the selected immutable revision's lineage, not a recomputation from its title or latest unrelated consequence.

## Ordering and pagination

- Do not infer a priority or confidence rank from the v6.9 illustrative rows. W1 default order is selected `episode_start` descending, then stable Finding UUID ascending. This replaces the provisional `(priority_tuple, updated_at, finding_id)` ordering in the pre-S3 guidance until a reviewed priority producer exists. A future reviewed priority rule may add a versioned `priority_tuple`; until then any priority/lens control without a supported producer is hidden or explicitly unavailable. Never order by mutable amount or arrival time. Return a deterministic total count and opaque cursor bound to tenant, Site, domain, window, selected basis/watermark and last sort key. A changed basis invalidates the cursor and requires a fresh first page; it must not splice different revision sets together. Page size is bounded. S5-02 consumes the same ordered Site rows and does not independently rank or select an S5-01 card Finding.

## Watermark and currentness

- Return a read-level selection token/basis ID, accepted-source watermark, S3 assessment selection and analytic watermark, S4 matcher/selection watermark, model/matcher version, `built_at`, coverage/limitations and a typed status. A transactionally consistent scoped read or atomically published projection is acceptable. `knowledge_at` is the stated selection cutoff; do not promise arbitrary commit-ordered historical replay from the current S3 worker clock. Exact revision IDs are the audit anchors.
- `CURRENT` requires complete scoped discovery: every UTC-day analytic window intersected by `[from,to)`, plus neighbouring windows reachable through the S4-01 20-minute episode-continuity rule, must have S3 selection and canonical S4 matching through each window's current selection seq on the same accepted-evidence/configuration/model basis. No affected dirty, leased or failed S3/S4 work, watermark mismatch or moving selection is allowed. Relevant late evidence or changed configuration/model invalidates affected windows and must rebuild or make them stale. `PENDING` means no usable completed selection yet; `STALE_PROJECTION` retains prior rows/IDs with the reason while a newer basis is unresolved; `FAILED` reports failed work and any prior selected rows as historical. `UNASSESSED` means no completed assessment/discovery basis. None of these statuses authorizes a current count, current empty claim or an inferred Healthy state. A source-coverage limitation may coexist with a current, complete assessment of the available evidence; state the limitation instead of calling the physical world complete.
- Apply the Site's S3 Performance cutover source gate before any unpinned index read. If it is closed, refuse the index with HTTP 409 `PERFORMANCE_CUTOVER_CLOSED` and the gate reason, matching the Finding routes. Return neither `CURRENT` rows nor a zero-row/no-Findings claim. Exact `revision_id` Finding detail remains the separate audit-only route. This rule also consumes the reviewed S4-05 stored provenance form of the gate once merged.
- Keep list freshness separate from each row's assessment claim and from money eligibility. A current list can include an `UNCONFIRMED` Finding or a row with no current amount. A stale list cannot silently replace its selected revision links with newer detail heads.

## Independent fixture proof

- `D-site-finding-index-empty`: persist a tenant/Site/domain/window with an accepted-source and S3/S4 selection watermark, complete assessed discovery, zero canonical intersecting rows and a `CURRENT` zero-row response. Prove a wrong Site/window is excluded and a boundary-touch episode is excluded. Separately exercise unassessed, dirty/stale and failed reads, each visibly Unknown/pending rather than a no-Findings assertion; close the S3 source gate and prove HTTP 409 `PERFORMANCE_CUTOVER_CLOSED` with its reason and no current rows or zero claim. A filtered empty page after a positive unfiltered read is not the zero-row fixture.
- `D-site-finding-index-rows`: use committed accepted evidence and S4-01 revisions to persist at least one intersecting canonical Finding, ideally multiple for order and cursor proof. Verify stable ID, latest selected revision, exact detail/history link after reload, recurrence versus extension and canonical merge behavior, cross-Site isolation, date change, boundary intersection and invalidation after a late revision. Empty and positive fixtures are separate W1 closeouts; both must be reviewed. Do not count the mock's F-108 or F-109 as produced Findings without their own reviewed analytics.

## Money and provenance

- A row's existence, order, lifecycle and links are independent of money. The optional consequence cell may use only the exact selected FindingRevision and compatible selected-window consequence. Consume the shared LR-01 `money_eligibility` state and S4-05 exact accepted-ID publication provenance when those reviewed but currently unmerged branches become the build baseline. `PENDING_REASSESSMENT` or `WITHHELD_GENERATOR_SERIES`, mixed/unknown source, stale list or consequence, wrong revision/window, unpriced quantity/price or unresolved source-open state means no current amount. Preserve an old value only behind an explicit historical/audit link. Coherent authored or registered simulation must carry its truthful label and still pass exact-head, currentness and quantity/price gates. Do not aggregate, sum overlapping Findings, infer savings, or turn missing price into zero. If S4-04 starts before those branches merge, leave the consequence cell unavailable and add the reviewed contracts before any current-money presentation or S5-02 integration.
