# S2-02 questions 5 (backend/gateway corrections Q14-Q16, Q19, Q21) - fail-closed defaults applied

Q25. **A missing legacy store reads as the zero inventory.** `current_legacy_inventory` (`backend/assetops_backend/evidence_migration.py`) loads the Site's file-store evidence (`JsonEvidenceStore.load_site`: an absent file is an empty `SiteEvidence`) and `JsonCommitStore.site_artifacts` (an absent `var/commits` is no artifacts). An unreadable file or artifact raises and closes the gate. So deleting the legacy store invalidates any non-empty pass (the digest changes), but an empty-set pass stays valid when the store folder is absent, since "no store" and "empty store" hold the same (zero) legacy input. Default built: as stated. Alternative: record store presence in the digest (would also close KOBO-001 the first time any Lab commit creates `var/commits`).

Q26. **Environment identity.** `environment_identity` = driver family + host + port + database name of `DATABASE_URL`, credentials dropped (`postgresql://127.0.0.1:55432/assetops`). A report copied into another workspace that points at the same database is treated as the same environment; tenant and Site UUIDs bind it further. Default built; no named environment variable exists in config to use instead.

Q27. **Inventory scope.** The fingerprint covers file-store batches, records, rejections, conflicts and every committed artifact filed for the Site (raw-byte SHA-256, sorted by run id). It excludes the S3 hand-off fixtures (file-saved `dispatch` claims, ledger recompute jobs), which are carried verbatim, make no Evidence claim, and change as the ledger ingests. Default built: fixtures do not gate the cutover. Any unreadable artifact of ANY Site closes the gate (fail closed; the store is scanned whole).

Q28. **Ambiguous database commit at issuance.** If the connection drops at COMMIT after the server committed, `issue_credential` raises `LedgerUnavailable`; the CLI exits 1 and removes the new file (Q16 ruling: "on DB failure remove only the unissued new file"). The old credential may then already be revoked. Default built: discard; the operator re-runs `issue` (a fresh selector). A recoverable alternative (keep the file and report "commit outcome unknown") would be a protocol change for the Architect.

Q29. **Gateway credential ownership on Windows.** `read_upload_credential` now refuses unless the file's protected DACL grants only the gateway process's own user (`gateway/assetops_gateway/credential_protection.py`). Provisioning must therefore run as the account the gateway runs as, or the operator must re-ACL the file to that account. Default: refuse otherwise; the pilot runs both as the owner account. A hand-copied credential file (inherited ACL) is refused with "inherits access from its folder".

Q30. **Lab diagnostics guard and ACKED.** S2-01c's `isEmittedDiagnostic` refused a newest stored diagnostic in state `ACKED` ("nothing is received centrally in this build"). S2-02 uploads now produce gateway-verified receipts, so once the newest diagnostic was receipted the whole Lab diagnostics read would show as unavailable. Built: ACKED accepted; `last_error_code`/`refusal_code` validated when present. The S2-01c test that asserted the refusal was updated (`frontend/src/shell/__tests__/gatewayPublication.test.tsx`).

Q31. **Conflict lineage time is not rendered yet.** Rejections now carry `conflicts_with_source_time` (the original accepted reading's time, lineage only) and the rejections route carries `rejected_without_source_time`. The Evidence UI still shows only the conflict's own time. Default: not rendered; 3c may add "original reading at ..." beside a conflict if the walkthrough needs it.
