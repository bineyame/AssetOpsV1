# S2-01c phase-1 decisions — Codex Architect, 2026-10-09

These are design rulings on `.agent/S2-01c-questions-1.md`, not a review or acceptance of the phase-1 implementation. The material contract is recorded as `D-2026-10-09-s2-gateway-diagnostic-semantics` in `.ai/DECISIONS.md`; the S2-01c and S2-02 packets now carry it.

1. **Q1 — Accept (a), local provenance only.** The recorded `GatewayDiagnosticsV1` wire has the operative pressure level and the registered `SIMULATED` source mode, while S2-01c AC3 requires injected causes to be identified locally. No V1 field or phase-2 gateway change is needed; phase 3 must show local `MEASURED`, `INJECTED_FAULT_FIXTURE`, or `UNMEASURABLE` accurately, and S2-02 must label central pressure as reported simulated-gateway state without claiming measured hardware pressure or a cause the wire cannot convey.

2. **Q2 — Accept the built STOP boundary.** S2-01c AC3 says refuse *new acquisition* before sequence allocation, and its preservation/recovery contract permits sealing previously admitted rows and emitting diagnostics when storage still permits. Phase 2 must retain whole-call refusal before writes for `admit`/`admit_texts`, including replays, and keep existing bytes and sealing progress intact; a failed disk probe yields operative `STOP` with local `UNMEASURABLE` provenance. S2-02 may still upload already sealed bytes at STOP and must not treat STOP as proof of central acceptance.

3. **Q3 — Accept the slot identity and provisioned defaults.** One immutable diagnostic per real-UTC cadence slot satisfies the packet's exact-byte retry requirement; immediate local state may change within a slot, while the next slot carries a new wire snapshot. Keep `CLOCK_BEHIND`, the frozen 60-second cadence and 1 GiB/256 MiB WARN/STOP triggers as provisioned demo values, not universal hardware limits; phase 3 should make the local current-versus-last-emitted distinction clear, and S2-02 must derive central freshness from server receive time and declared cadence.

4. **Q4 — Accept queue membership, change `mapping_error_count`.** `STAGED|READY|IN_FLIGHT` envelopes are admitted pending evidence whether sealed or not, so `queue_count` includes them and excludes holds/dead letters; its age uses real-UTC outbox `created_at`, as required by the virtual-publication-clock decision. Counting every hold as a mapping error mislabels invalid values, conflicting reports, sequence exhaustion and batching refusals: phase 2 should count distinct `mapping_hold` rows only for `NO_ACTIVE_MAPPING`, `UNKNOWN_CHANNEL`, `SOURCE_NOT_PERMITTED`, `OUTSIDE_VALIDITY`, `UNIT_INCOMPATIBLE`, and `INVALID_ENUM`, while retaining the all-kind `held_reports` local breakdown and a focused counter check. When phase 2 virtualizes V3 `published_at`, it must leave `envelope_outbox.created_at` on real UTC; phase 3 and S2-02 should not present `queue_count` as upload-ready batch count.

5. **Q5 — Accept the built contact rule.** S2-01c AC3 permits contact from an observed public simulated report, and gateway receipt of a permitted source's report remains a contact even if its value is held or its identity is replayed. Keep gateway real-UTC timestamps, null for never heard, and `OBSERVED_SIMULATED_REPORT`; phase 3 and S2-02 must distinguish this from physical-device contact, valid evidence and source health. The STOP refusal precedes writes, so it does not advance contact.

No owner choice is needed for these contract semantics. The only required phase-2 product correction is Q4's narrowed mapping-error counter and preservation of real-UTC outbox creation when publication time becomes virtual; phase 3 must render the local distinctions above. S2-02's outline is amended for central interpretation and should verify these semantics when refined after S2-01c review. No product code was changed here.
