# Codex Architect — S3-01 phase-3a rulings (2026-10-11)

These are Q9–Q13 rulings for the phase-3a fix round and phase-3b UI, subject to the fresh Claude review. They do not accept phase 3a or replace the S3-01 owner checkpoint.

1. **Q9 — overrule the no-bump default: publish `dispatch-3.1`.** The default changed from accepting successive epochs as one cohort to marking them ambiguous, which can change the selected evidence, claim and input digest. Before phase 3b, change the model identifier and the versioned decision table/read/comparison labels; automatically enqueue and reassess every stored default `dispatch-3` window, and keep the cutover closed until its selected run is `dispatch-3.1` or visibly unassessed/stale. Preserve old runs and revision URLs exactly as historical records. Explicit selections remain point-in-time choices, not silently remapped to the new default.
2. **Q10 — accept the closed gate on `MISSING_SOURCE`.** A legacy claim citing a record absent from central Evidence lacks a comparable public basis, so documenting the exception cannot prove the new read for that claim. Phase 3b must display the exception and closed gate with the missing IDs, and route remediation or a separately scoped migration decision; an empty KOBO-001 legacy-claim set may pass only with its zero-inventory statement, unchanged-input digest, same tenant/Site/environment and live lineage proof. The UI/owner walkthrough must not call that empty comparison claim parity.
3. **Q11 — overrule the broad `INTENTIONAL_DELTA` predicate.** `INDETERMINATE` plus any named window limitation may be unrelated to the legacy interval and does not establish that a versioned rule change caused the difference. Before opening a nonempty comparison gate, match the claim to one selected interval and comparable accepted public records, then name the specific `dispatch-2` → `dispatch-3.1` rule/role/control difference and limitation affecting that interval; otherwise classify `UNPROVEN` and keep the gate closed. Phase 3b shows that exact reason and linked IDs for a proven delta, or an explicit unproven/closed state. Do not add a permissive catch-all delta class.
4. **Q12 — accept `STALE_PROJECTION` with `RECOMPUTE_OUTSTANDING`.** An overlapping PENDING/LEASED job can reflect new evidence even when the currently selected hash still matches, so `CURRENT` would overstate freshness; `PENDING` remains the no-selected-run first-build state. Phase 3b must retain the pinned prior result visibly stale, show the job state/reason, and show `FAILED` with an inspectable prior revision when retry exhaustion occurs.
5. **Q13 — overrule the no-bump default: include the limitation lift in `dispatch-3.1`.** A `LIMITED` window with no named reason was an invalid persisted explanation; lifting interval reasons changes the result payload and basis digest even where claim levels stay the same. Preserve pre-fix `dispatch-3` rows rather than rewriting them, reconcile/reassess all stored default windows, and verify that a `dispatch-3.1` `LIMITED` window has its actual interval/spans named. Phase 3b displays those reasons and the selected model version, and historical `dispatch-3` detail remains marked as an older rule result.

The phase-3a comparison report generated before the bump is no longer cutover authority: regenerate it against the current `dispatch-3.1` selection and current legacy digest, then independently review the corrected gate. The phase-3b walkthrough needs Necessary, bounded Candidate and Indeterminate cases, stale/failed states, pinned history, fixture provenance, an explicit empty-set caveat and desktop/narrow mock comparison. No new owner product choice is needed for these technical semantics; the owner still verifies the finished S3-01 UI at its existing checkpoint.
