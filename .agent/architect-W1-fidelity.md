## Binding layout contract for W1 rework and W2+ UI

For every named screen, render the v69 panel **set, order, titles, relative prominence and size, grid, and visual style** from `frontend/mockups/v69/index.html`, `screens.js`, `mockups.css`, `screen-manifest.json`, and `frontend/docs/architecture/v69-rendered-panels.json`. Use the mock's page heading, compact metric, panel, two-column, timeline, badge, table and gap patterns; port missing tokens/patterns into `frontend/src/ui/tokens.css` and `primitives.css` or shared UI components. Existing type/colour tokens that already match should be reused. Compare the rendered mock at both widths; the JSON titles alone do not define spatial structure. The mock's illustrative values never become product values.

The panel title map below is exhaustive. Default title is exactly `v69-rendered-panels.json`. Approved plain-language changes are: `foundation:2` **Identity and operating obligations** for `Identity & operating obligations`; `dispatch:2` **Selected block · {actual selected interval}** for the mock's illustrative `14:20–14:35`; `readiness:2` **Gateway status · {actual gateway name or “No gateway selected”}** for `GW-MG-01`; `finding-evidence:1` **Evidence bundle · {actual Finding name or “Selected Finding”}** for `F-104`; `sld:1` **{actual site name} · {configured topology type, if stated}** for `Kobo Mini-grid · AC-coupled mini-grid`. Dynamic titles must use the selected read, never mock fixtures. An unknown dynamic value is labelled unknown in the same panel. No other title substitutions are approved here.

Each mock panel retains its slot when a selected read cannot support its content. Put the precise honest gap **inside that panel** (unavailable, refused, pending, stale, withdrawn, not assessed, absent, or proved zero as appropriate); never synthesize a value, omit the panel, or fill it with a different period's value. A page-level refusal or no-version state may state the refusal before the panel grid, but still renders the panel skeletons with in-panel gaps where the route and screen are valid. Place current app-only content within its owning mock panel or the named contextual Analysis/Evidence/History destination below. Remove the W1-UX leading answer cards and duplicate old panels after merging their supported answer, visible state/scope/as-of, and next action into the matching mock panel. No new leading card. Keep material limits visible beside the claim.

`D-2026-10-16-w1-ux` and `-w1-ux-disclosure` still govern contextual Analysis tabs, narrow exact-reference disclosures, plain words and honest claims. At 390 px the same Analysis destination stays accessible. A closed disclosure cannot hold substantive method or hide a material limit. `D-2026-10-17-w1-rail` and `-w1-ux-06` continue to govern navigation and the configuration/contact/condition distinction.

## F5 navigation and Site Findings ruling (`D-2026-10-17-f5-subtabs-and-contact`)

Extend the owner's full mock-menu rule to the named in-page rows as a narrow W1 exception to the earlier absent-Site-tab rule. Preserve the v69 row order and labels. Render supported destinations as real tabs with registered routes and an active state; render unbuilt destinations as visibly muted, readable, noninteractive text in the same tab row, each with the visible and accessible status `Not available yet`. Reuse the rail's unavailable-entry semantics, not a disabled button: no `href`, `to`, handler, pointer affordance or tab stop; Enter and Space cannot activate it. The tab styling may differ from the rail. Keep rows readable and reachable at 390 px without clipping or horizontal page overflow. Amend the navigation guard narrowly for these declared inventory entries and test their order, status, absent destinations, active route and keyboard behavior; continue rejecting other disabled/labelled-in-place Site tabs.

In Foundation, show the Site model, Single line diagram, Readiness and **Change & effect** subtab row on the Changes screen and its sibling screens; Change & effect links to the existing Changes route. In Site Work, retain Actions as the live subtab and show Incidents and Maintenance as unavailable. In Finding, show Alternatives as unavailable in the mock's tab position. In Financials, show Scenarios as unavailable in the mock's subtab position. Do not copy mock counts, imply those sections have records, or create placeholder routes. Any of these entries becomes live only with a reviewed, truthful destination.

For Site Findings, use the mock's `All`, `Cost`, `Risks`, `Opportunities` lens-chip row within the single Findings panel. `All` is the selected live view; a lens becomes interactive only when an authoritative classification and exact Site/window filter can return its rows and an honest empty result. Preserve the existing date/window selection as the real scope control, placed compactly with the panel heading; a chip must not silently change or discard that selection. Keep the current supported columns and exact Finding links; mock priority, confidence, consequence or lens values remain gaps unless backed by the selected read. Include the chip row and both widths in the F5 capture audit.
