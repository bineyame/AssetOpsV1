## S6-03 - `A-action-index` / `sitework:1#a`

**Source and scope.** Add a read over persisted `action` and `action_event`, authenticated to one tenant and resolved Site. W1 is mini-grid Actions only. Select a half-open UTC creation window `[from,to)` of at most 31 days; `created_at >= from AND created_at < to` is the membership rule, irrespective of later events. Echo scope and display timezone. The stable row key is `(tenant_id, site_id, action_id)`; include Action code, creation time, exact origin Finding and FindingRevision IDs, latest selected event ID, event recorded time, reduced lifecycle, and the canonical and exact-event Action links. The detail/event selection uses **recorded** order, `(recorded_at,id)`, not `occurred_at`; a backdated observation does not move the row in the list. Default order is `created_at DESC, action_id ASC`, with bounded pages and an opaque cursor bound to tenant, Site, window, selection watermark and last sort key. No unreviewed priority, owner, due date, verification verdict or cross-domain/global Work aggregate is inferred from v6.9.

**Watermark and missingness.** Read one consistent DB snapshot; return `read_at`, max included Action creation/event recorded fence (or explicit zero-row fence), total, page cursor, selected window and `CURRENT` only if the scoped store read succeeds. A zero-row `CURRENT` means no **persisted Actions created in this Site/window**, not no Finding, recommendation, incident, maintenance or unrecorded work. Store unavailable, unauthorized scope or a page cursor whose bound fence changed never becomes an empty list: return a typed failure or invalid-cursor response and reload page one. For selected rows, show the state as of the fence and preserve exact origin/event links after reload. An event arriving after the first-page fence invalidates subsequent pages; do not splice states. Keep exact historical Action detail available separately.

**Refusals and reuse.** Apply `D-2026-10-09-pre-s3-claim-routes-and-actor` identity rules: 401 unauthenticated, 403 known forbidden scope, 404 foreign/nonexistent Site or root. Refuse invalid/unbounded windows and changed cursors; no generic empty success on DB failure. Reuse the Site-scoped Action columns and event ordering in `backend/assetops_backend/actions/adapters/postgres_action_store.py:43-48,184-200`; the Action detail, origin, basis, state and stable links in `backend/assetops_backend/actions/service.py:524-581`; and S6-01 lifecycle/actor authority (`D-2026-10-14-action-lifecycle-and-policy-application`, `D-2026-10-15-s601-action-store-and-ui`, `D-2026-10-15-s601-reopen`). The **new** producer is the Site/window index query, consistent selection/pagination and Site Work UI. The existing `actions_for_finding` is a Finding-scoped helper, not this index. The S4 FindingIndex decision `D-2026-10-15-a-finding-index` is the Site/window, cursor and zero-row precedent; it does not select Action rows.

**Fixtures and packaging.** Reuse `D-action-records` for a persisted positive row, adding two Actions at distinct creation times and a later/backdated event to prove order, selected state, exact FindingRevision/event links, same-basis pagination, Site isolation and reload. Add an independently asserted assessed zero-row Site/window and a changed-fence cursor case; a client-filtered empty page is insufficient. S6-03 can be **one S slice**: one small read and one list UI, then independent review and owner checkpoint. It closes only the Actions tab of `sitework:1`, with Incidents/Maintenance and global queues honest gaps.

## S7-01 - `A-S7-health` / `health:2#a` and `asset:3#a`

**Source and scope.** Site Health reads registered gateway/source identities and the most recent centrally stored `GatewayDiagnosticsV1` per gateway for the authenticated Site. Use the server receipt clock for contact freshness under declared cadence, and separately report the diagnostic's own `observed_at`, source contact times, queue depth/oldest age, clock offset/trust, disk pressure and their reported-fact age. Return gateway/source/diagnostic IDs, registration, received/observed clocks, cadence, `read_at`, selected diagnostic sequence and a per-gateway source watermark. A fresh receipt of an old diagnostic makes contact potentially `CURRENT`, while queue/device facts remain old or `UNKNOWN`; virtual Lab time never measures real network lag. Per-source contact is reported only when the diagnostic supplies that source's timestamp; gateway contact alone does not prove a device is connected. `CURRENT | STALE | UNKNOWN` applies to **contact**, not battery condition. `STALE_PROJECTION` is separate if any derived read lags the selected central diagnostic.

The battery asset detail is a separate Site/asset-scoped boundary read. Resolve the configured battery and binding from the effective S1 Site basis, and disclose the selected asset/configuration IDs. In W1, return `UNKNOWN` physical condition and explicit missing causal inputs (for example accepted temperature/capacity/stress history) unless a separately reviewed causal battery observation and rule actually exist. The asset may display accepted SOC or declared nameplate facts only under their own labels and exact accepted evidence/binding IDs; neither proves degradation or remaining life. Withhold replacement exposure, warranty-at-risk, stress score, diagnosis and date. An unbound or absent battery is `NOT_CONFIGURED`/`UNKNOWN` with reason, never a healthy asset or fabricated asset row. `asset:3#b` positive physical condition remains non-core and unmapped.

**Watermark, empty and refusal.** No registered gateway is `NO_REGISTERED_SOURCE`; registered but never received is `UNKNOWN` contact. A stale contact is not proof that an outage began at the last receipt; queue pressure is the last **reported** state, not current hardware pressure. Return a watermarked empty or Unknown with reason, not a green zero. Any unreadable central store, inconsistent registration/diagnostic selection or stale projection refuses a current operational claim. Apply tenant/Site/asset 401/403/404 rules. Do not join diagnostic facts to accepted measurement evidence or claim battery condition from the gateway's own health. Reuse central latest-diagnostic selection in `backend/assetops_backend/evidence/adapters/postgres_gateway_access.py:172-194`, cadence-based contact and diagnostic fields in `backend/assetops_backend/evidence/gateway_access.py:289-343`, and the existing Site gateway read route in `backend/assetops_backend/gateway_api.py:94-109`. The **new** pieces are the selected two-clock fact-age/trust interpretation, bounded Site Health UI and asset Unknown/missing-input read/UI. `D-2026-10-09-pre-s3-evidence-readiness-health` already governs the semantic split; this decision narrows S7's first panel.

**`D-edge-health-cases` and packaging.** Build persisted central diagnostic cases through registered gateway authentication: (1) received/current heartbeat, (2) no later receipt across the declared cadence threshold, (3) delayed old diagnostic received now with old reported facts, (4) growing queue and old queued item, (5) reported clock offset or untrusted clock, and (6) disk pressure/acquisition-stop then recovery. Preserve local sequence, diagnostic ID, server receipt and source reported time; reload the central read. Add never-received and wrong-Site cases plus battery configured-but-causal-input-missing; private Lab state cannot satisfy them. S7-01 needs a **non-UI/UI split** inside its one owner-facing slice: first review diagnostic fixture and two reads, then Health/Asset UI, desktop/narrow behavior, links and owner checkpoint. Do not wait for `I-sim-battery-cases` or a positive physical condition claim.

## S3-02 - `I-capability-read` / `evidence-analysis:2#b`
