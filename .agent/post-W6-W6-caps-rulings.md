# Architect rulings: post-W6 W6 caps and list-cell overflow

Authority: `.agent/architect-request-post-W6-W6-caps.md`, W6 Q15–Q16 in `.agent/post-W6-W6-rulings.md`, and the mounted-page probe at product `f3da6e90` in `../AssetOpsV1-review8/.agent/post-W6-W6-evidence/q15/summary.json` (five rows with every intended variable text field at 160 characters, 1440/390 px). These are build rulings; the listed measurements are from the pre-fix probe, not a claim that the final build passes.

1. **Work done and History, 1440 px.** Revise the closed-panel caps to **600 px for Work done** and **650 px for History**. The measured peaks are 503 px against 500 and 558 px against 550 respectively. The revised caps allow the five-row Work done case and the six-event History case with its pager, with roughly the Q15 15% reserve rounded to a 50 px step. Keep every row and the pager. The adjacent Lifecycle panel may stretch to the Work done grid-row height; that stretch is not independent content overflow. Its own 1440 px cap remains 500 px (442 px measured). User-expanded disclosures are exempt from these closed-height caps.

2. **Ratified provisional caps.** Ratify the following closed-panel caps, in pixels, at **1440 / 390**: Incident Case boundaries **150 / 150** (fixed-copy peaks 103 / 126); Operational Record a manual reading **400 / 600** (325 / 513); Operational How records are used **400 / 300** (325 / 223); WR Work done at 390 **800** (690); WR Lifecycle at 390 **250** (194); WR Maintenance record · activity at 390 **900** (763). The producer and case evidence are the corresponding `part-inc`, `part-op`, `part-stress`, and `part-detail` entries in the Q15 summary. The previously explicit caps remain: Incident cases **700 / 800** (647 / 737), Corrective work requests **700 / 800** (657 / 737), Preventive plan **600 / 690** (599 / 690), Operational records **650 / 780** (631 / 744), WR Maintenance record · activity at 1440 **700** (622), and WR History at 390 **690** (630). The Preventive plan phone case is exactly at its cap, so any closed-height increase requires the fallback in ruling 5, not a pass by rounding.

3. **R356, desktop table width with a vertical scrollbar.** Retune **Feeds from 140 to 125 px**; retain Record 90, Type 110, Site 150, When 130, By 120, What it says 270, and State 90. The fixed column sum becomes **1085 px**. The five-row table's 500 px high vertical scroller leaves a measured 1090 px client width at 1440 (1105 minus its 15 px scrollbar), giving 5 px clearance. Update the 390 px inner table minimum to the same 1085 px, preserving its horizontal scroller. Keep wrapping and all eight columns. Verify `scrollWidth <= clientWidth` at 1440 for positive and five-row cases with the vertical scrollbar present, and record row/panel heights again. This follows the WCAG 2.2 Reflow data-table pattern: keep two-dimensional scrolling inside the table container rather than forcing page-wide overflow ([W3C Reflow guidance](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)).

4. **Clipped list cells.** Apply **progressive disclosure in the cell**, not an undisclosed clamp or a hover-only/title tooltip. For the affected Incident cases (Site, Severity, Owner, Findings), Corrective work requests (Asset/site, Owner), Preventive plan (Asset/site, Trigger, Last done, Next due, What it proves), and Operational records (Record, Type, Site, By, Feeds), keep the two-line preview only when the complete value would overflow it. Show an explicit, visible **“Show full”** affordance within the existing two-line cell box, with a column-and-row-specific accessible name; activating it reveals the complete unchanged value inline and offers **“Show less”**. The expanded value wraps without clipping. The control must work by keyboard and touch, have a visible focus indicator, and remain separate from any cell link (no nested controls). Do not add a third closed line or a hover/focus popover. When the full value fits, show it plainly with no disclosure. This uses the disclosure pattern and WCAG 2.2 keyboard/focus guidance ([W3C Focus Visible](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html)); it avoids the transient-tooltip constraints in [Content on Hover or Focus](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html). WR panels have no newly found clipped cells and retain their existing full-text disclosures.

5. **Caps under the cell fix and fallback.** Rulings 1–2 are the target **closed-state** caps with the two-line disclosure layout in ruling 4; the disclosure trigger must fit inside the current row height, so it must not consume a new line or reduce the preview to unusable fragments. The final-SHA probe must demonstrate all affected cells can expose their full 160-character value in both viewport widths; all disclosures open are exempt from panel-height caps and must leave every row and full value reachable. Retain the bounded, labelled, keyboard-focusable inner table scrollers, with visible vertical and phone horizontal scroll affordances. If the Feeds retune, scrollbar rendering, text control, or any remeasure exceeds a target cap or creates horizontal overflow at 1440, adjust the table's inner scroll height/width or the closed disclosure layout locally and remeasure the same worst-case fixture; return the actual peak and proposed revised cap to the Architect if the target still cannot be met. Never hide rows, truncate a value without its full disclosure, or silently claim a passing cap.
