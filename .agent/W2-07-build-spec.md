## 0026 schema, writer and exact money calculation

Migration 0026 widens only the existing `financial_assumption_revision` key/unit checks for `ev_gross_tariff_per_kwh`. Preserve diesel `currency/L`, authored/source/valid/recorded succession, correction and overlap checks, existing API authorization/idempotency and mini-grid fuel consequence check. Add EV design §1's scoped append-only `ev_consequence_revision`, `ev_consequence_session`, `ev_consequence_evidence` plus §8 `ev_consequence_work` and `_attempt`, scoped FKs/uniques, positive revision/attempt numbers, finite nonnegative Decimal checks, one success per work, triggers and guarded downgrade. `amount` is nonnull **iff** state ESTIMATED and all complete quantity/tariff/currency fields exist; `amount=quantity_kwh×tariff_value` with exact Decimal, no storage rounding. `UNPRICED`/`WITHHELD` have null amount/currency. `source_gate` is one of `AUTHORED_DEMONSTRATION|REGISTERED_SIMULATION|MIXED|UNKNOWN` from S4-05, not an invented real-source class. Existing fuel consequence rows/checks stay byte-identical. Downgrade refuses while EV tariff revisions or consequences/work/history exist; no cascade deletion.

One canonical Site/window consequence lineage, not a per-Finding sum: aggregate distinct included `ev_meter_interval` accepted evidence IDs across latest settled selected session revisions. For every included interval, session outcome must be COMPLETED or OBSERVED_ABORT, `energy_complete=true` across that session's active span, and no contradictory/unattested/overlap condition. An aborted session contributes only delivered pre-abort intervals; its unmet demand is unknown. Exclude incomplete sessions as *whole-session pricing* while displaying their supported partial kWh separately. At selected cutoff, each interval must be covered by exactly one tariff revision's valid range and recorded visibility; v1 requires the **same revision and currency for all included intervals**. A valid selected empty window has no eligible quantity, so `quantity_kwh=null` and no ESTIMATED zero. A tariff gap, two revisions across a window, missing tariff or unsupported unit yields `UNPRICED/PRICE_GAP_OR_CHANGE` (or `TARIFF_MISSING` for no revision) and null amount. A pending/failed/late assessment, contradictory meter, historical cutoff offered as current, source class MIXED/UNKNOWN or incoherent price/source basis yields `WITHHELD` and null current amount. A historical exact revision may display its old amount with a clear **Historical scenario** label, never as the current amount. No counterfactual sales, billing collections, margin, repair or warranty amount is computed.

`technical_input_sha256` hashes sorted exact included session revision IDs/basis, accepted meter IDs+SHA, exclusion reasons and window/cutoff; `basis_sha256` additionally includes tariff revision/value/currency, source class/gate, formula `ev-gross-tariff/1`, state/reason and recorded basis. A changed selected cutoff or source/price revision appends history; identical basis is idempotent. `overlap_group='ev:'+sha256(canonical(tenant_id,site_id,window_start,window_end,tariff_revision_id_or_NO_TARIFF))`; do not count a meter interval twice through two Findings. Session link quantity is exact included kWh; evidence link is each included accepted meter ID once. Keep exact Finding link nullable because Site consequence is not owned by one Finding.

Migration triggers, not runtime modules, insert dirty work when an EV session/assessment revision, accepted relevant late event/meter, EV tariff publication or source-gate publication affects a window. Scope trigger selection by tenant/Site and overlapping selected window; use `ON CONFLICT (site_id,window_start,window_end,dirty_basis_sha256) DO NOTHING` against §8's declared unique key only inside the trigger and test a real INSERT path. Site IDs are globally unique and the row retains tenant/Site-scoped FKs; this conflict target must match the actual SQL constraint. A duplicate accepted upload or identical tariff request creates no duplicate consequence. `PostgresConsequenceStore` selects work without a SUCCEEDED attempt, locks by work ID transaction advisory lock, appends next `revision_no` for the Site/window and exact links plus a SUCCEEDED attempt atomically; a failed derivation appends FAILED with code and remains retryable. No no-op fictional zero consequence is required if no qualifying session exists: an empty-ID SUCCEEDED attempt is allowed and the read says no scenario assessed. DB server timestamps are omitted by writers. Probe pass/fail Rule 8 against actual runtime modules **and the migration trigger text** (runtime scanner alone cannot prove trigger-only work). No SQL writer enters EV read service.

## Five selected reads and source/claim vocabulary

Create a pure `ev_site_reads.py` composition service with SQL kept in existing assessment/consequence/assumption adapters; mount `build_ev_site_router` from `main.py`. In one repeatable-read transaction authenticate/resolve tenant and EV Site, capture committed S2 watermark, select effective Foundation, settled W2-06 revision heads, accepted evidence/provenance and exact tariff/consequence at the same cutoff. Source-link lookup uses `batch_publication_link.batch_id` as in W2-04; resolve class from exact accepted IDs, not Lab mode. If an adapter cannot accept a caller connection, add that method there; never compose via loopback HTTP or independently opened connections. All responses include `{site_id,window:{from,to,known_at},currentness,source_provenance,limitations}` and EV design §6 fields. `currentness` names CURRENT, PENDING_RECOMPUTE, STALE_SOURCE, HISTORICAL or UNKNOWN according to selected basis; a historical complete technical record remains visible even when money currentness is withheld. Accepted fact age = selected `to` minus latest qualifying source time; contact is only identified source diagnostic at/before cutoff, otherwise UNKNOWN. Return exact `as_of` and limitation on each overview card. Unknown source is not “offline”; online gateway is not charger health.

`/ev/overview` uses W2-06 **full-window** denominator, not a page of sessions. Energy response separates `supported_kwh`, `complete_kwh`, `partial_kwh`, `unknown_seconds`; `complete_kwh` is the eligible full-coverage session sum, while an interrupted session with complete coverage contributes delivered energy, never loss. `site_power.observed_peak_kw` is max accepted aligned import mean in covered selected slots, with configured limit and coverage; `claim_limit=CONTEXT_ONLY` unless independent requested+allocated signals and synchronized import exist, and even then competing causes remain unknown. Status is `OBSERVED_SESSIONS|NO_SESSIONS_OBSERVED|UNKNOWN|CONTRADICTORY`; do not say Healthy solely because observed peak is below cap. Attention order: pending, fault abort, incomplete session, meter/source gap, tariff missing, each with exact link if target proved. `consequence_summary` selects one latest Site/window revision by exact basis and overlap group, never sums Finding consequences.

`/ev/evidence` returns capability rows in mock order, with §8 `SUPPORTED|LIMITED|UNAVAILABLE|CONTRADICTORY`, exact required/missing roles, `{known_seconds,expected_seconds,ratio}` and selected accepted IDs. Use claims SESSION_OUTCOME, SERVICE_STATE, DELIVERED_ENERGY, FAULT_ASSOCIATION for mock four rows, plus SITE_POWER_CONTEXT, POWER_CONSTRAINT and GROSS_TARIFF_SCENARIO in detail. A “Full” outcome claim requires coverage for the stated interval, not a general equipment condition. Source rows are configured c1, c2, site meter and billing system slots; billing is `Not connected` only if configuration proves absence, else `No record`. Contact from source-specific diagnostics, quality from accepted facts; no status is inferred from Site mode. Ranked next evidence is deterministic: terminal gap, meter gap, status gap, independent diagnostic/request/limit, tariff, billing; show first applicable and keep the three mock row slots with explicit `None identified` when fewer.

`/ev/evidence/analysis` pages accepted public records at selected cutoff, sorted `(source_time,evidence_id)`, preserving exact event/delta value, unit, `source_time`, nullable sent/published timestamp, `received_at`, quality, role, session ID and exclusion reason. Add `value_display`, `unit`, `sent_at`, `record_target_state:PROVED|UNAVAILABLE` as W2-04 did for cold. A missing END or meter report is an explicit **gap row only when W2-06 expectation proves it**, never counted as accepted or given an invented ID. Claim-rule rows state each required role, observed/missing, coverage, result/limit, exact IDs/source class/cutoff. Exact record/assessment link requires integration proof that the target renders that ID under same Site/window/cutoff; otherwise labelled ID and `Analysis view not available for this EV record` (retro ruling #14).

`/ev/financials` returns one current Site consequence with exact basis and separate explanatory `not_included:[lost_sales,collections,margin,repair,warranty]`. For no warrant/eligible interval, use one in-table empty state; do not fabricate three financial DB rows to match mock illustrations. A fault-abort row can explain delivered pre-abort kWh and unmeasured lost demand; warranty/repair row is a named **unrecorded gap**, never `$0` or `$850`. `/ev/financial-assumptions` reads actual published EV tariff revisions effective/recorded at cutoff plus `missing_keys`; billing/collections remains an unconnected capability/gap, not a publishable assumption. Currency is selected tariff currency or `Not declared`, not default USD. Both preserve selected read-only context; the existing authorized publication API creates the next time-valid tariff revision.
