### H1 (High, contract defect): the Site-wide "defer S4 while S3 is due/leased/failed" gate freezes a Site on any terminal S3 failure, and is unnecessary for correctness

Packet :19 says: "S4 matching runs only after S3 work relevant to that Site has reached a completed basis; if S3 remains due, leased, failed or deferred, record it as pending and defer that Site's S4/currentness promotion."

- **Failed.** A job that exhausts `max_attempts`, or whose lease expires on its last attempt, is FAILED. It stays live (`_LIVE_JOBS`) until a later DEFAULT selection covers its window, and `reconcile` never re-enqueues it. One deterministic failure on one UTC day therefore stops S4 for **every** window of that Site indefinitely. Late evidence on unrelated days never reaches a revised Finding. That defeats the slice's Outcome, and the packet names no recovery command (none exists: `assess` writes an EXPLICIT cohort-suffixed run, not the default selection).
- **Due.** The gate is checked after a bounded S3 drain. On a Site whose arrivals outpace its per-tick S3 share, or behind other Sites' older jobs in the global FIFO, S4 is deferred tick after tick.
- **Not needed.** The matcher already ignores non-CURRENT windows per window (`finding_episode.py:12-14`) and replans idempotently from the selection basis. Running S4 every tick after the S3 stage is safe.

**Why it matters:** the implementer would build exactly this. The phase-1 proof "no S4 promotion ahead of due/leased/failed S3 work" would pass, the phase-2 "failed S3 job" proof would show "deferred" as intended, and production would freeze silently except for an alarm.

**Fix (Planner):** separate S4 *execution* from *currentness*.
- (a) Run `match` for every selected Site every tick after its S3 stage. The matcher's CURRENT-window rule is the correctness gate.
- (b) Make the currentness gate window-scoped. A selected window is not CURRENT while a live S3 job intersects it (with its continuity bracket), its `match_state.matched` is false, or relevant consequence work is outstanding. This is what item 4 already needs.
- (c) A terminal FAILED S3 job is a `FAILED` stage state with job ID and `last_error`, and an alarm. Specify an operator recovery that re-enqueues the window through the existing `AssessmentStore.enqueue` (for example an `assess_dispatch requeue --tenant-id --site-id --start --end` command, an INSERT/UPDATE already allowed to the assessment writer) and document it in README-db.

# Seams: Configuration persistence port, and Shipped versus user-authored
# configuration.
#
# These exist so that replacing a store stays one new adapter module plus one
# composition change, and so that shipped canonical configuration cannot
# acquire a write path by accident.
#
#   - adapters are imported only by their own domain's composition module or
#     by a sibling adapter in the same layer
#   - no storage technology above the adapter layer, in any configuration
#     domain
#   - shipped configuration roots hold no write-capable call, the shipped Site
#     store ships empty, and the shipped scenario store ships the definition
#     the catalog needs
#   - configuration is written only by the user-store adapter
#   - each writable user store root has one owner and is gitignored
#
# T017 adds a second configuration domain, so the rules below are stated once
# and applied per domain rather than written out twice. Two copies would drift,
# and a seam enforced for Sites and forgotten for scenarios is the same as a
# seam that is not enforced: the scenario port would leak the first time
# somebody reached past it.
#
# T019 registers a third domain, and it is deliberately not configuration: a
# SimulationRun is a record this installation produced, not a document
# somebody authored. It is registered here anyway because the persistence
# seam it needs is exactly this one - a port, one composition module, one
# adapter layer, one write path, one owned root outside version control - and
# the guard caught the run store the moment it appeared, which is the whole
# point of the "resolves outside every known domain" failure below. A second
# copy of these rules for runs would be the drift this file was written to
# avoid.
#
# Test files are exempt from the scans below for the same reason they are
# exempt elsewhere: a test must be able to reach an adapter directly in order
# to prove what the adapter does.
#
# Do not weaken the checks below to make a task pass.

function Invoke-ConfigurationPersistenceCheck {

            Name        = "financials"

            Composition = "$backendRoot/financials/composition.py"

            UserRootVar = $null

        $domain.Adapters = "$($domain.Package)/adapters"

    #    package is permitted from that domain's single composition module
    #    only, plus from inside that same adapter layer: one adapter reusing a
    #    sibling adapter's reader does not leak storage technology above the
    #    layer, which is what this check exists to prevent. Everything above
    #    the layer still receives the port by injection.

    #    Crossing domains is not permitted either. The Site composition module
    #    may not import a scenario adapter, because that would be a second

    $adapterImport = '(?:^|\s)(?:from|import)\s+[A-Za-z_.]*adapters(?:[.\s]|$)'

                    $_.Package -eq "$backendRoot/$package"
                } | Select-Object -First 1
            }

            if ($null -eq $targetDomain) {

                    "configuration domain in $($module.Path):${lineNumber}: " +
                    "$($line.Trim()). Add the domain to " +
                    "tools/checks/configuration-persistence.ps1 so its seam is " +
                    "enforced, rather than letting the import go unchecked.")) | Out-Null
                continue

                $adapterImportsSeen[$targetDomain.Name]++
                continue
            }

            if ($module.Path.StartsWith("$($targetDomain.Adapters)/")) { continue }

            $failures.Add(("Banned adapter import in $($module.Path):${lineNumber}: " +
                "$($line.Trim()). Only $($targetDomain.Composition) may import " +
                "$($targetDomain.Adapters); every other caller receives the " +
                "$($targetDomain.Name) port by injection.")) | Out-Null
        }
    }

    foreach ($domain in $domains) {
        if ($adapterImportsSeen[$domain.Name] -eq 0) {
            $failures.Add(("The adapter-isolation check found no adapter import in " +
                "$($domain.Composition), so it is no longer proving anything for " +
                "the $($domain.Name) domain. Update the check, do not delete it.")) | Out-Null
        }
    }

    #    package but outside its adapters/, storage modules and direct file
    #    opening are banned: a port that speaks paths and YAML is not a seam.
    $storageTechnology = @(
        '(?:^|\s)import\s+yaml(?:[.\s]|$)',
        '(?:^|\s)from\s+yaml(?:[.\s]|$)',
        '(?:^|\s)import\s+pathlib(?:[.\s]|$)',
        '(?:^|\s)from\s+pathlib(?:[.\s]|$)',
        '(?:^|\s)import\s+sqlite3(?:[.\s]|$)',
        '(?:^|\s)from\s+sqlite3(?:[.\s]|$)',

        '(?:^|\s)(?:import|from)\s+(?:sqlalchemy|psycopg|alembic)(?:[.\s]|$)',
        'open\('
    )
    $storageTechnologySeen = @{}
    foreach ($domain in $domains) { $storageTechnologySeen[$domain.Name] = $false }

    foreach ($module in $backendModules) {
        $domain = $domains | Where-Object {
            $module.Path.StartsWith("$($_.Package)/")
        } | Select-Object -First 1

        $insideAdapters = $module.Path.StartsWith("$($domain.Adapters)/")

        $lineNumber = 0
        foreach ($line in $module.Lines) {
            $lineNumber++
            foreach ($pattern in $storageTechnology) {
                if ($line -notmatch $pattern) { continue }

                if ($insideAdapters) {
                    $storageTechnologySeen[$domain.Name] = $true
                    break
                }

                $failures.Add(("Storage technology above the adapter layer in " +
                    "$($module.Path):${lineNumber}: $($line.Trim()). Move it into " +
                    "$($domain.Adapters) and speak domain records across the port.")) | Out-Null
                break
            }
        }
    }

    foreach ($domain in $domains) {
        if (-not $storageTechnologySeen[$domain.Name]) {
            $failures.Add(("The storage-technology check matched nothing inside " +
                "$($domain.Adapters), so its patterns may no longer match real " +
                "storage code. Update the check, do not delete it.")) | Out-Null
        }
    }

    #    configuration is read-only at runtime, so no module that resolves a
    #    path inside a shipped root may also hold a write-capable call.
    if (-not (Test-Path -LiteralPath $shippedCatalogRoot -PathType Container)) {
        $failures.Add("Missing shipped template configuration root: $shippedCatalogRoot") | Out-Null
    }
    elseif (-not (Get-ChildItem -LiteralPath $shippedCatalogRoot -Filter "*.yaml" -File)) {
        $failures.Add("$shippedCatalogRoot ships no template document") | Out-Null
    }

    if (-not (Test-Path -LiteralPath $shippedSiteRoot -PathType Container)) {

        $failures.Add(("$shippedSiteRoot ships a site document. M1 ships zero " +
            "canonical sites: every site in the product is one a user created.")) | Out-Null
    }

    # ship empty. T017 has no scenario creation flow, so without a tracked

    # checkout and the surface would have nothing to inspect. The asymmetry is

    if (-not (Test-Path -LiteralPath $shippedScenarioRoot -PathType Container)) {
        $failures.Add("Missing shipped scenario configuration root: $shippedScenarioRoot") | Out-Null
    }
    elseif (-not (Get-ChildItem -LiteralPath $shippedScenarioRoot -Filter "*.yaml" -File)) {
        $failures.Add(("$shippedScenarioRoot ships no scenario definition. The " +
            "product has no scenario creation flow, so a fresh checkout would " +
            "have no scenario to inspect at all.")) | Out-Null
    }

    # Each named reference must be found somewhere, so that adding a shipped
    # root without wiring it in here cannot leave it unprotected.
    $shippedRootReferences = @(

        "SHIPPED_SITE_TEMPLATE_ROOT",
        "SHIPPED_SITE_ROOT",
        "SHIPPED_SCENARIO_ROOT"

    $shippedRootReference = ($shippedRootReferences -join "|")

        '\.write_bytes\(',
        '\.mkdir\(',
        '\.touch\(',
        '\.unlink\(',
        '\.rmdir\(',
        '(?:^|\s)os\.(?:remove|unlink|replace|rename|makedirs|mkdir)\(',

    $shippedRootReferencesSeen = @{}
    foreach ($reference in $shippedRootReferences) { $shippedRootReferencesSeen[$reference] = $false }

    foreach ($module in $backendModules) {
        $namesShippedRoot = $false
        foreach ($line in $module.Lines) {
            foreach ($reference in $shippedRootReferences) {

                }

        $lineNumber = 0
        foreach ($line in $module.Lines) {
            $lineNumber++
            foreach ($pattern in $writeCapable) {
                if ($line -match $pattern) {
                    $failures.Add(("Write-capable call in a module that resolves a " +
                        "shipped configuration root, $($module.Path):${lineNumber}: " +
                        "$($line.Trim()). Shipped configuration is read-only at runtime.")) | Out-Null
                    break
                }
            }
        }
    }

    foreach ($reference in $shippedRootReferences) {
        if (-not $shippedRootReferencesSeen[$reference]) {

                "shipped-root write check is vacuous for it. Update the check, " +
                "do not delete it.")) | Out-Null
        }
    }

    #
    #    T006 made the product able to write configuration for the first time.
    #    That is one capability in one module, and this check is what keeps it
    #    that way: a write-capable call anywhere else in the backend is a
    #    second write path that no port, no composition root, and no atomicity
    #    guarantee covers.
    #
    #    The scenario domain has no writer at all, so this rule is also what
    #    holds "T017 cannot write a scenario": a write appearing in any
    #    scenario module fails here, because no scenario module is on the
    #    allowlist.
    #

    #    confines to the adapter layer.
    $writeCall = @(
        '\.write_text\(',
        '\.write_bytes\(',
        '\.mkdir\(',
        '\.touch\(',
        '\.unlink\(',
        '\.rmdir\(',
        '(?:^|\s)os\.(?:remove|unlink|replace|rename|makedirs|mkdir|open|write|truncate)\(',
        '(?:^|\s)shutil\.',
        '(?:^|\s)tempfile\.'
    )
    $writers = @($domains | Where-Object { $null -ne $_.Writer })
    $writerModules = @($writers | ForEach-Object { $_.Writer })
    $writeCallsByWriter = @{}
    foreach ($writer in $writerModules) { $writeCallsByWriter[$writer] = 0 }

    if ($writerModules.Count -eq 0) {
        $failures.Add(("No configuration domain declares a writer module, so the " +
            "single-write-path check has nothing to anchor on. Update the " +
            "check, do not delete it.")) | Out-Null
    }

    foreach ($module in $backendModules) {
        $lineNumber = 0
        foreach ($line in $module.Lines) {
            $lineNumber++
            foreach ($pattern in $writeCall) {
                if ($line -notmatch $pattern) { continue }

                    $writeCallsByWriter[$module.Path]++
                    break

                    "$($module.Path):${lineNumber}: $($line.Trim()). " +
                    "Configuration is written only by " +
                    "$($writerModules -join ', '), through its port.")) | Out-Null
                break
            }
        }
    }

                "Update the check, do not delete it.")) | Out-Null
        }

    # 5. Each writable user store root has exactly one owner.
    #
    #    "Outside the shipped configuration roots" is only checkable if a root
    #    is declared in one place. Two declarations mean two answers to where
    #    user data lives, and the .gitignore check below would then be covering
    #    whichever one it happened to find.
    #    A domain may own more than one writable root (`ExtraUserRoots`); each

    $userRoots = @(foreach ($domain in $domains) {

            @{ Name = $domain.Name; Var = $domain.UserRootVar; Owner = $domain.UserRootOwner }
        }
        foreach ($extra in @($domain.ExtraUserRoots)) {
            if ($null -eq $extra) { continue }
            @{ Name = "$($domain.Name) ($($extra.Var))"; Var = $extra.Var; Owner = $extra.Owner }
        }

        $userStoreOwners = @()
        $userStoreRootSegment = $null

            foreach ($line in $module.Lines) {
                if ($line -notmatch $userStoreDeclaration) { continue }
                $userStoreOwners += $module.Path
                if ($line -match "$($root.Var)\s*=\s*REPO_ROOT\s*/\s*""([^""]+)""") {
                    $userStoreRootSegment = $Matches[1]
                }
                break
            }
        }

        if ($userStoreOwners.Count -eq 0) {
            $failures.Add(("No backend module declares $($root.Var), so the " +
                "writable $($root.Name) store has no owned configuration point " +
                "and the gitignore check below is vacuous for it.")) | Out-Null
            continue
        }
        elseif ($userStoreOwners.Count -gt 1) {
            $failures.Add(("$($root.Var) is declared in " +
                "$($userStoreOwners -join ', '). A writable store root must have " +
                "exactly one owner.")) | Out-Null

            $failures.Add(("$($root.Var) is declared in $($userStoreOwners[0]). " +
                "It belongs to $($root.Owner), the adapter that owns it.")) | Out-Null
        }

        #    gitignored. User-authored configuration is user data, not shipped
        #    configuration. If it were tracked, a developer's demo site or
        #    scenario would ship to everyone and the shipped/user split would
        #    exist only in the code.
        if ($null -eq $userStoreRootSegment) {
            $failures.Add(("$($root.Var) is not declared as a path under the " +
                "repository root, so the gitignore check cannot resolve it.")) | Out-Null
            continue

        }

        '\b(?:full|unsafe)_load(?:_all)?\s*\(',
        '\bload_all\s*\(',
        'yaml\.(?:Safe|Full|Unsafe|Base)?Loader\b',
        'from\s+yaml\s+import\s+.*\b(?:SafeLoader|FullLoader|UnsafeLoader|BaseLoader|Loader)\b',
        'Loader\s*=\s*(?!CSafeLoader\b)\w',

    )
    $cImportSeen = $false
    $cLoadSeen = 0

    foreach ($module in $backendModules) {

                    "are loaded only by yaml.load(text, Loader=CSafeLoader) in " +
                    "$runDocuments, with no fallback " +
                    "(D-2026-09-29-run-store-libyaml).")) | Out-Null
                break

simulated instant produce the same id with (usually) different content - a real
collision that T027's Commit or ingestion must decide about (refuse, scope by
commit, or treat as a conflicting report). Not decided here because nothing
crosses a stage yet.

### Interval envelopes and typed unavailability are proved on fixtures only

The shipped allowlist is the fuel level sensor, a state signal that always has a
value, so the shipped run exercises neither `INTERVAL_MEAN` nor `UNAVAILABLE`.
Both are proved by `simulator/tests/test_gateway_publication.py`. T026's
allowlist extension is where they first meet a real run.

### A stage is rewritten whole on every step

`JsonSourceStages.admit` re-reads and rewrites the stage, and the host
republishes the whole series every step: quadratic per run. About 110 KB and
150 envelopes at completion today. An append-only format belongs with T026's
larger allowlist if it matters.

### Release eligibility rests on a publication watermark, not a seal

Corrected in the T023 fix round. This entry first said write order made
eligibility honest; the independent review (R1) showed it did not - a failed
final stage write with the process alive, and a publication refusal caught in
`_stage`, both read as ELIGIBLE. The stage now records `published_through`
against `boundaries_total`, advanced only by a successful write, and a short
watermark blocks release (`STAGING_INCOMPLETE`). What remains carried: the
watermark proves publication through the run's end, not that the stage is
sealed against later change. Sealing is Commit's (T027).

### Some corrupted stages answer HTTP 500 rather than STAGE_UNREADABLE (review R2)

`host/source_stages.py` decodes UTF-8 outside the `StageUnreadable` wrapper, and
`source_envelope._exact_value` calls `Fraction(value)` without translating a
zero denominator, which `parse_stage_text` does not catch. A stage replaced by
byte `0xff`, and one whose envelope value is `"1/0"`, both return HTTP 500 from
the stage route instead of `STAGE_UNREADABLE` / `INTEGRITY_FAILURE` (reproduced
again after the fix round). Fails closed - the frontend shows the stage as
unavailable, never as content - but loses the integrity diagnosis. Carried as a
localized exception-translation gap: widen the negative corpus and translate
both when parser robustness is next touched.

### Identifier and unit validation accept a trailing newline (review R3)

`_IDENTIFIER` and `_UNIT` in `source_envelope.py` are anchored with `$` and
applied with `match`, and Python's `$` matches before a final newline. An
otherwise valid envelope with device id `"fuel-level-sensor\n"` and a correctly
recomputed message id is accepted by `parse_source_envelope`. Narrow against
criterion 4; the shipped allowlist does not admit that id and generated
identities are unaffected. Fix with `fullmatch` (or `\Z`) for both patterns and
a trailing-newline negative case.

### The stage's integrity digest is redundant with its canonical-form check

A guard probe removed the digest comparison and every damage case was still
refused, by the final check that re-renders the whole text including a
recomputed digest. Only the REASON changed, which a test now asserts. Harmless
duplication; a later reader simplifying it should keep one of the two and the
reason assertion.

### Stage selection buttons scale with the stage

The inspector renders one "Show envelope N" button per envelope (154 at the end
of the browser run). Utilitarian by instruction; a later slice with thousands of
envelopes needs paging, not polish now.

## Carried from T024

### The controller decides once per step, at T

The controller's request is made from the view at T and holds as a ceiling
across the step, even when the step is split into segments because a forcing
window starts or ends inside it. A demand rise mid-step can therefore leave
load unserved that a re-deciding controller would have served. Deterministic
and stated in `resolver-is-a-declared-cascade`; the shipped scenarios align
every window to the step grid, so they never meet it.

*What would change the answer:* a scenario with off-grid demand windows that
the owner reads as wrong, or T025's generator start logic needing sub-step
decisions.

### "Battery first" in the source priority means the controller asks for the whole demand

The Implementer's reading of a source priority placing the battery ahead of PV:
the controller requests the whole demand from the battery and PV serves what
the battery cannot; PV surplus during battery discharge is curtailed, because
the battery cannot charge while it discharges. Physically coherent and tested,
and a domain choice nobody else made. The shipped template puts PV first.

*What would change the answer:* the owner's hands-on review, or T025 adding
the generator to the same list.

### One PV array, one inverter, one battery and one PCS

The daytime model relates exactly one of each (`TOPOLOGY_INCONSISTENT`
otherwise), like the fuel model's one tank and one generator. Loads are the
first relation of many. Two batteries resolve and freeze independently at
setup and then refuse to execute.

### The kernel still imports the fuel pack as its default model

The new dependency guard tolerates `packs.fuel` in the kernel and forbids any
other pack. Removing the default is a refactor across every fuel caller.

### Electrical observations are generated, not published

Publication profile 3 declares the electrical reporting paths and the transform
generates their readings; the gateway allowlist is still fuel-only, so a Kobo
Draft stages no envelope. T026 extends the allowlist.

### The screen approximates exact ratios

A state of charge after a 95 % efficient conversion is a ratio such as
`965/19`. The Lab shows it to two decimals marked approximate, with the exact
text in the title. The wire and the artifact stay exact.

### Priority lists cannot change during a run

Only the battery reserve has a scenario override in T024; the two priority
lists are baseline-only and the Lab says so.

### Layout evidence: one CDP hang on the first attempt

The first `tools/layout-evidence.mjs` run of this slice stopped with "the
browser stopped answering" while stepping the fuel Draft (no step request ever
reached the server); the immediate re-run passed every claim. Each run now adds
five Drafts to `var/runs` (four as before plus the Kobo Draft), and the Kobo
Draft adds one execution artifact and one stage.

# Seams: Configuration persistence port, and Shipped versus user-authored
# configuration.
#
# These exist so that replacing a store stays one new adapter module plus one
# composition change, and so that shipped canonical configuration cannot
# acquire a write path by accident.
#
#   - adapters are imported only by their own domain's composition module or
#     by a sibling adapter in the same layer
#   - no storage technology above the adapter layer, in any configuration
#     domain
#   - shipped configuration roots hold no write-capable call, the shipped Site
#     store ships empty, and the shipped scenario store ships the definition
#     the catalog needs
#   - configuration is written only by the user-store adapter
#   - each writable user store root has one owner and is gitignored
#
# T017 adds a second configuration domain, so the rules below are stated once
# and applied per domain rather than written out twice. Two copies would drift,
# and a seam enforced for Sites and forgotten for scenarios is the same as a
# seam that is not enforced: the scenario port would leak the first time
# somebody reached past it.
#
# T019 registers a third domain, and it is deliberately not configuration: a
# SimulationRun is a record this installation produced, not a document
# somebody authored. It is registered here anyway because the persistence
# seam it needs is exactly this one - a port, one composition module, one
# adapter layer, one write path, one owned root outside version control - and
# the guard caught the run store the moment it appeared, which is the whole
# point of the "resolves outside every known domain" failure below. A second
# copy of these rules for runs would be the drift this file was written to
# avoid.
#
# Test files are exempt from the scans below for the same reason they are
# exempt elsewhere: a test must be able to reach an adapter directly in order
# to prove what the adapter does.
#
# Do not weaken the checks below to make a task pass.

reports `"skipped": true` and exits 0, and Task Scheduler's "Do not start a new instance" hides it further. The
