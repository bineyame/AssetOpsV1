## 1. W2-00: ordinary source-to-evidence format

### W2-00 implementation rulings (`D-2026-10-17-w2-00-answers`)

1. **Event equality.** In `source_envelope_v4.py`, define `event_identity_sha256` as SHA-256 of UTF-8 canonical JSON with exactly three keys: `source` (the complete v4 source object), `timing` (`source_time,interval_start,interval_end` only), and `payload` (the complete v4 payload). Compute it from the stored canonical `envelope_text` on collision reread; add no column. Exclude `schema,message,mapping,timing.published_at`, batch and publication metadata. The existing `envelope_sha256` remains the full canonical text digest for same-message comparison. For an existing event key, equal event identity is `DUPLICATE` with its first accepted ID even when message, mapping or publication time differs; unequal identity is `EVENT_ID_CONFLICT`/`CONFLICT`. `EVENT_ID_CONFLICT` records `field='payload.event_id'`; `SESSION_ID_CONFLICT` records `field='payload.session_id'`. Message collision always wins. A distinct START at the same scoped connector/session is `SESSION_ID_CONFLICT` after the event-key check. `postgres_evidence_ledger.py` uses a per-ordinal savepoint for event/START unique violations, then rereads message, event, START in that order; unrelated integrity errors propagate. Tests change only transport fields versus source time, outcome and payload, and cover both double collisions and a race loser.
2. **Delta storage and refusals.** In migration `0020`, the CHECK predicate is `measurement='INTERVAL_DELTA'`, never `conversion_kind='INTERVAL_DELTA'`: conversion stays the binding's `IDENTITY` (or another explicitly supported conversion), and `INTERVAL_DELTA` is the v4 measurement kind. Use the exact delta and ID-pair CHECKs below (names `accepted_evidence_ev_delta_shape`, `accepted_evidence_measurement_ids`). For every non-delta MEASUREMENT, both IDs are null in `0020`; W2-05 may extend that rule only with a reviewed migration. In `source_envelope_v4.py`, wrong delta unit yields `EV_DELTA_UNIT_INVALID` at `payload.unit`, absent/nonpositive/misaligned bounds yields `EV_DELTA_INTERVAL_INVALID` at `timing.interval_start` or `timing.interval_end`, and negative or unavailable delta yields `EV_DELTA_VALUE_INVALID` at `payload.value`. Missing/null/invalid session or connector ID yields `CORRELATION_INVALID` at its payload field, including an absent key as a specific exception to generic `MISSING_FIELD`. A present but wrong bound connector yields `EV_CONNECTOR_MISMATCH` at `payload.connector_id` in `ledger.py`. All five are ordinal `REJECTED`, null conflict reference. Existing v3 parser and shared measurement allowlist stay unchanged.

   `CHECK (measurement IS DISTINCT FROM 'INTERVAL_DELTA' OR (family = 'MEASUREMENT' AND original_unit = 'kWh' AND normalized_unit = 'kWh' AND original_value_text IS NOT NULL AND normalized_value_text IS NOT NULL AND original_value_text ~ '^(0|[1-9][0-9]*)(\.[0-9]*[1-9])?$' AND normalized_value_text ~ '^(0|[1-9][0-9]*)(\.[0-9]*[1-9])?$' AND interval_start IS NOT NULL AND interval_end IS NOT NULL AND interval_start < interval_end AND interval_end = source_time AND session_id IS NOT NULL AND connector_id IS NOT NULL))`

   `CHECK (family <> 'MEASUREMENT' OR ((measurement = 'INTERVAL_DELTA' AND session_id IS NOT NULL AND connector_id IS NOT NULL) OR (measurement IS DISTINCT FROM 'INTERVAL_DELTA' AND session_id IS NULL AND connector_id IS NULL)))`
3. **Batch admission.** `ingestion_batch_v2.py` retains strict v3 parsing for ordinary schema-3 texts. For a text declaring schema 4, or schema 3 with `payload.family='EVENT'` or `payload.measurement='INTERVAL_DELTA'`, its header-only reader validates the JSON object and the exact `message` identity/order and `source`/`mapping` fields needed for Batch V2 homogeneity and batch ID; it does not validate payload, timing, schema version or canonical inner-envelope bytes. `ledger.py` dispatches each stored text by stated schema and records parser refusals per ordinal; schema-3 v4-only kinds yield `SCHEMA_UNSUPPORTED` at `payload.family` or `payload.measurement`. Bad/missing header fields that prevent batch identity or scope checks remain whole-batch `INVALID_ENVELOPE` before a ledger ordinal exists. Once a valid header exists, malformed payload, timing and noncanonical text are ordinal rejections with `evidence_rejection` and `ingestion_disposition`; preserve the valid header's message ID on `Rejected`. Tests prove a mixed valid/invalid v4 batch completes with one disposition per ordinal and that v3 golden batch/receipt bytes remain fixed.
4. **Binding and profile home.** Extend only the immutable `assetops.acquisition-snapshot/1` `bindings` rows: optional `allowed_record_kinds: string[]`, `allowed_outcomes: {record_kind:string[]}`, `requires_correlation: boolean`, `requires_session: boolean`, `allowed_units: string[]`. `binding_alignment.py` serializes these when supplied; `gateway/snapshot.py` admits exactly these optional keys; `ledger.py` `BindingBasis` reads absent keys as `None` for v3. A v4 binding requires all five explicitly (measurement rows use `[]`, `{}`, `false`, `false`, and their one allowed unit; event rows use their closed kinds/outcomes, `true`, session requirement, and `[]` except manual-log `['degC']`). For EV session rows `requires_session=true`; connector fault/clear rows permit null session with `requires_session=false`. In `source_envelope_v4.py`, `V4_CHANNEL_MAPPINGS` is the closed `(device_id,signal_id)` table in §4 plus the two reserved EV tuples, versioned as `simulator-lab-gateway-cold/1` and schema 4. S2 checks exact tuple, family, kind, outcome, role, unit and required correlation/session against both the closed table and pinned row; missing or divergent v4 mapping metadata yields ordinal `MAPPING_INCOMPATIBLE` at `mapping`, and a unit mismatch yields `UNIT_INCOMPATIBLE` at `payload.unit`. W2-00 owns the parser, table and snapshot compatibility reader. W2-01 publishes cold binding rows; W2-02 registers and emits the new cold runtime publication profile. Those runtime producer/profile steps are an explicit W2-00 deviation deferred to W2-02. W2-05b registers/emits its separately pinned EV profile; existing profiles never switch in place.
5. **Tenant and recompute boundaries.** The authenticated principal's tenant/Site selects the binding set before any ordinal decision; a binding registered only in another tenant yields whole-batch `CONFIGURATION_UNREGISTERED` at `mapping` with no accepted evidence or ordinal disposition. Once scope and header pass, per-ordinal parser/binding refusals are persisted. Keep the existing `dispatch` recompute job only for accepted v3 measurements. W2-00 enqueues no job for v4 records: no current worker understands cold or EV inputs. W2-03 adds `cold_chain` enqueue/worker for accepted cold roles/events; W2-05 adds the EV domain under its own reviewed contract. Test that v4 acceptance creates no dispatch job and v3 still does.
6. **Read ownership and proof.** Extend the Postgres route only: `evidence_api.py` validates `family=MEASUREMENT|EVENT` and `kind` from the v4 event allowlist (bad values 422), then passes both through `ledger_reads.py` to `postgres_evidence_ledger.py` `records_page`; `kind` filters `record_kind`, including an empty result when paired with `family=MEASUREMENT`. Include the seven named fields in `record_payload`, null on old v3 rows, and in Postgres list/detail queries. The legacy file-backed read route retains its current contract and rejects either new filter with 422 `FILTER_UNSUPPORTED` rather than silently ignoring it. Update both receipt conflict-count SQL locations and the Postgres rejection-list conflict split to include `MESSAGE_CONFLICT,EVENT_ID_CONFLICT,SESSION_ID_CONFLICT`; freeze a `MESSAGE_CONFLICT` Receipt V2 byte fixture before the change. W2-00 tests use real private Postgres `*_test` databases and may patch `basis_from_snapshot` with v4 `BindingBasis` entries reusing registered binding/asset IDs until W2-01/02 can publish them; this is test-only, never runtime admission evidence. Test snapshot optional-key parsing, all ordinal codes, old-null/read filters, tenant refusal, receipt bytes/counts and rule-8 probes on the final revision.

Two episodes split only after two stable in-band points (excursion) or a new start request (backup). If late evidence invalidates the anchor, append `NO_LONGER_SUPPORTED` and create a new episode with `split_from` relation; never rewrite old. Separate excursion and start-response Findings can cite the same event but share one `overlap_group` for money.
