Every accepted-evidence INSERT, including EVENT and EV START, retains `ON CONFLICT ON CONSTRAINT accepted_evidence_message_unique DO NOTHING`. For each ordinal, the ledger opens a savepoint around that INSERT. On a message-target `DO NOTHING` or a unique violation of `accepted_event_identity_unique` or `accepted_ev_start_unique`, it rolls back to the savepoint where needed and rereads under the same batch transaction in fixed order: message key, then event identity, then EV START identity. A matching message SHA returns `DUPLICATE`; a changed message SHA returns `MESSAGE_CONFLICT` even when the event or START key also collides. If the message key is free, a matching event SHA returns `DUPLICATE` and a changed event SHA returns `EVENT_ID_CONFLICT`; only if neither key matches does a distinct START collision return `SESSION_ID_CONFLICT`. Thus message wins a double collision, then event wins over session. Each conflict references the first accepted row for its winning key. A non-unique or unlisted unique violation propagates; never convert it to a typed conflict. Unique indexes arbitrate races; the reread is not an application precheck.

## 4. W2-02 causal producer and publication

Add `cold-thermal/1` `ModelSpec` and `cold-publication/1`; resolve frozen profile identity in `host/execution_adapter.py:113-140`, `host/lab_execution.py:1978-2015` and `simulator/assetops_simulator/kernel/execute.py:90-105` through a closed registry, with fuel/mini-grid identities preserved. **Time and state.** Fixed 1-minute UTC step; all updates use exact rationals/decimal text and a defined end-of-step publication order. State: chamber air temperature `T` degC, controller demand, compressor `OFF|STARTING|RUNNING|FAILED`, grid/backup bus energized flags, generator `STOPPED|STARTING|RUNNING|FAILED`, transfer position `GRID|BACKUP|OPEN`, door `OPEN|CLOSED`, probe `OK|FAILED`. Private forcing: ambient `Ta`, door schedule, grid loss, generator failure, probe failure; private truth never serializes into a product envelope. Initial `T=3°C`, `Ta=20°C`, door closed, compressor off, grid and bus on, generator stopped, transfer grid, probe OK. Per minute, `heat_kWh = (heat_leak_kW_per_C*(Ta-T) + door_open*door_heat_kWh*60)*1/60`; `cool_kWh = compressor_running_and_bus_powered*cooling_kW*1/60`; `T_next=T+(heat_kWh-cool_kWh)/thermal_capacity_kWh_per_C`. Defaults: thermal capacity `1.2 kWh/degC`, leak `0.08 kW/degC`, door heat `0.02 kWh/min` (stored as `1.2 kW` equivalent while open), cooling `3 kW`, compressor start delay 1 minute, generator start delay 2 minutes, transfer delay 1 minute, start timeout 5 minutes, control on `T>=4°C`, off `T<=2°C`, policy `[2,4]°C`, hysteresis 0.2°C, probe bound ±0.1°C. Clamp no state: fail run if `T` outside `[-40,60]°C`, energy residual nonzero, negative capacity/power, or impossible transition. The standalone cold pack owns its generator and bus power port; W2-02 does not compose with mini-grid.

Grid loss opens transfer and deenergizes compressor bus; controller emits `START_REQUEST` only if backup enabled, generator reaches RUNNING after delay unless failed, transfer closes to BACKUP after delay if generator power exists, and compressor restarts after its own delay if controller still demands cooling. Failed start emits `START_RESULT/FAILED` at timeout; successful start emits `START_RESULT/SUCCEEDED` when running. Transfer result is emitted only if a position sensor is configured; absence stays absence. Door events are sensor transitions; door opening adds heat only while open. Probe failure emits one `UNAVAILABLE` reading with reason `SENSOR_FAILURE` if the profile publishes it, then no numeric sample; reporting-path loss emits no envelope. Device measurement is `T + fixed observation bias` (default 0), rounded to 0.1°C by half-even rule; no private cause field. Controller and power events use observed public transitions and stable correlation ID.

Each row lists the entire non-default forcing, ordered by `(time,kind,asset)`; observation faults occur after a valid world transition and cannot bypass `PhysicallyUnacceptable` guards.

## 5. W2-03 assessment, episodes and Findings

Analytic IDs `cold-excursion/1`, `cold-start-response/1`. Input selection is accepted evidence only, fixed half-open `[from,to)`, explicit `known_at` cutoff on server `received_at`/decision time, effective Foundation/binding versions, and source gate. Include exact accepted IDs and SHA, configuration IDs, model version, window/cutoff in sorted basis SHA. A reading is usable only if GOOD, calibrated, mapped to the room, and clock-attested; SUSPECT is context. Expected five-minute points: coverage = usable distinct scheduled timestamps / scheduled timestamps, capped at 1; `>=0.8` needed for an interval claim, but no gap >10 minutes may be bridged. Latest point must be <=10 minutes old at read time for a **current** state; historical window conclusion can remain bounded with explicit as-of. A failed worker or newer accepted relevant evidence marks prior projection `PENDING_RECOMPUTE` until a new immutable revision is written.

Excursion begins after two consecutive GOOD observations above upper band (or below lower band) at least 5 minutes apart; return requires two consecutive observations inside band by at least 0.2°C. The start is bounded by `[last in-band, first out-of-band]`; return by `[last out-of-band, first stable in-band]`; duration low = max(0, earliest return - latest start), high = latest return - earliest start, computed only across continuously covered spans. Initial out-of-band sample with no prior in-band gives unknown start; window end without return gives open episode and no finite high. `degree_minutes` bounds use observed rectangles only between adjacent usable samples <=10 minutes apart: low uses min adjacent exceedance, high max adjacent exceedance times interval minutes; add no unobserved gap area. Peak is the maximum **observed** value. An exposure Finding requires 15-minute lower duration and coverage >=0.8; otherwise `POSSIBLE` or `UNKNOWN`, never “no excursion” from missing samples. In-band fully covered is `NO_EXCURSION_OBSERVED` scoped to window, not equipment health.

Start chain groups by accepted `correlation_id`, generator asset and outage window. Require ordered grid LOST → START_REQUEST → START_RESULT → generator RUNNING/FAILED → optional TRANSFER_RESULT → bus POWERED/UNPOWERED → compressor state → probe response; tolerance is source-clock bound <=30 seconds for event ordering, with timeout from effective Foundation (default 5 minutes). A failed automatic start is `OBSERVED_FAILURE` only with request, explicit failed result or timeout plus complete generator state coverage through timeout, and no contradictory success; missing request/result/state is `UNKNOWN_STEP`. A transfer-position claim requires accepted transfer event; bus energization alone proves only bus state. Cooling failure cannot be assigned from temperature alone. Emit claim levels `OBSERVED`, `BOUNDED`, `POSSIBLE`, `UNKNOWN`, `CONTRADICTORY`; explanations list exact missing/excluded records and claim ceiling.

Episode key = SHA-256 of `(tenant,site,kind,subject room/generator asset,first accepted qualifying crossing/request event ID)`; retain anchor when late evidence adjusts boundaries, append `cold_episode_revision` and corresponding FindingRevision with transition `SUPPORT_CHANGED` or `BASIS_REFRESHED`. Two episodes split only after two stable in-band points (excursion) or a new start request (backup). If late evidence invalidates the anchor, append `NO_LONGER_SUPPORTED` and create a new episode with `split_from` relation; never rewrite old. Separate excursion and start-response Findings can cite the same event but share one `overlap_group` for money. Use existing S4-05 exact accepted-ID provenance and source classification (`backend/migrations/versions/0009_finding_store.py:33-87`; `.ai/DECISIONS.md:5-15`).
