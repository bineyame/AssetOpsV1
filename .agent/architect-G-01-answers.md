**C5 — split the bundled gateway sentence in G-02.** Uptime trend, expected-versus-delivered completeness and signal strength have different producers, tests and closure conditions. Replace `GATEWAY_NOT_AVAILABLE_YET` with three distinct visible missing-state elements, each with its own gap ID and unique placement (for example `readiness.gateway.uptime`, `readiness.gateway.completeness`, `readiness.gateway.signal-strength`); preserve the separate firmware gap. Do not make one rendered element carry several IDs or reuse a placement: the one-element/one-placement rule is what makes the corrected orphan scan auditable. A gap ID may recur at another *registered* placement only when the claim is genuinely the same. This is a **G-02 carry**, not a G-01 merge blocker.

**C7 — widen the scan selectively in G-02.** Add exact absent-capability cues such as `not tracked yet` and the commissioning-specific `commissioning confirmation not recorded`; audit their current product occurrences and add mutation fixtures proving that newly untagged instances fail. Keep generic `not recorded`, `unavailable` and `no results` out of the global phrase set: those often describe an empty window or failed read of an existing capability. If another G batch introduces a new euphemism for a missing capability, extend the reviewed phrase set or use a scoped, documented opt-in with a failing mutation fixture; do not silently baseline it. This is a **G-02 guard carry** and requires independent review because it changes detection behavior, not a pre-walkthrough G-01 change.

The owner decides only whether the visible firmware missing-state treatment is acceptable after the real 1440/390 evidence is available. Q1–Q4, C5 and C7 need no additional owner product choice.
