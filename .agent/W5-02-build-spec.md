## Frozen model, migration and selection

W4 `work/model.py` defines INC/WR roots, append-only events, performed records and `UNVERIFIED` outcome. `work/site_index.py` selects cases by root occurrence/creation in `[from,to)` and exact `known_at` on one snapshot; its list wire is `site-work-index-1`. `work_api.py` already mounts `/api/sites/{site_code}/work/incidents|maintenance` and the case commands. W1 `SiteWorkActions.tsx` and `SiteAction.tsx` are presentation/route patterns only: `backend/migrations/versions/0016_action_store.py` requires a battery asset, reserve-trial rule and 5-point SOC change, so a cold Action cannot be inserted there. S6 verification similarly requires `reserve-trial-verification-1`. W5-01 supplies selected cold evidence and Finding revisions. K1 adds a domain Action root under the same public Action code namespace and URL, while preserving W4 Incident/Maintenance identities. It never writes a fake battery Action.

**K1 migration.** Create `backend/migrations/versions/0033_w5_cold_work.py`, `revision='0033_w5_cold_work'`, `down_revision='0032_w5_cold_scenarios'`; abort unless that exact parent has merged. Add append-only `domain_action`: `id uuid PK`, `tenant_id uuid`, `site_id uuid`, `action_no bigint`, `action_code text`, `domain text CHECK(domain='COLDCHAIN')`, `origin_finding_id uuid`, `origin_finding_revision_id uuid`, `title text`, `owner_label text NULL`, `due_at timestamptz NULL`, `raised_at timestamptz`, `recorded_at timestamptz DEFAULT clock_timestamp()`, `actor_kind text`, `actor_id text`, `idempotency_key text`, `payload_sha256 text`; scoped Site/Finding/revision FKs and unique `(tenant_id,action_code)`, `(action_no)`, `(site_id,idempotency_key)`. Allocate `action_no` from the existing `action_code_seq` in `0016_action_store.py` in the writer transaction; a DB trigger rejects a code already in the W1 `action` table, and W1's writer must reject a code already in `domain_action` if sequence allocation is ever bypassed. Add append-only `domain_action_intent`: `id uuid PK`, scoped `action_id` FK to `domain_action`, `supersedes_id uuid NULL`, `declared_at`, `recorded_at`, `criteria jsonb`, `basis jsonb`, actor fields, idempotency key and SHA; same-action supersession FK, unique `(action_id,idempotency_key)`/`(supersedes_id)`, partial unique root and `(action_id,recorded_at,id)` index. Add append-only `domain_action_case_link`: scoped `action_id` FK to `domain_action`, scoped `case_id` FK to W4 `work_case`, selected case revision/event IDs, recorded_at and attestation; a case link is explicit, never synthesized from telemetry. Extend the W4 list/detail adapter to expose this relation as an exact Action link with the same `Link` shape, without inserting it into W4's existing `action_links` FK to the battery table. Service validates four criterion keys, IDs and basis. Reuse W4 append-only triggers and rule-8 INSERT-only writer registration. Downgrade refuses nonempty new tables. Intent declares success conditions, not a `VerificationOutcome`; never infer `VERIFIED` from it.

**Command/read wire.** Add `POST /api/sites/{site_code}/domain-work/actions` (SERVICE principal only) to create the domain Action from an exact selected Finding, plus `POST /api/sites/{site_code}/domain-work/actions/{action_id}/intents` and `POST /api/sites/{site_code}/domain-work/actions/{action_id}/case-links`; all use W4 grant/attestation and return 201 or 200 identical retry. Action creation validates `raised_at` as UTC, no later than DB time plus five minutes and no earlier than 30 days before DB time; `recorded_at` is always database time. Action creation body is closed `{domain:'COLDCHAIN',origin_finding_id,origin_finding_revision_id,title,owner_label:null|string,due_at:null|string,raised_at,actor:{kind:'SERVICE',id,attestation},idempotency_key}`; response `{schema_version:'domain-action-1',id,action_code,recorded_at}`. Intent body is closed `{supersedes_id:null|string,declared_at,criteria:[{key,label,required_evidence}],basis:{finding_revision_id,work_case_id,work_record_id:null|string,accepted_evidence_ids:string[]},actor:{kind:'SERVICE',id,attestation},idempotency_key}`. Case-link body names exact `case_id,case_revision_id,case_event_id`, actor and idempotency key. The W4 case is created with `action_links:[]` because its battery-only FK cannot target this root; the separate case-link command then binds the returned exact W4 revision/event. The W4 read adapter unions both link relations without copying a domain row into the battery link table. Intent response `{schema_version:'domain-action-intent-1',intent_id,action_id,recorded_at,selection_token}`. `GET /api/sites/{site_code}/domain-work/actions/{action_id}?known_at=` returns `{schema_version:'domain-action-intent-read-1',site_code,action:{id,action_code,title,owner_label,due_at,raised_at,recorded_at,state:'OPEN'},known_at,status:'CURRENT'|'HISTORICAL'|'PENDING_RECOMPUTE'|'STALE_SOURCE'|'UNKNOWN',intent:{id,recorded_at,criteria,basis}|null,results:[{key,result:'NOT_TESTED'|'NOT_ESTABLISHED'|'PENDING',evidence_ids:string[]}]|null,links:{finding:{label,href|null},work:{label,href|null}},source_provenance,selection_token}`. `intent:null` is a successful missing declaration, not invented results. The caller-connection repeatable-read adapter selects exact Finding, W4 case/record and W5-01 cold evidence. The token hashes tenant/Site, domain Action, raised_at, Finding revision, intent, case/record and cited accepted evidence IDs. Site URLs use stored Site code; `known_at` defaults to DB read time and cannot be future. Domain Action state is `OPEN` throughout this slice because no domain lifecycle event contract is introduced. All other W1 Action routes keep their battery semantics.

**Site Action index.** K1 adds `GET /api/sites/{site_code}/domain-work/action-index?from=&to=&known_at=&limit=&cursor=` as `site-domain-action-index-1`: a union projection of W1 battery Actions and `domain_action` roots for one Site on one repeatable-read snapshot. It never inserts a domain row into W1 `action`. Exhaustive envelope keys: `schema_version,site_code,window:{from,to,bounds},known_at,status,coverage:{state,reason},total_count,rows,next_cursor,selection_token`. Exhaustive row keys: `action_id,action_code,domain,title,owner_label,due_at,raised_at,recorded_at,origin:{finding_id,finding_revision_id,label,href:null|string},state,criterion_summary,links:{action,history:null|string}`. Battery rows retain W1 labels/links and `criterion_summary:null`; domain rows use stored title/owner/due and selected intent; their state is `OPEN`. Membership uses the domain root attested `raised_at` and W1 root `created_at`; order `(membership time desc,action_id asc)`; count is full set before paging; limit 1-100/default 5; cursor binds exact cutoff and full-set fence, returning 409 `WORK_BASIS_CHANGED` after a change. Before K4 mounts domain detail, its canonical Action href resolves to an honest `Action details are being prepared.` panel; K4 replaces that panel. K1 owns the new index adapter and `domain_work_api.py`; it may read but not change W1 `action_index_api.py` semantics.

Refusal order: 401 `UNAUTHENTICATED`, 403 `SITE_SCOPE_FORBIDDEN`, 404 `SITE_NOT_FOUND`, 503 `WORK_STORE_UNAVAILABLE`, then 422 `INVALID_KNOWN_AT`/`DOMAIN_INTENT_INVALID`/`DOMAIN_INTENT_LINK_INVALID`, 404 `ACTION_NOT_FOUND`, 409 `DOMAIN_INTENT_CONFLICT` or `DOMAIN_INTENT_BASIS_CHANGED`. Writes also return 403 `WORK_WRITE_FORBIDDEN` or `WORK_ATTESTATION_INVALID` 422 through W4's gate. A refused read has `intent:null,results:null` and no count. Exact new messages: `The cold Action declaration is incomplete or invalid.`; `The declared Finding or work record is not selected at this site and cutoff.`; `This Action declaration has a newer version; reload it.`; `The selected cold work basis changed; reload the Action.` Existing W4 messages remain literal. A 401/403/503 is never an empty success.

Criteria keys and display order are fixed: `AUTOMATIC_START` / `Automatic start` / `Accepted command followed by successful running status`; `POWER_DELIVERY` / `Power delivery` / `Generator supply reaches the cooling system`; `COOLING_RECOVERY` / `Cooling recovery` / `Temperature recovery within declared test conditions`; `RECURRENCE` / `Recurrence` / `Covered observation window without a qualifying repeat`. K1 validates exactly these keys/labels/required evidence, in this order, and an attested basis; a different declared test becomes a new contract, not free text. For the initial supported replay, result keys are `NOT_TESTED`, `NOT_TESTED`, `NOT_ESTABLISHED`, `PENDING`, respectively. A later accepted observation may make a result more informative only with an explicit reviewed evaluation rule; this slice does not add a pass result.
