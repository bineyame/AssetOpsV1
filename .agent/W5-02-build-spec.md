## W5-02a build rulings (K1 deviations)

1. **`work_record_id`: confirm the builder's table.** In A1, A3 and B3, `work_record_id` means the ID of a W4 `maintenance_record` for the selected MAINTENANCE_REQUEST. There is no `work_record` table; neither `operational_record` nor an arbitrary UUID qualifies. Validate its Site, case, performed record and cutoff in the write transaction. Test: an existing selected WR's `maintenance_record.id` succeeds; an operational-record ID and a maintenance record from another case or Site each return 422 `DOMAIN_INTENT_LINK_INVALID`.
2. **Missing Action and link refusal order: confirm the builder's dependency order.** For each command, apply the authentication/Site/store gate first; then closed-body, path and static shape validation (422 `DOMAIN_INTENT_INVALID`, except a malformed Action path ID uses 404 `ACTION_NOT_FOUND`), then W4 actor authorization/attestation; in the transaction resolve the scoped Action (404 `ACTION_NOT_FOUND`) before any Action-dependent link lookup. Next do advisory-locked idempotency (identical request returns its original response as 200; changed body gets its specified 409), DB-time bounds (422 `DOMAIN_INTENT_INVALID`), selected Finding/case/record/evidence checks (422 `DOMAIN_INTENT_LINK_INVALID` or stale selected basis 409 `DOMAIN_INTENT_BASIS_CHANGED`), chain or duplicate conflicts (409), then insert (201). Thus the general refusal list's 422-before-404 order applies to independent request validation, not to link checks that require an Action. Test: a well-formed request with both an absent Action and invalid link returns 404; the same invalid link against an existing Action returns 422; an invalid closed body returns 422 before Action lookup.
3. **Case-link selection: confirm head revision and latest event.** The request carries explicit `case_id`, `case_revision_id` and `case_event_id` from the selected W4 case at the caller's cutoff. At the command's DB read time, the case must be scoped to the Site and the named revision and event must belong to it. If either is no longer its selected head revision/latest event, return 409 `DOMAIN_INTENT_BASIS_CHANGED` with `The selected cold work basis changed; reload the Action.` A nonexistent, foreign-Site or case-mismatched ID returns 422 `DOMAIN_INTENT_LINK_INVALID`; an identical idempotent retry still returns 200 before reevaluating selection. Test: link the current pair successfully; advance the case revision or append an event and submit the old pair under a new key to get 409; submit an ID from another case to get 422; retry the original key/body after the advance to get 200.
