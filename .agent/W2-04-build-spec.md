## Selection, projection and capability

One `ColdSelection` has `tenant_id,site_id,code,from_at,to_at,known_at,watermark,foundation_revision_ids,binding_revision_ids,assessment_revision_id,finding_revision_ids,source_gate`. `from_at` and `to_at` are UTC and half-open; `known_at` defaults to latest committed disposition watermark captured once at request start. The effective Foundation/binding is selected at each evidence source time (W2-03), with the selected policy at the requested window; conflicting/absent effective revision is an explicit limitation. 31 days maximum. No newer assessment, Finding or consequence may be silently mixed with an older `known_at`. A late accepted report makes the current projection `PENDING_RECOMPUTE` until a new exact assessment and cold consequence both settle. A selected old cutoff is `HISTORICAL`, even when there is no pending work.

`ColdSiteReadService` joins, by exact UUIDs, W2-03 `ColdReadService` output, W2-01 Foundation, S4-05 source/publication links and the cold consequence head. It does not use a display-name join or the latest Finding irrespective of window. Capability claims are exactly `TEMPERATURE_POINT,EXCURSION_BOUNDS,BACKUP_START_RESULT,TRANSFER_POSITION,COOLING_RESPONSE,PRODUCT_EXPOSURE`. Each has `state:SUPPORTED|LIMITED|UNAVAILABLE|CONTRADICTORY`, `required_roles:string[]`, `missing_roles:string[]`, `coverage:{known_points:int,expected_points:int,ratio:decimal}` and `as_of,limitation`. `TEMPERATURE_POINT` requires GOOD calibrated room probe and attested clock; `EXCURSION_BOUNDS` adds policy, two qualifying samples and >=0.8 coverage with no >10-minute bridge; `BACKUP_START_RESULT` requires correlated accepted request/result and the W2-03 causal rules; `TRANSFER_POSITION` needs its own bound transfer report; `COOLING_RESPONSE` needs an accepted compressor state and probe series; `PRODUCT_EXPOSURE` means bounded thermal exposure only and requires an eligible excursion. Contradictory accepted facts give `CONTRADICTORY`, not healthy/failure. Source `contact` and `fact_age` derive from recorded gateway diagnostic/contact plus accepted last fact separately; no source contact becomes equipment condition. Panel 3's “next evidence” is simply a named missing role/link, never a scored recommendation.

Analysis rows are selected accepted public records from the pinned assessment basis and exact links, ordered `(source_time,evidence_id)`, with `evidence_id,kind,source_time,received_at,quality,role,exclusion,source_id,envelope_sha256,assessment_revision_id`; `exclusion` is W2-03's SUPPORT/CONTEXT/EXCLUDED reason or null. Keep a record in the list when excluded, label why, and link to the existing Site Evidence exact record when source gate permits. `claim_rules` lists rule ID `cold-excursion/1` or `cold-start-response/1`, requirement, observed/missing role, coverage and resulting limit, all derived from the selected assessment; no speculative prose rule. Opaque cursor encodes `(source_time,evidence_id)` and selected basis SHA; mismatch returns 409 rather than changing pages.

## Money schema `0023` and rules

Create four new tables (do not widen the mini-grid `financial_consequence_revision`, whose CHECK constrains `POTENTIAL_FUEL_COST`, `fuel-cost-1`, L and priced amount). All UUID references below are composite `(tenant_id,site_id,id)` FKs, including Site, FindingRevision, cold episode revision, assessment revision and accepted evidence. Add scoped unique targets to referenced tables only where `0022` has not already supplied them. All tables have `tenant_id,site_id`; every immutable row has server `created_at`/`finished_at`, with UPDATE/DELETE refusal triggers. Downgrade refuses while any of these rows exist; otherwise drops only W2-04 triggers/tables/indexes.

* `cold_consequence_revision`: `id uuid PK`, `finding_revision_id`, `episode_revision_id`, `assessment_revision_id` UUID NOT NULL; `revision_no int >0`, `prior_revision_id uuid NULL`; `kind` CHECK `PRODUCT_EXPOSURE|RECORDED_REPAIR`; `state` CHECK `UNPRICED|WITHHELD`; `reason` nonempty; `window_start,window_end timestamptz` with start<end; `room_asset_id uuid`; `overlap_group text`; `quantity_unit` CHECK `degC_min|none`; `quantity_low,quantity_high numeric NULL` nonnegative/ordered; `amount_low,amount_high numeric NULL`, `currency char(3) NULL`; `finding_basis_sha256,consequence_basis_sha256 char(64)`, `model_id` CHECK `cold-exposure/1|cold-repair/1`; `source_classification`, `source_gate_sha256 char(64)`, `assumption_revision_ids jsonb` array, `limitation text NULL`. Unique `(finding_revision_id,kind,revision_no)` and `(finding_revision_id,kind,consequence_basis_sha256)`. DB CHECK requires `amount_low IS NULL AND amount_high IS NULL AND currency IS NULL` for every row; a later approved migration must widen this. `RECORDED_REPAIR` is `UNPRICED`, quantity null/`none`, until an exact accepted cost feed and non-overlap rule exist. `PRODUCT_EXPOSURE` may carry nonnegative bounded `degC_min`; if insufficient evidence both bounds null. No zero amount or stock count stands for unknown.
* `cold_consequence_evidence`: `consequence_revision_id,evidence_id,use,reason` with PK `(consequence_revision_id,evidence_id,use)`, `use=SUPPORT|CONTEXT|EXCLUDED` and scoped FKs. Include all exact evidence cited by the pinned Finding/episode basis, no private world keys.
* `cold_consequence_work`: `id uuid PK`, `cause` CHECK `FINDING_REVISION_APPENDED|EPISODE_REVISION_APPENDED|ASSUMPTION_PUBLISHED|SOURCE_GATE_CHANGED`; typed nullable locators for FindingRevision/episode revision/assumption revision/source gate, `window_start,window_end`, `room_asset_id`, `dirty_key_sha256 char(64)`, `enqueued_at`; unique `(tenant_id,site_id,dirty_key_sha256)`. Trigger-only INSERT with `ON CONFLICT DO NOTHING` on that named unique target. A trigger on cold FindingRevision and episode revision enqueues the shared Site/window/room; assumption/source-gate triggers enqueue only overlapping cold scopes. No runtime work insert/status update. Backfill existing W2-03 cold heads once during upgrade, idempotently.
* `cold_consequence_work_attempt`: `id uuid PK`, `work_id` scoped FK, `attempt_no int >0`, `outcome` CHECK `SUCCEEDED|FAILED`, `error_code text NULL`, `consequence_revision_ids jsonb` array, `finished_at`; unique `(work_id,attempt_no)`. Success has no error and exact returned IDs; failure has error and empty IDs. A failed attempt leaves work pending; pending means no successful attempt. Index `(site_id,enqueued_at)` and `(work_id,attempt_no DESC)`.

`overlap_group = 'cold:' + sha256(canonical JSON array [tenant_id,site_id,window_start,window_end,room_asset_id])`. An excursion and backup Finding of the same selected room/window share it; the financial read groups `PRODUCT_EXPOSURE` by this key and takes the single selected excursion exposure basis, never sums both. The start-response Finding may carry a `WITHHELD` context consequence with the same key but zero *counted* exposure entries, not a numeric zero. No cross-window summing without an explicit disjoint-window contract.

The source-gate event is an appended `batch_publication_link` to a previously accepted cold batch, if one exists; its trigger selects only cold heads whose linked accepted IDs use that batch and enqueues `SOURCE_GATE_CHANGED` inside the link transaction. An initial link before acceptance has no heads and creates no money work; later W2-03 Finding/episode append enqueues it. `evidence_publication` is immutable and a new unrelated publication never dirties an existing cold basis. `ASSUMPTION_PUBLISHED` watches `financial_assumption_revision` for only the three reserved cold keys; the current publisher refuses them, so this arm has no W2 fixture rows and future publication requires its own approval/migration. Each trigger derives the same canonical dirty key from `(cause,locator,tenant_id,site_id,window_start,window_end,room_asset_id)` and takes a Site advisory transaction lock before selecting heads, following `0012_evidence_consequence_work.py`'s enqueue lock pattern. No trigger on an accepted disposition bypasses W2-03 assessment: it waits for the new exact cold Finding/episode revision.

`cold-exposure/1` derives observed rectangle degree-minute bounds only from W2-03's persisted episode bounds/accepted evidence, not a continuous curve. A bounded positive or zero technical quantity is allowed only when W2-03 actually proved it; missing-probe/contradictory has null quantity. `PRODUCT_EXPOSURE` is unpriced for sound technical bounds because no `cold_stock_quantity`, `cold_stock_unit_value`, reviewed `cold_exposure_rule`, product/currency binding or source-gated valuation exists. These are **reserved future scenario keys**, displayed as missing, not publishable via the diesel-price publisher. Product value/currency and EV tariff would be explicitly authored scenario assumptions and still would not prove sales, collections, spoilage or lost revenue. Recorded repair needs an accepted exact cost/currency/work record; none of the six replay cases has one. Mixed/unknown source, closed S4-05 gate, stale/pending assessment, incomplete period or contradictory evidence yields `WITHHELD` and null amount. LR current-money gate also refuses a current money claim from historical/pending basis. `exact_basis` returns selected Finding/episode/assessment UUIDs, accepted evidence UUIDs, source gate digest, assumption revision UUIDs (empty in W2) and consequence basis SHA. Basis SHA hashes canonical sorted IDs, window/cutoff, model/formula version, quantity bounds, source gate and missing assumption markers; an identical basis returns the existing ID and a changed basis appends a new revision.

`PostgresColdConsequenceStore` alone inserts `cold_consequence_revision`, `cold_consequence_evidence` and `cold_consequence_work_attempt`. `cold_recompute.process_one` selects unfinished work under `pg_advisory_xact_lock(hashtextextended('cold_consequence:' || work_id,0))`, takes one repeatable-read snapshot, refuses a foreign/missing exact basis, writes consequence/links and `SUCCEEDED` attempt in one transaction. On derivation failure it rolls back that transaction and appends a typed `FAILED` attempt in a fresh transaction. A crash before success commits leaves no partial revision; retries are idempotent. `run` uses the existing `financials/recompute.py:retry_due_at` 1,2,4,8,16-minute schedule and bounded batch; one bad work item cannot starve others. Trigger-created work does not depend on a successful worker.

## Five API reads

`cold_site_api.py:build_cold_site_router` mounts five GET paths below `/api/sites/{code}/cold`. Request query for all is `from,to,known_at` (strict UTC); Analysis additionally `after,limit` (default 50, max 200). Use W2-03 shared common envelope exactly: `site_id,window:{from,to,known_at},currentness:{state,watermark,latest_relevant_evidence_at,pending_since},source_provenance:{classification,source_ids,evidence_ids,basis_sha256},limitations`. Every card/object includes `as_of` and `limitation`; scalar decimals serialize as decimal strings and absent values as JSON null. `currentness.state` is `CURRENT|PENDING_RECOMPUTE|STALE_SOURCE|HISTORICAL|UNKNOWN`. Valid empty selection is 200 with `UNKNOWN` and empty arrays. 401 unauthenticated, 403 tenant/source disclosure, 404 missing/wrong-type Site, 409 unresolved selected revision or cursor/basis conflict, 422 malformed/range/unknown query, 503 store unavailable use `{error:{code,message}}`; never downgrade 503 into a blank page.
