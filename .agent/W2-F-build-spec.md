## State and copy rules

The W2 selected read remains the authority. For refused reads, render the existing date/window selection when supplied by the URL, a neutral `Window cannot be read` strip and the same number/order of mock tiles **on screens that have tiles**, each with `Not assessed`; no last-good selected data is silently reused. Evidence has a strip and panels but no tile row, so do not add one. Keep all panels and their in-panel refusal copy. For no selection, use the existing no-assessment copy and unknown/none tiles where present; pending and historical responses keep their existing selected basis and explicit currentness sentence. Null destinations are noninteractive `No linked page for this item`; genuinely unbuilt mock tabs use `UnavailableEntry` and `Not available yet`, without an `href`.

**One recovery rule (H1):** `COOLING_RESPONSE` means *observed cooling resumed after the relevant interruption*, not merely that a compressor channel and two probes exist. A selected start chain must have an accepted compressor-running observation after its off/failure observation and an accepted subsequent probe showing return to the selected policy band; both must be on the same selected assessment basis and order. If the chain has an off report and no running report, show `Not recorded` in Backup, `Recovery comparison not assessed` in Overview, and `Limited` with `Compressor running report after interruption; subsequent in-band chamber reading` in Evidence. If there is no chain or no selected assessment, Evidence is `None`, Backup `Not recorded`, Overview `Recovery comparison not assessed`. Only that complete ordered chain permits `Full`/`Cooling resumed`; contradictory selected observations give `Contradictory` and never Full. A compressor report and probe coverage without the ordered chain may still support a limited *condition* statement, never recovery. Do not infer recovery from topology, a status report before the interruption, elapsed time, a synthetic model state, or a previous selected head.

`PRODUCT_EXPOSURE` is a product claim, not a synonym for thermal exposure. `Full` would require the exact selected bounded excursion plus declared product identity, stock quantity/unit value, currency and reviewed product response rule; W2 has no such complete basis. An excursion with no product identity and no exposure rule is `None` (the stocked audit fixture). If some product basis exists but remains incomplete, it is `Limited`. No selected excursion is `None`; contradictory excursion is `Contradictory`. Full support cannot coexist with `Stock identity and value are not declared` or with `Nothing required for this claim`. Financials remains unpriced; no spoilage/loss/amount is invented. Implement in `backend/assetops_backend/analytics/cold_site_reads.py::_capabilities` and the existing selected overview/evidence projection so one rule feeds the three screens, not three independent UI overrides.
