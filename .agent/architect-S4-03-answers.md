# Codex Architect — S4-03 questions batch 1 (2026-10-13)

These rulings govern phase 3 and closeout; they do not change Finding identity, selected-assessment rules, revision immutability or the reviewed phase-1 read's membership/count semantics. Phase 2 remains under independent review, and the S4-03 owner walkthrough remains required.

| Question | Ruling and exact action |
| --- | --- |
| Q1 — assessment-keyed legacy Evidence tab | **Overrule automatic redirect on a unique day-level result.** A single Finding recorded for the UTC day is still not proof that the old assessment ID created or cites that Finding; the episode can span days and assessment revisions. **Before phase 3 closeout/owner walkthrough**, replace the one-result `<Navigate replace>` with the same explicit candidate link used for multiple results, headed “Findings recorded for this day” (or equivalent) and labelled as a day-level navigation aid, not “Evidence for this Finding”. Keep the no-result/refused state and the Site records link; never restore the old per-segment Evidence list or silently select a Finding revision. A later backend navigation contract may map an exact assessment revision to its cited Finding revision(s), after which exact redirects can be reviewed. This is a small phase-2 UI correction to review with phase 3, not G-04 mock-gap backfill. |
| Q2 — broken-lineage words | **Overrule the raw engineering-text fallback and make the API's display words product-safe.** The link codes and exact IDs stay machine-readable; the human-facing `BROKEN_WORDS` (including `lineage.words`, `set_breaks.detail` and `withheld` where reused) should use the existing plain-language meanings in `LINK_WORDS`, without “envelope”, “binding”, “mapping” or raw field names. **Before owner walkthrough/merge**, update the phase-1 read wording and its focused API/UI tests, then render the API words or a reviewed frontend map for known codes. For an unknown code or absent word, show a neutral “A record link could not be checked” plus the code in an explicitly technical detail, never raw backend prose or the code alone as product copy; keep the positive lineage claim withheld. This is a bounded phase-3/closeout contract correction, independently reviewed with the UI. |
| Q3 — selected window context | **Ratify the shipped default.** The exact Finding revision pins its stored assessment window(s) and cited records; `revision_id` is therefore the historical selection carried between Finding, Evidence and History. `offset` and `record` belong only to Evidence, and `view=analysis` belongs only to the Finding root. **No change before phase 3 or the owner walkthrough; no per-assessment-window filter.** Phase 3 must prove old → new → Evidence → old, reload and back/forward retain exact revision IDs, with omitted IDs plainly labelled “latest at read time”. If a later UI adds a separate user-selected window, that new context will need its own explicit address and preservation rule. |
